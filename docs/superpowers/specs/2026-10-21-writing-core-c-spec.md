# 写作工作台共用核心 C：任务单元、问题、版本与路线规格

日期：2026-10-21
上位设计：`docs/superpowers/specs/2026-10-20-writing-domain-expansion-design.md` 第 8、11、12、13、14、16、17 节
当前基线：共用核心 A、B 已验收；写作文章保存仍默认关闭，轮次已有 `parentRoundId`、提示词、结果、反馈、材料与基础包快照。

## 目标

让用户能把一项写作任务拆成可单独处理的章节/片段；将每条问题绑定到发现它的任务单元和结果版本；查看提示词与结果版本差异；从旧版本建立新分支；并按基础包中有来源的路线推进步骤。简单任务继续可直接生成提示词。

本阶段仅把现有普通文章工作台做成上述能力的首个完整使用案例，不增加或宣称已支持其他文体。

## 当前缺口和实现边界

- 工作区以整篇文章为单位；轮次已有稳定 ID 和父轮次，但更新操作可能改写当前轮次，没有任务单元或结构化问题记录。
- 历史可只读查看，不能对照两个版本，也不能从旧轮建立不覆盖后续历史的新分支。
- 基础包 schema 已有 `routes`，但路线尚未被工作台选择、消费或保存进度；路线没有标题、任务范围和来源关联。
- 本阶段复用 `writingArticles`、轮次、基础包、现有存储与备份，不新增数据库或服务。
- 不实现正文编辑器、自动代写、PDF/DOCX/OCR 解析、学术文献全库批处理或其他文体专项流程。

## 数据与关系

### 任务单元

普通文章工作区可有 0 至 100 个单元。单元最少记录稳定 ID、单元类型（章节/片段/任务）、标题、目标、完成标准、顺序和归档状态。单元是上下文范围，不保存或自动改写整篇正文；无单元时继续按全文任务运行。

轮次绑定一个 `unitId`，并保存生成时的单元摘要快照。材料卡片可关联一个或多个单元；未关联单元的材料属于全文上下文。选择单元后，实际提示词只采用全文材料和当前单元材料，并显示其他单元材料未被采用。每轮仍遵守最多 3 份材料、每份最多嵌入 1200 字的现有限额。

删除已被轮次或问题引用的单元时转为归档，不使历史引用悬空。旧工作区没有单元时按全文任务读取，不伪造单元记录。

### 问题记录

问题以工作区内稳定 ID 保存，并至少包含：来源轮次/版本、单元、原文位置说明、精确摘录、可观察表现、影响、依据类别与说明、可选基础包/来源 ID、修改建议、优先级、判断类别、处理状态、处理理由、复核轮次和时间。

- 判断类别：候选问题、待核对疑点、个人偏好、无法判断。
- 处理状态：未处理、待用户判断、已处理待复核、复核通过、暂不处理。
- 模型生成的问题始终先作为候选；只有用户明确操作才能确认、改状态或标记复核通过。
- 复核需绑定新轮次，并保留原问题与原摘录；收到新稿不会自动解决旧问题。
- 模型结果不能改变问题状态、删除已有问题或把材料内容当作应用规则。

模型诊断可返回受 schema 校验的结构化 JSON 问题候选。无法解析或校验失败时，原始诊断仍保留并显示“未解析为结构化问题”；不猜测字段、不丢失会话内容，用户仍可手动录入问题。

### 提示词和结果版本

- 轮次作为结果版本，`parentRoundId` 表示版本分支关系；已提交轮次不得被恢复操作覆盖。
- 每轮保存生成的提示词，以及用户编辑并明确保存/复制的提示词版本。每个提示词版本记录稳定 ID、父版本、内容、创建时间和应用是否执行了复制操作。复制只表示复制动作，不表示外部模型已接收或执行。
- 带回外部结果时记录用户选择的来源提示词版本；若用户无法确认，明确标为“来源提示词未关联”，不得推断。
- 历史对照默认比较当前和所选历史轮次，可并排查看提示词、结果、反馈、诊断和已关联问题；必要时显示逐行文本差异。
- “从此轮继续”创建新的子轮次并保留 `restoredFromRoundId`；只复制用户选择的上下文，不覆盖原轮或更晚轮次。
- 诊断结果始终关联产生它的结果轮次和实际使用的提示词，不因继续编辑表单而重新绑定。

### 专业路线

路线只能从当前任务实际选用且适用的基础包读取；本阶段不让模型凭空发明专业路线。扩展现有路线字段，支持标题、任务类型、来源 ID、核验状态，以及步骤标题、输入、输出、检查项、来源 ID、是否可跳过和缺项退回条件。旧路线按旧字段读取，未提供来源或核验信息时明确标为“未提供/未核验”。

用户选择路线后，工作区记录路线包 ID/版本、来源、步骤快照、当前单元和逐步状态。步骤状态为待开始、进行中、用户确认完成、已跳过、受阻；仅在包允许跳过时提供跳过。标记完成需要用户确认，可附结果/证据；点击完成不等于专业认证。缺少前置输入或检查项时可标受阻，并按路线配置退回，不生成虚构完成事实。

无适用路线时保持直接模式，提示“当前选用的基础包没有适用路线”；临时建议必须单独标为临时内容，不得显示成专业路线。

### 保存、备份与兼容

- 新数据沿用 `normalizeWritingWorkspace` 白名单，更新存储迁移、工作区备份校验与恢复；不改变旧文章和轮次 ID。
- 项目保存默认关闭。关闭时新单元、问题、路线状态与版本留在当前会话；开启后按现有写作存储行为保存。暂停不删除旧轮次。
- 工作区备份可恢复单元、问题、路线快照、轮次和提示词版本；资料库备份仍不包含正文、任务反馈、问题和写作记忆。
- 基础包和材料的原有快照/备份边界继续有效；不得把本机路径、凭证或未保存附件加入新结构。
- 旧轮没有 `unitId`、提示词版本或路线快照时仍可回看、复制和从中建立新轮；缺失关系明确显示“未记录”。

## 验收路径

1. 在同一普通文章任务中新建两个单元，为其中一个指定材料并生成提示词；提示词只包含全文和所选单元材料，显示材料实际长度与未选内容。
2. 从有来源记录的基础包选择路线，查看来源、适用范围、步骤输入/产出/检查项；启动、确认完成、受阻退回及允许的跳过均留有状态。
3. 保存并复制一个提示词版本，用户编辑后保存并复制第二个版本；带回结果时可将其关联至实际提示词版本，也可如实选择未关联。
4. 从诊断 JSON 生成候选问题，显示摘录位置、表现、影响、依据和建议；手动判断并在新轮复核，原问题与原版本仍可回看。无效 JSON 保留原文并提供手动录入。
5. 对比两轮提示词和结果；从较早一轮继续后生成新的子轮次，旧轮和后续轮次不变。
6. 开启保存后重启应用仍可恢复上述关系；暂停保存后不写入新历史；工作区备份往返后关系完整，旧备份仍可恢复。
7. 390px 窄屏和键盘可完成单元选择、问题判断、路线推进、版本比较和从旧轮继续。

## 验收边界

本阶段的固定结构化诊断样例只验证解析、关联和复核路径，不证明真实模型质量。没有已核验来源的路线保持未核验；未配置模型、远程解析或真机测试时分别记录为未验证。
