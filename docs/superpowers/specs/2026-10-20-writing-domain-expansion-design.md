### 1.2 已被后续纠正的方向

- 将工具扩成自动代写器、正文编辑器的方向，已被“这个工具就是写提示词的”取代。
- 将文献能力默认设计成完整文献管理平台、Zotero 自动同步的方向，已被“文献处理和参考文献库，为提示词提供材料”取代。
- 只做论文、其他文体不做的理解，已被“这些文体都要纳入范围”取代。
- 强制按完整论文流程工作、必须使用文件夹的理解，已被“按任务进入、多入口按需使用”取代。
- 统一用普通文章模板覆盖所有文体的方向，已被“共用机制、专业内容分别配置”取代。

## 2. 产品定位与完成标准

工作台帮助用户澄清写作任务、处理参考材料、选择专业方法、规划当前路线、诊断外部结果、生成和优化提示词。用户把提示词交给外部 AI 使用，再把结果和反馈带回同一任务继续推进。

可配置模型用于材料分析、诊断、路线选择和提示词生成；其结果仍须标明证据与不确定性。工作台的主要交付物是可编辑、可复制的提示词、检查结果和任务路线。外部 AI 的正文不由应用自动执行生成，也不自动写回用户原文件。

支持“辅助写论文”“优化论文”等快捷入口。快捷入口生成对应提示词，不隐含应用已经完成写作、实验、统计、核引或投稿。

不提供 AI 作者身份判断、去 AI 味客观分数、自动投稿、自动发表、未经授权的联网抓取或整库上传。不把多 Agent 运行平台、云账户、新数据库、向量数据库作为本轮前提。

## 3. 当前代码基础与实际缺口

以下是本轮只读核对和首版交付记录中的现状，用于约束后续设计；扩展实施时应再次核对实际代码版本。

| 现状 | 扩展必须解决的问题 |
| --- | --- |
| 写作 schema 和 coordinator 主要支持普通文章，部分逻辑有文章硬编码 | 引入明确的文体、任务与基础包选择契约，保留已有文章数据兼容 |
| 当前以单稿件、轮次为中心 | 支持项目下的章节、片段或任务单元及其关联，不建设全文编辑器 |
| 当前正文和提示词存在 8000 字符限制，材料数量和摘录较少 | 增加分段、选择、预算预览和批次处理，不能静默取前缀冒称全文审查 |
| 来源标记主要是本轮选择编号 | 增加稳定来源标识、原位置、书目信息、论断与来源关联 |
| 诊断主要是文本摘要 | 增加可定位问题、状态和跨轮复核关系 |
| 历史可回看，但没有本设计所需的完整对照与恢复行为 | 支持提示词和结果版本比较、从历史建立新轮，保留旧轮 |
| 授权目录索引以文本类型为主 | 为 PDF、DOCX、图片、链接等提供解析适配、能力显示和失败状态 |
| 写作搜索以普通文章方法问题为主 | 区分方法研究、任务主题检索、引用核验，分别限定范围和用途 |
| 模型入口依赖已提交轮次，可编辑副本与表单可能不同步 | 复制和发送均清楚显示实际版本、未提交变更和使用材料 |

已有保存、记忆范围、偏好晋升、材料用途分离、搜索预算、发送预览和备份不是全新能力。扩展它们时保持兼容，并验证旧任务不丢失、不串文体。

## 4. 共用核心与专业内容的职责

沿用现有原生 JavaScript、DOM、Electron 和本地服务方式，按已有 schema、prompts、coordinator、ui 分工扩展。只在职责确实不同处拆出小模块，不为文体扩展先建立通用插件运行框架。

| 单元 | 负责内容 | 输入与交付 |
| --- | --- | --- |
| 项目与任务 | 管理目标、文体、任务类型、章节/片段、轮次 | 用户任务与项目上下文；输出当前任务范围 |
| 基础包管理 | 管理通用、文体、专项包及版本和选择 | 包内容与适用条件；输出本轮采用的规则和来源 |
| 材料与参考库 | 导入、解析、索引、检索、摘录和来源定位 | 多入口材料；输出选材清单与覆盖记录 |
| 路线与阶段 | 按适用方法组织可调整路线和当前步骤 | 目标、已完成结果、阶段条件；输出下一步及理由 |
| 提示词组织 | 按任务组合要求、材料、约束与输出格式 | 当前草稿和选定内容；输出实际可复制或发送的文本 |
| 诊断与复核 | 对照标准定位问题、区分证据等级、复核修改 | 原提示词、外部结果、来源与反馈；输出问题及状态 |
| 记忆、案例与历史 | 保留偏好、经验、版本和轮次依据 | 明确操作及既有晋升规则；输出适用的少量上下文 |
| 调用与存储边界 | 复用发送预览、搜索预算、本地保存和备份 | 实际载荷、授权范围；输出真实成功/失败状态 |

数据流为：描述任务 → 识别文体与任务 → 挑选基础包 → 选择材料 → 直接生成或规划路线 → 生成当前提示词 → 复制给外部 AI → 带回结果 → 对照检查 → 优化或进入下一步。配置模型的分析调用发生在用户主动操作和实际发送预览之后。

## 6. 可管理的专业基础包

### 6.1 三层结构

- 通用包：任务澄清、材料使用、反馈定位、提示词组织、版本比较和结果复核等跨文体内容。
- 文体包：论文、新闻、技术文档、小说、口播、商务等各自的专业内容。
- 专项包：某文体下的任务或场景，例如文献阅读、综述、核引、审稿回复、人物设计、连续性检查。

三层共享组织机制，专业内容分别建设。任务只加载相关部分，不把全部包拼成一个长提示词。包是可检查的内容与规则，不自动安装或执行第三方仓库代码。

### 6.2 每个包的内容契约

| 内容 | 必须说明的问题 |
| --- | --- |
| 任务分类与适用条件 | 支持哪些任务、学科/领域、阶段、语言和对象；不适用什么 |
| 需求采集与澄清问题 | 必需输入、可选输入、合理默认与必须澄清的关键歧义 |
| 材料要求与用途规则 | 所需资料、内容/风格/反例/反馈用途、证据和位置要求 |
| 专业方法与规划路线 | 阶段顺序、输入输出、完成条件、可跳步骤与退回条件 |
| 专属提示词与组合规则 | 任务模板、可选模块、变量、缺失信息和冲突处理 |
| 结构与输出要求 | 章节职责、内容顺序、格式、篇幅、修改说明和交付形式 |
| 风格、术语与表达规则 | 语气、视角、术语、一致性、作者声音和应避免的表达 |
| 事实与证据规则 | 需要来源的表述、证据定位、引用与不确定性处理 |
| 诊断与验收标准 | 具体检查项、问题定位、严重程度和完成判定 |
| 常见问题与修复策略 | 可观察问题、候选成因、修复方向及何时不能直接修复 |
| 案例、反例与练习 | 输入、提示词、结果、修改理由和读者测试/练习 |
| 复核与下一步条件 | 带回结果后的检查、继续/重做/补材料条件 |
| 来源与验证记录 | 原始出处、文件/条目、版本、许可、日期、采用理由和验证范围 |

不是每个专项都必须出现一份独立教学练习；不适用项应明确说明并引用上层包，不能以空白字段假装完成内容建设。

### 6.3 包的身份与操作

每个包有稳定标识、名称、类型、版本、内容结构版本、作者/来源、适用范围、验证记录和启用状态。规则和方法卡有稳定条目标识，便于提示词、问题和历史引用。

- 内置包支持停用、移除、更新和恢复默认。用户编辑时形成可追踪的自定义版本，保留内置原版供比较和恢复。
- 自建和导入包支持新增、编辑、复制、导入、导出和删除。导入先预览来源、许可、适用范围、版本、覆盖对象及规则差异，不运行其中脚本。
- 包内单项方法、模板、风格或检查规则也可编辑和停用，不要求为改一条规则复制一整套领域内容。
- 内置更新先展示变化，不覆盖用户自定义版本；接受更新后新轮使用新版本，旧轮保留原依据。
- 上下层引用缺失、结构不兼容或重复标识时明确指出受影响的任务，不静默套用另一文体规则。
- 本轮自动推荐适用包，用户可改选、排除和查看实际生效条目。停用专业包后可以选择通用提示词路径，但须标明不具备该领域专用判断。
- 移除包不删除历史轮次。历史保存当时实际使用条目的必要快照及出处，不依赖被删包继续存在。
- 包增删与历史删除是不同操作；整篇/项目历史删除时也删除该范围内的快照，不借版本追溯永久保留用户已删除内容。

验证状态与启用状态分别管理：公开参考/待审查、已审查适用、经实际案例验证。自定义包可以直接启用，但不能因此标成专业已验证；用户改动过的条目必须重新记录其审查与案例验证状态。

### 6.4 方法、偏好与冲突

专业方法记录任务要求，个人记忆记录偏好，成功案例记录有条件的经验，原材料提供当前任务证据。它们分别存储并展示来源，不互相自动升级。

风格冲突沿用首版顺序：本次明确要求 → 当前任务指定样本与更正 → 适用个人偏好 → 文体/平台基线 → 模型临时建议。指定样本只用于用户选择的用途。

专业规则冲突先检查适用条件、时点和用户指定目标。用户选择的学校、期刊、机构或项目要求作为当前目标要求加载。两条有效要求不兼容时展示差异、影响和推荐理由，由用户确定方向；未解决前不声称同时满足。模型可以提供临时建议，但必须标明来源性质，不能冒充标准条目。

用户偏好不能把不存在的文献、尚未完成的实验或未经验证的判断变成事实。对于无法证实的要求，生成核对或补材料提示词，并保留未确认标记。

## 8. 任务入口、专业路线与下一步

### 8.1 四种起点

| 用户状态 | 工作台行为 |
| --- | --- |
| 只有想法或目标 | 澄清关键需求，选择适用方法，生成起步提示词 |
| 已有待处理材料或正文 | 识别任务范围和材料，生成阅读、规划、诊断或优化提示词 |
| 有提示词但结果不理想 | 关联原提示词、实际结果和反馈，区分提示词、材料、执行和偏好问题 |
| 外部 AI 已完成一步 | 对照本步标准复核，再生成修复、补充或下一步提示词 |

可以直接描述任务，也可以选快捷入口。快捷入口只是预选任务，不强制增加表单，也不替代完整任务列表。

### 8.2 复杂度与路线

简单任务直接展示当前提示词。复杂、跨章节或跨材料集合的任务展示简短路线，只展开当前步骤；用户可以调整目标、顺序、跳过步骤或从中间加入。跳过时展示缺失输入及对后续检查的影响，不自动补造已完成状态。

路线源于已选方法卡，不让模型从零生成并冒称专业流程。模型可以根据任务删减或细化已有步骤，逐项说明依据；新增启发性步骤标记为临时建议。普通综述、系统综述、实验论文、学位论文有不同适用条件，不能自动套同一路线。

每步至少记录：方法来源、任务目的、输入材料、预期输出、完成检查、可跳条件、失败/补充材料去向。用户改动路线后保留改动记录，不篡改包的原始方法。

### 8.3 学术优先任务

| 任务 | 需要的关键材料 | 当前提示词的主要目标 |
| --- | --- | --- |
| 阅读文献 | 原文/摘录、阅读问题、文献定位 | 提取问题、方法、结果、局限及可定位证据，区分原文与推断 |
| 整理综述 | 综述类型、范围、文献集合、检索与筛选记录 | 比较研究、提取证据、组织综合；按所选路线记录覆盖 |
| 规划提纲 | 研究问题、已有材料/结果、篇幅和目标要求 | 明确章节职责、论证关系及各节所需证据 |
| 辅助写论文/章节 | 章节目标、核心论点、已有结果、来源和相邻章节关系 | 生成给外部 AI 的起草提示词，缺失事实保留标记 |
| 优化论文/章节 | 原文、问题位置、允许修改范围、保留项 | 生成定向优化提示词并要求说明改动，不擅自增强结论 |
| 核对引用 | 论断、引用记录、书目、来源摘录和位置 | 分别检查书目信息、文献存在、论断支持与格式，并列未核实项 |
| 回应审稿 | 原始意见、实际修改、支撑证据、正文位置 | 逐条组织回应，核对承诺、正文和实际修改是否一致 |

选题、研究规划、方法核对、统计/图表说明、投稿格式和答辩准备可作为学术专项任务组织；只输出相应规划、检查和提示词，不宣称完成实际实验或专业认证。

### 8.4 下一步的判断

每个下一步建议说明：当前发现、检查依据、缺少什么、建议动作、为什么优先，以及完成后如何复核。存在未解决的关键问题时优先修复或补充，不为推进流程强行进入下一阶段。

审稿示例：未完成修改 → 修改规划/补充分析提示词；已带回改稿 → 修改与意见对应核对提示词；修改及证据齐全 → 逐条回复提示词。生成回复不等于可以投稿。

用户可指定下一步。若缺少专业包或必要证据，仍可输出通用规划和补充材料提示词，并清楚标明不能完成的专业判断。

同一材料有稳定标识；本轮显示序号不能替代长期来源标识。更新原文件或重新解析时记录版本，不让旧摘录无提示地指向新的内容。

### 9.2 文献处理和库

参考文献库保存适用的标题、作者、年份、期刊/出处、DOI/链接、文献类型、摘要/笔记、摘录、原文件关联、页码/章节和验证记录。缺失字段标未提供或待核对，不靠模型补造。

支持参考文献文件导入和重复项候选提示；合并前展示差异，不自动把名称相似的文献合并为同一条。文献格式和中文规范按适用的目标要求配置，不能把英文格式直接套给中文论文。

引用核对至少区分：书目字段是否完整、文献是否存在、记录是否对应正确文献、原文是否支持具体论断、位置是否可定位、格式是否符合目标。单一 DOI 可解析不代表全部通过。

库用于检索选材和提示词生成。Zotero 等外部工具可作为材料来源或外部操作提示词的对象，不把自动同步、完整引文编辑器或文献管理平台作为默认建设要求。

### 9.3 文件夹与两种选材方式

选择目录时先展示授权范围、是否含子目录、支持类型、发现数量、排除项和解析失败项；不越出授权目录。默认只读，使用时不修改、移动或删除原文件。

1. 自动挑选相关材料：从授权范围检索与当前任务相关的文献/资料，展示选中原因、采用摘录、原位置和覆盖范围，用户可以增减。这是默认方式。
2. 覆盖整个集合：用户先确认范围和筛选条件，按批次安排阅读、证据记录和综合提示词。展示各材料未处理、待处理、处理完成、排除、失败等状态，以及状态依据；重试不重复计数，范围变化时更新覆盖记录。

“整个集合”指用户确认范围内符合筛选条件的材料，不包含明确排除项。报告同时展示发现总数、排除、可用、失败、完成/未完成数及各自清单；覆盖统计与实际可用材料对应，失败项不能从总范围悄悄消失。

检索全目录不等于读取所有全文，解析成功不等于模型已阅读，复制分批提示词不等于外部任务已完成。外部处理只有用户带回相应结果或明确确认后才能记录完成，并标明是用户确认还是有结果依据；未核实结果的完成确认不等于质量通过。

需要按全文阅读的任务，只有实际处理范围达到要求才可标记该文献全文处理完成；只读摘要或部分章节的条目必须保留范围。综合之前可选择继续补齐或在报告中明确限定当前覆盖范围。

### 9.4 解析、附件和实际发送

- 应用列明当前环境支持的文件类型和解析能力，不能接受文件后静默丢弃。不支持、加密、损坏或解析失败时保留条目并提示替代入口。
- 链接无法访问、需要登录或正文不完整时明确提示，可以改为粘贴、导入文件或提供可访问页面；不绕过访问控制。
- 图片识别的文字、数字、公式和表格保留原图位置及不确定标记，关键项可由用户核对。不把 OCR 文本当成已验证数据。
- 本项目解析适配优先评估用户已配置的 MinerU；实施时先检测当前可调用能力，未暴露时说明并采用已有解析能力或手动摘录。解析器本地/远程、实际发送文件和凭证范围均需可见。
- 用户若选择需要远程服务的解析，先展示上传范围并确认。选择本地文件或文件夹本身不授权向远程解析/模型/搜索服务上传其全部内容。
- 生成提示词之前显示实际选用材料；调用模型时继续复用现有实际发送预览，包含摘录、附件和必要元数据。不会逐文件重复审批同一批已经明确确认的发送。
- 复制提示词不会自动携带图片和原文件。提示词列出所需附件名称、用途及必要位置，提醒用户给外部 AI 同时提供。外部工具不能访问本机路径时，不声称已自动获得文件。
- 解析失败、尚未读取、未采用的内容不能写成“已参考”。提示词区分已嵌入文字、需外部附件读取和未核实内容。

### 9.5 保存范围

新材料默认仅关联当前任务，不自动进入长期资料库。用户选择“保存到资料库”后才长期留库；当前项目内可以继续引用已关联材料，避免每轮重选。

任务/项目是否跨重启保存由其保存开关决定，与“是否加入资料库”分开。默认关闭项目持久化，沿用首版默认不保存的约定；开启时说明保存范围。存入资料库的材料不因关闭当前项目保存而消失。

目录授权、原路径和索引全文不自动进入可分享备份；恢复后需要重新关联原文件或授权目录。普通库记录保存可用摘录和来源元数据，原文件的独立持久保存必须明确选择。整库索引、原附件和本轮实际采用摘录分别计量。

## 10. 提示词的组成和实际版本

通用组织能力按任务组合目标、输入材料、执行要求、保留项、输出格式和检查标准；这不是要求每项任务使用同一份长模板。字段必要性和专属要求由经过审查的任务包决定，用户不必为简单任务填写无关项。

| 提示词任务 | 需要的专属内容 |
| --- | --- |
| 辅助写章节 | 章节职责、核心论点、已有结果、可用证据、相邻章节关系和缺失标记 |
| 优化已有稿件 | 原文、问题位置、改动范围、保留项、风格依据和修改说明 |
| 整理综述 | 研究问题、综述类型、文献范围、比较维度、证据记录和综合方式 |
| 核对引用 | 待核对论断、引用记录、来源摘录/附件、位置及无法核实时的输出规则 |
| 回应审稿 | 原始意见、实际修改、支撑证据、正文位置、回复结构与篇幅 |
| 技术操作说明 | 读者环境、前置条件、动作、预期结果、失败与恢复要求 |
| 口播/播客 | 平台或场景、时长、说话人、听觉节奏、开场和材料使用要求 |
| 小说/剧本 | 场景/章节目的、相关人物设定、视角/格式、连续性状态和修改边界 |

所有提示词均明确材料用途、缺失信息的处理方式和事实保真要求，不补造实验结果、数据、引文、用户经历或已完成修改。需要外部 AI 执行工具或读附件时，说明能力前提和不能完成时的替代输出。

提供以下结果：可编辑完整提示词、所用包与方法来源、实际材料清单、需要外部 AI 同时获得的附件、尚未确认项，以及任务适用的检查要求。来源说明和提示词正文可分别查看；复制正文仍包含执行所需的材料与附件要求。

用户修改表单、材料、包或提示词副本后，清楚区分尚未提交输入、已生成版本和已发送版本。复制操作使用屏幕上明确选中的版本；模型发送预览展示最终载荷。已有诊断和外部结果关联到其实际提示词版本，不因后续编辑自动改绑。

## 11. 诊断、优化与有依据的专业判断

### 11.1 检查层次

| 检查层 | 依据 | 能得出的结论 |
| --- | --- | --- |
| 提示词设计 | 适用方法卡、用户目标与约束 | 必要输入是否缺失、要求是否矛盾、交付是否明确 |
| 材料 | 实际可读范围、来源和解析记录 | 资料是否足够、对应正确、存在不确定或覆盖缺口 |
| 外部结果 | 原提示词、原材料、任务检查项 | 是否漏答、改变原意、缺证据、违背约束或步骤未完成 |
| 个人反馈 | 用户位置、偏好、认可和不认可样例 | 哪些表达不符合本次需要，与规范性问题分开 |

没有外部结果时只能静态检查提示词，不能声称已证明实际效果差。材料不足或外部 AI 无读取能力时，不能一律归因为提示词不好。

### 11.2 问题记录和模糊反馈

每个问题包含稳定问题标识、所属任务/稿件版本、原文位置、可观察表现、影响、检查项与来源、证据、修改建议、优先级和判断状态。判断状态区分已确认问题、待核对疑点、个人偏好及无法判断。

用户说“不够专业”“有 AI 味”“不自然”时，先结合材料和专业规则列出有位置的候选原因及影响，例如证据缺失、术语不一致、论证跳跃、空泛夸张或节奏不合场景。关键歧义仍会改变修改方向时，再提出一个具体问题，不连续抛出整套问卷。

AI 味沿用首版对可观察表达和作者声音的处理，不推断作者身份，不用机械禁词替换，事实强度和专业术语优先保真。没有问题的部分不强制改动。

问题处理状态为未处理、待用户判断、已处理待复核、复核通过、暂不处理；记录处理理由和关联新版本。跨轮复核对照原问题及目标，不因收到新稿就自动标记解决。

### 11.3 优化与对照验证

优化提示词说明问题、依据、修复策略、改动范围、保留项和复核方法。原版和新版并存；外部 AI 结果分别关联，不覆盖旧记录。

对照时尽量使用相同材料、模型和其他条件，并记录已知差异。检查目标满足、事实保真、约束遵守、问题解决、引入的新问题及用户偏好；模型自评分可作为待复核意见，不能单独证明有效。

代表案例区分公开参考、专业适用性审查、实际使用验证。实际验证记录输入、采用版本、模型条件（如已知）、外部结果、检查结论、用户反馈与适用范围。用户满意是个人使用证据，不自动升级为全领域专业标准。

## 12. 项目、记忆、案例与版本

项目关联目标、文体、任务、提纲/章节或片段、术语表、材料和轮次。章节只是选择上下文和管理任务的结构，不提供正文自动改写编辑器。小说可独立保存角色、设定、时间线、伏笔与章节摘要，不能强行复用论文章节的全部语义。

记忆分为通用、文体、项目/任务范围。保留首版显式保存、编辑、删除、撤销和跨不同文章的偏好晋升要求；仅同一文体至少两个不同作品的证据可按原规则自动晋升到该文体，并显示可撤销提示。单篇多轮重复不算多个作品，专业规则不通过偏好晋升自动生成。

新文体默认只继承适用通用偏好，不继承普通文章或其他文体偏好。本次更正优先用于当前任务，长期偏好冲突可见、不静默覆盖。风格档案记录可观察特征、来源、用途、把握度和用户更正，不等同于长期记忆。

案例分公开参考、用户确认成功/失败、专业审查和有实际对照的验证记录。成功与失败均保留场景和条件，不把一次成功推广为万能模板；可提供示例、练习、前后对照和读者测试来帮助用户学习改稿。

每轮关联目标、范围、方法/规则版本快照、采用材料及位置、实际提示词、外部结果、诊断问题、反馈和路线状态。支持提示词/结果的前后比较、必要的文本差异查看、回看历史和从旧轮建立新轮；恢复不覆盖后续轮次，过期位置或缺失原附件要明确提示。

项目/作品历史持久化默认关闭；开启后保存开启期间新增的全部轮次及其必要关联信息。资料入库、个人记忆和自定义包保存分别管理，不受项目历史默认关闭的设置影响。暂停只停止后续历史持久化，历史删除单独确认。历史超限前展示影响并提供导出或明确清理选择，不静默丢失支撑当前判断的版本。

完整工作区备份包含已保存的项目、轮次、偏好、自定义包及已保留资料；仅资料库备份不包含正文、任务反馈和个人记忆。凭证、未保存临时内容、目录授权、索引全文和未选择保存的原附件不进入备份。内置包可通过标识/版本恢复，自定义和历史所需内容须可恢复；缺少原文件或外部服务时显示重新关联/配置要求。

## 13. 数据与上下文预算

后续阶段至少维护以下关系；实际字段命名沿用项目模式，在对应阶段规格确定：

| 对象 | 最小关系与信息 |
| --- | --- |
| 项目/作品 | 文体、目标、任务、单元/章节、保存范围 |
| 基础包和方法条目 | 标识、版本、适用条件、来源、许可、验证和启用状态 |
| 材料/文献 | 稳定来源标识、原版本、元数据、用途、解析状态和位置 |
| 摘录与论断 | 所属来源、页码/章节/图区域、实际内容及支持关系 |
| 任务路线与批次 | 方法、当前步骤、输入输出、完成依据、覆盖范围和失败记录 |
| 轮次与问题 | 实际提示词/结果版本、所用包与材料、问题及复核状态 |
| 记忆与案例 | 适用范围、来源作品、使用结果、状态和撤销信息 |

索引与来源保存范围大于单次模型上下文范围。每次仅带入当前单元、适用规则、相关记忆、采用摘录和复核所需历史；不能依赖“最近两轮”代替仍未解决的问题和已确认约束。

预算预览显示已选内容、长度、可处理范围、遗漏项和需分批内容。优先完整保留目标、必须保留项和关键约束；超限时要求分段、减选或生成批次路线，不静默截断关键要求。字符截取标记为截取，未经语义处理不得称摘要，更不能冒称全文已审查。

具体长度、批次数、文件大小和支持类型在实施阶段结合解析器、模型、存储和外部复制方式设定并显示；本蓝图不承诺无限全文和无限文件。预算或环境限制不能改变覆盖统计的真实性。

## 14. 应用中的信息呈现

保留统一写作工作台，任务从简单到复杂逐步展开。以下是功能层次要求，不冻结未经视觉讨论的最终布局：

- 任务区：目标、文体、当前任务、选用基础包和可选章节/片段；直接粘贴即可开始。
- 本次参考材料：统一入口、材料卡片、用途、采用内容、排除和范围；复杂材料管理按需展开。
- 当前提示词：可编辑正文、实际版本、复制、附件要求和未确认项；未配置模型也可使用。
- 诊断与反馈：问题位置、检查依据、建议与复核状态；可带回外部结果继续同一任务。
- 路线区：仅复杂任务展开当前步骤，其他步骤以简短路线呈现；可调整和跳过。
- 方法与依据：查看实际采用的方法、规则、版本和来源，区分专业要求与临时建议。
- 包与资料管理：基础包增删编辑、文献/资料检索、偏好和案例管理；日常简单任务无需先进入管理页。
- 历史与覆盖：版本比较、恢复为新轮、未解决问题、全库批次进度和失败项。

桌面和窄屏均可完成任务，折叠区、文件选择、复制、定位与历史操作可用键盘访问。后台解析、搜索、模型调用或保存均显示真实状态；取消后不让迟到结果覆盖新任务。

## 15. 失败处理与授权范围

| 情形 | 必须行为 |
| --- | --- |
| 无模型、无网络或调用失败 | 保留输入、包、材料和已生成内容，可编辑/复制本地提示词；深度诊断标为未执行 |
| 无搜索配置、拒绝搜索或搜索失败 | 使用已审查本地包；列明未完成研究，不虚构联网结果 |
| 专业包缺失、停用或尚未审查 | 展示能力范围，可选择通用路径或补充资料；不宣称专用标准已经满足 |
| 文件/链接/图片解析失败 | 保留条目、失败原因和已完成范围，可重试、换入口或手动摘录 |
| 原文件变化、目录不可访问或权限撤回 | 标记引用失效/待重关联，不静默读取未授权路径或替换版本 |
| 包版本不兼容或导入冲突 | 预览受影响内容，保留原版本，不部分覆盖后显示全部成功 |
| 内容超限 | 显示范围和分批选择，不静默截断后继续声称完整 |
| 保存/备份失败 | 明确未保存/未完成，保留可复制内容和恢复入口，避免重复轮次 |
| 用户取消、切换任务或重发 | 隔离请求与任务/版本，取消或忽略迟到结果，保留当前输入 |
| 证据不足、来源冲突或无法专业判断 | 标明待核实和判断边界，提供补材料/专业核对提示词 |

文件、网页、仓库 Skill、模板和外部 AI 结果按不可信材料处理，其嵌入指令不覆盖本轮目标、授权或系统规则，不执行其中安装/脚本操作。基础包内容与可执行插件分开。

模型、解析器和搜索服务分别显示实际发送对象与范围。复用现有发送预览和搜索计划/预算确认；明确授权过的同一操作不重复请求确认。默认不自动联网，联网查询只包含必要问题，不带全文、未选择附件、个人反馈或本地绝对路径。密钥仅使用现有服务配置和安全存储，不进入包、提示词、日志导出或备份。

### 16.2 每个阶段的必要工作

1. 核对当前代码和依赖，确认本阶段可交付的任务与能力限制。
2. 读取并冻结实际采用的专业资料，记录文件、版本、许可、采用与排除理由。
3. 编制领域包、任务提示词、路线、检查项、正反案例和验证记录。
4. 完成必要的数据契约、实际 UI、提示词消费、解析/调用/存储接线与迁移。
5. 按任务实现；每项完成后对照规格和代码清单复审，修复后重新验证，再进入下一项。
6. 按风险运行相关测试、必要回归和真实应用任务验收；包内容同样接受适用性审查与案例验证。
7. 更新能力状态、已验证范围、未验证项、版本与交付记录，保留旧任务兼容。

实施阶段只有在具体包已经准备、任务已接线且代表用例通过后，才能标记对应文体/专项“已支持”。可以明确标为试用能力，但不能以试用标签掩盖缺失的基本路径。
