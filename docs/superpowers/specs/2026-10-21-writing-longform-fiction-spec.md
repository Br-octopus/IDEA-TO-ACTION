# 长篇创作：小说、剧本与连续性工作台规格

日期：2026-10-21
上位设计：`docs/superpowers/specs/2026-10-20-writing-domain-expansion-design.md` 第 5–17 节
复用基线：共用核心 C、学术 C（章节/任务单元机制）
状态：实施依据草案

## 1. 目标与产品边界

为小说、剧本及其他长篇创作提供项目级故事资料和分章/分场任务。用户可以维护世界设定、人物、时间线和伏笔，选择章节或场景，关联材料与未解决问题，生成规划、起草、连续性检查和定向修订提示词，并把外部 AI 的结果带回原任务和实际提示词版本。

工作台交付的是可编辑、可复制的提示词、检查问题、材料关系和任务进度。正文由用户在外部工具中创作并按需粘贴带回；本工具不自动代写正文、不提供全文编辑器、不覆盖原稿、不判断作品质量或市场成功。模型或规则发现的连续性问题均为候选，须由用户判断；设定冲突不自动改写故事资料或历史。

支持小说与剧本两个明确创作模式，共用故事资料、章节/场景单元和历史机制；剧本额外采集剧种/媒介、场景格式、人物出入场和可呈现动作等提示词约束。其他长篇体裁可选择“长篇创作（通用）”，不宣称具有未建设的专门规则。

## 2. 用户与代表任务

- 新作规划：整理题材、读者、核心冲突、篇幅/集数、创作边界，生成故事规划或结构提纲提示词。
- 世界与人物：记录设定、人物目标/动机/关系/已知信息及明确状态；生成设定补全、人物弧线或关系检查提示词。
- 小说章节：以章节目标、视角、时间地点、在场人物、前章摘要、相关设定、伏笔和未解决问题为上下文，生成章节起草或修订提示词。
- 剧本场景：以剧种/媒介、场景目的、内外景/时间、人物出入场、行动与对白约束及前后场关系生成场景任务提示词。
- 连续性核对：对带回的章节/场景文本提出有定位的候选问题，检查设定、时间、人物知识/关系、因果和伏笔状态；明确指出适用材料范围与无法判断项。
- 变更影响：用户修改既有设定、时间线或伏笔时，列出引用此资料的单元、材料和未解决问题作为待检查清单；用户确认后记录影响审查，不自动修改单元或旧轮。
- 跨章关联：从项目故事资料中选择少量相关单元摘要、材料、未解决问题和伏笔，不把整部正文或全部项目资料塞入一次提示词。
- 结果回带：关联外部结果、反馈和所选提示词版本；不确定来源时保持“未关联”，在新轮复核旧问题，不自动关闭问题。

## 3. 当前实现复用与新增数据

### 3.1 复用核心 C

- 复用 `writingArticles` 工作区、保存开关、轮次、父轮/恢复分支、提示词版本及复制状态、材料来源与单元关联、结构化问题、路线快照、工作区备份和既有 UI 模式。
- 复用任务单元稳定 ID、标题、目标、完成标准、顺序和归档行为。小说主要使用“章节/片段”；剧本使用“场景/幕/集”，通过单元类型或明确的呈现标签区分，不另建平行章节系统。
- 复用 `unitIds` 选材、全文材料规则、轮次单元快照、issue 的 `unitId`/`roundId`/`promptVersionId` 和跨轮复核。长篇上下文仅消费用户选中或按明确关联规则匹配的条目。
- 新增任务类型和提示词字段必须进入现有 schema 白名单、轮次快照、历史回看和备份恢复；旧文章/学术记录缺少长篇字段时仍按原行为读取。

### 3.2 长篇创作项目资料

在现有工作区中加入有界的 `longform` 项目资料区，不引入新数据库、插件框架或自动图谱服务。最小包含：

- 项目创作模式：`fiction`、`script`、`longform-general`；可选类型/媒介、视角、时态、目标读者、篇幅/集数、风格边界和明确的“不得改动”约束。未填字段显示未提供，不自动推断。
- 世界/故事设定条目：稳定 ID、类别、名称、事实/规则文本、适用范围、状态（暂定/确认/废弃）、来源或用户说明、更新时间。类别至少覆盖地点、组织、物件、规则及自定义。
- 角色卡：稳定 ID、姓名/称谓、身份/关系、目标与动机、已知/未知信息、状态/弧线、首次/最近出现单元及用户补充备注。没有提供的特质不由应用补造。
- 时间线事件：稳定 ID、事件说明、故事内时间（保留用户输入的文本，不强制建立日历日期）、涉及角色/设定 ID、关联单元、先后/同时/未知关系和确认状态。允许标为顺序未定；不自行解决冲突。
- 伏笔卡：稳定 ID、铺设内容/位置、预期回收或作用、关联角色/设定/单元、状态（计划/已铺设/待回收/已回收/放弃/未确认）及用户确认说明。状态变更需显式操作并可追溯。
- 章节/场景上下文：复用单元目标与完成标准，可增加视角、时间地点、出场角色、场景目的/冲突、前后单元关系、用户撰写摘要和状态。摘要由用户提供或明确保存，不从正文隐式推断为事实。

所有集合设合理条数与字段长度上限，沿用现有元数据凭证/绝对路径清理。移除被轮次引用的设定、角色、事件或伏笔时，优先软归档并保留历史快照；项目历史删除仍遵守现有显式删除和保存边界。

### 3.3 关系、变更影响与历史

- 稳定 ID 关联角色、设定、时间线、伏笔、单元、材料和问题；关系失效时显示缺失/已归档，不静默换成同名对象。
- 设定修改前后形成项目资料版本或变更记录，包含对象 ID、旧/新值、时间、用户说明。提示“可能受影响”必须可追溯到实际关联，不以文本相似猜测作确定关系。
- 变更影响清单至少指出受影响的章节/场景、相关材料、未解决问题和伏笔；用户可以逐项标记待检查、已检查、暂不处理并记理由。仅用户确认的检查结果可标记完成。修改设定不改变旧轮快照、外部结果或问题状态。
- 每轮保存本次实际使用的故事资料摘要/ID 及版本、当前单元快照、选用材料、未解决问题、提示词版本和带回结果关系。历史比较和从旧轮建立新分支沿用核心 C，不覆盖原轮或较新轮次。
- 项目资料与作品历史的保存范围沿用现有明确开关；备份需完整往返保留已保存的长篇资料和关系。资料库备份不得因此包含正文/问题/作品历史。

## 4. 任务与提示词契约

第一阶段任务类型：`longform-planning`、`longform-outline`、`longform-worldbuilding`、`longform-character`、`longform-chapter-draft`、`longform-scene-draft`、`longform-continuity`、`longform-revision`。如现有接口限制任务类型，应以稳定枚举扩展并保留旧任务默认行为。

提示词仅组合完成当前任务所需的内容：

1. 用户目标与明确约束、当前创作模式及任务类型。
2. 当前章节/场景目标、完成标准和用户提供的摘要/场景信息。
3. 用户选定的相关设定、角色、时间线事件与伏笔，注明状态、来源和未确认项。
4. 前后单元中用户提供或已保存的摘要、直接关联材料和仍未解决的问题；明确未采用的其他单元材料，不声称已读取全文。
5. 对应任务的输出结构、视角/剧种格式/可呈现性要求、连续性检查项和修改边界。
6. 缺失、冲突或证据不足信息的待确认标记；要求外部 AI 不新增与已确认设定冲突的事实，提出冲突供用户判断，不擅自统一。

规划/起草任务要求外部 AI 输出工作提案或创作稿，而本工具只生成该请求的提示词；诊断任务只要求定位问题、影响和核验建议，不直接给替换正文；修订任务必须标明范围、保留项、关联问题和复核要求。

连续性提示词按用户选定范围检查，至少区分：世界规则/事实、故事内先后关系、人物状态及其在该时点已知信息、动机/关系变化、因果、视角、伏笔铺设/回收和剧本场景职责/人物出入场。每条问题包含章节/场景或文本位置、摘录（可缺省并标明）、可观察表现、影响、关联设定/来源、待用户判断状态。不得把“检查未发现”描述成整部作品无矛盾。

变更影响只生成审查清单和可选复核提示词，不自动批量重跑任务、不改写正文、不改伏笔状态、不将候选冲突升级为已确认事实。

## 5. 界面与交互

- 长篇创作入口明确区分小说、剧本和通用长篇项目；用户可沿用项目列表打开既有记录。
- 项目资料区按世界设定、角色、时间线、伏笔组织；支持新增、编辑、排序/关联、确认/暂定、归档和来源状态查看。
- 单元区管理章节/片段或幕/场景；展示前后关系、摘要、涉及角色及相关伏笔。任务选择控件明确当前范围。
- 当前轮显示实际采用的故事资料、材料和问题清单，允许用户调整选择；提示词预览与实际复制/发送版本一致，未提交输入和版本差异清楚可见。
- 结果回带可选实际提示词版本或明确未关联，保留原文与反馈；诊断生成的问题先作为候选，状态需要用户显式更新。
- 变更影响面板呈现基于稳定关系的影响项和逐项处理状态；没有关联对象时如实显示未发现已登记关系，不推断无影响。
- 小屏可用、键盘可达、状态和错误信息可读；保存/生成失败保留当前输入。

## 6. 来源、质量与风险边界

- 为小说、剧本专项包建立独立于学术包的原创方法卡、任务模板、路线、连续性检查表、案例和来源映射。实施时逐项核对实际阅读内容、版本、适用范围与许可；未核验材料只作研究线索，不直接复制或标为审查通过。
- 来源和用户设定不是同一证据层：公开写作建议、用户确认的故事正典、外部 AI 候选、个人风格偏好分别标示，不能互相晋升。
- 内置故事方法包示例和固定模拟案例状态保持未验证，直至完成相应来源审查及实际案例复核。内容可帮助发现可观察矛盾，不宣称可证明故事逻辑完整或作品专业质量。
- 不做自动网页抓取、第三方脚本执行、自动全文分析、云同步、多人协作、自动写稿或自动改写。上下文过长时显示纳入范围和省略项目，提供用户选择/精简，不静默截断并声称覆盖全文。

## 7. 验收标准

### 7.1 数据与兼容

- 旧文章、学术工作区、历史轮次和备份可读取，长篇字段仅在长篇项目出现；未知字段、凭证和本地绝对路径按既有白名单规则剔除/清理。
- 小说、剧本和通用长篇模式可独立创建；章节/场景稳定 ID 与排序、归档及轮次快照可恢复。
- 世界设定、角色、时间线和伏笔的创建/编辑/状态与关联正确；归档或删除对象后历史引用不悬空、不误绑同名对象。
- 保存开启时刷新和工作区备份往返保留已保存资料、变更记录、影响清单、问题和轮次关系；保存关闭/暂停时遵守既有写作保存契约。资料库备份不泄露作品历史。

### 7.2 任务闭环

- 小说代表路径：建世界/角色/时间线/伏笔，创建至少三个章节，给章节关联材料与摘要，生成规划/章节起草提示词，核对提示词准确包含所选上下文且排除无关单元材料。
- 剧本代表路径：创建幕/场景和角色出入场，录入剧种格式与场景目的，生成场景提示词；剧本格式要求不污染小说任务。
- 连续性路径：对模拟带回结果生成至少两类有位置的候选问题（例如时间顺序、人物知识或设定冲突），问题关联实际轮次/单元/提示词版本；用户判断并在新轮复核后才更新状态。
- 伏笔路径：记录铺设、待回收和用户确认回收；连续性检查能指出关联信息，不因候选文本自动更改状态。
- 变更影响路径：修改被多个单元引用的设定，清单准确指出关联单元、材料/问题/伏笔；逐项处理后留有用户状态和理由，旧轮及其故事快照保持不变。
- 历史路径：比较提示词与带回结果版本，从较早轮建立新分支，确认历史和较新轮未被覆盖，未确认提示词来源仍显示未关联。
- 上下文过长、缺字段、相互冲突、保存失败、生成失败和迟到结果场景均有明确状态并保留用户输入；不得静默伪造完成、来源或覆盖范围。

### 7.3 应用与质量验收

- 新增 schema、协调器、提示词和 UI 定向测试；相关写作/基础包/存储/备份回归及 `pnpm check` 通过，`git diff --check` 无空白错误。
- 在 D 盘主项目实际启动的开发应用中完成小说和剧本的代表路径、保存刷新、问题复核及变更影响；应用检查无未解释的控制台错误。
- 390×844 视口无横向溢出，键盘可完成项目资料编辑、单元选择、提示词复制/结果回带和问题状态操作。
- 验收记录明确区分自动化、浏览器开发版或 Electron 实测、模拟结果、真实模型效果、安装包和用户真机。模拟结果只证明工作流和数据关联，不证明外部写作质量。用户实施的真机/真实模型测试可暂缓并列为待验。

## 8. 明确不做

不实现全文编辑/自动写作/自动修订、自动推断并固化故事正典、自动决定矛盾优先级、全文语义索引或未经选择的项目级长上下文、协作云库、剧本专业排版导出、影视制作管理、自动投稿/出版及市场表现承诺。未来需要这些能力时另立规格和验收。
