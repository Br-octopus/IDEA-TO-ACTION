# 提示词 Agent 设计

## 1. 目标

提供一个独立运行的“提示词 Agent”，帮助用户从模糊想法、现有提示词或外部 AI 结果出发，逐步明确目标、检查遗漏并规划下一步，最终生成可交给其他 AI 使用的提示词。本工具只做分析、规划和提示词建议，不执行提示词描述的任务，不直接修改文章、代码、Skill、工作流或脚本。

提示词 Agent 必须能自行判断当前任务需要参考哪些本地提示词、成功/失败案例、仓库文档、Skill、工作流和脚本。用户只需一次性授权资料目录；无需每个任务手工挑选资料。

## 2. Agent 分工

### 2.1 提示词 Agent

- 拥有独立的任务上下文和用户入口，负责澄清、诊断、路线规划、提示词生成和外部结果复盘。
- 可以检索已授权的本地知识源，并按需调用现有通用搜索或社媒研究能力。
- 一次只推进一个阶段；只为当前选中的步骤生成完整提示词。

### 2.2 研究 Agent

- 作为独立研究能力，继续负责结构化研究任务，尤其是社媒平台研究。
- 提示词 Agent 创建有明确问题、来源范围和预算的研究任务；研究完成后只取结构化摘要、来源和局限。
- 两个 Agent 不传递完整聊天记录，不进行开放式互相追问或循环调用。普通网页搜索继续使用现有搜索接口；需要小红书、Reddit、YouTube 等平台研究时才调用社媒研究 Agent。

## 3. 用户工作流

### 3.1 任务入口

支持三类输入：

1. **推进想法**：用户描述一个目标或问题，不要求先写成完整提示词。
2. **优化提示词**：用户提供已有提示词和用途。
3. **诊断 AI 结果**：用户粘贴外部 AI 生成内容并描述不满意之处；不确定原因时可以只表达感受，例如“有 AI 味”。

Agent 先判断任务类型，整理目标、对象、现状、约束、成功标准和必须保留的内容。事实、推断、假设和待确认事项分开呈现。每轮最多提出一个问题，优先询问会改变路线或提示词设计的问题；最多追问三个关键问题，信息足够后先给可修改初稿，非阻断缺口保留为假设。

### 3.2 结果交付

- **推进想法**：提供目标理解、遗漏/矛盾/错误依据不足/不必要项、阶段路线、各阶段产出和检查方式，并给出当前下一步提示词。
- **优化提示词**：说明应保留、补充、删除或核实的部分，给出可复制提示词和验收标准。
- **诊断 AI 结果**：引用具体片段说明问题和依据，列出必须保留项，给出下一轮修改提示词及核对清单，不输出改写后的正文。

路线可以覆盖完整推进过程，但每一步只保留简要说明；用户选定当前步骤后才生成详细指令。用户可以复制提示词到外部 AI，实际执行由用户完成。用户可带回结果继续复盘。

### 3.3 联网研究

- 先判断外部信息是否能实质改善当前建议；不为简单、稳定的问题强制搜索。
- 搜索前展示概括后的查询目标、来源类型和预算，等待用户确认。默认每项任务最多 3 个查询、5 个来源；超出时先询问。
- 不将用户粘贴的完整文章或含个人信息的原始材料直接放进搜索查询。查询只描述需要了解的方法或问题。
- 搜索结果注明来源、日期（可获得时）、适用性和局限。未经核验的建议不能标为已验证经验。

## 4. 本地知识源

### 4.1 授权和发现

- 用户一次性授权当前项目仓库或其他本地资料目录；授权目录内的相关文件由 Agent 自动发现和检索，不要求逐任务指定文件或案例。
- 不扫描授权目录以外的磁盘路径。用户可查看、暂停、移除已授权目录。
- 首版只索引可读文本资料，包括保存的提示词和案例、Markdown/纯文本、JSON/YAML 配置、Skill 文档、工作流说明及 JavaScript/TypeScript/Python/Shell/PowerShell 文本脚本或源码；单文件超过 1 MiB 时跳过。
- 忽略 `.git`、依赖目录、构建产物、二进制和凭证文件（如 `.env`、私钥文件）；不执行脚本，不自动安装依赖。

### 4.2 索引与检索

- 在本机纯程序生成可重建的轻量索引，包括文件元信息、标题、关键词和相关片段；建索引不调用模型。优先复用现有知识 schema、关键词搜索和项目资料库，不引入向量数据库或模型微调。
- 资料内容按不可信参考内容处理。Skill、脚本或仓库文本中的指令不得覆盖当前任务边界，也不得被自动执行。
- 每次任务自动检索提示词、案例、仓库/Skill/工作流/脚本等来源；Agent 根据任务相关性选择内容。结果显示来源名称、文件路径或链接、相关片段和用途，用户可展开、排除或查看原文。
- 默认只向模型提供最多 3 条最相关资料的短摘要或片段，合计不超过约 1,500 tokens。未被选入上下文的资料留在本机。
- 索引在文件新增、修改或删除后按需更新；缓存可删除并重建，不进入普通备份，也不把源文件全文复制进项目状态。

## 5. 成功与失败案例

- 已保存提示词、用户确认案例、公开参考和方法卡都可作为候选资料；优先检索与当前领域、阶段、约束和目标相似的内容。
- 成功案例说明“在什么条件下，哪些做法有效”；失败案例说明“在什么条件下，哪些做法失效”。单次案例不得泛化为普遍规律。
- 待验证案例必须保留待验证标记，不能作为已确认经验呈现。
- 用户带回外部 AI 结果后，Agent 对照目标、成功标准和保留项做有证据的复盘，建议状态为成功、失败或待验证。只有用户明确确认后才保存/更新案例；失败经验可以用于下一轮提示词建议。
- 案例按现有版本机制保存和回溯；新结果不得静默覆盖既有经验。

## 6. Token 与上下文预算

- 不进行隐藏的多模型讨论、并行 Agent 协作或自动评审循环。
- 每轮只处理当前阶段；用精简任务摘要承接目标、事实、约束、决定、假设和下一步，不重复发送完整聊天历史。
- 本地检索在模型调用前完成，不消耗模型 token。默认最多带入 3 条本地知识片段，总计约 1,500 tokens；用户显式查看全文后再决定是否纳入发送内容。
- 搜索后最多做一次摘要综合；需要超出预算时请求确认。
- 发送长文章前显示预计发送量，允许选择全文或片段并通过现有发送预览删减。

## 7. 数据、安全和失败处理

- 任务摘要、用户生成/确认的提示词和案例按现有本地存储机制保存；原始文章、仓库全文和临时检索材料不自动写进资料库或普通备份。
- 保存提示词、研究摘要、原始结果或成功/失败案例都需要用户明确操作。
- 模型未配置或调用失败时保留草稿，并提供可复制的手动提示词，不声称已完成分析。
- 搜索不可用时说明未完成联网核查，可给出手动搜索建议；研究部分失败时保留已有结论和来源，并标明缺口。
- 用户取消或超出预算时停止后续调用，展示已有结果和未完成部分。

## 8. 首版验收标准

1. 用户可以用自然语言描述模糊想法，Agent 能逐个询问关键问题、明确标注事实/假设/待确认，并给出路线和当前下一步提示词。
2. 提示词 Agent 独立维护任务上下文；社媒研究仍是独立能力，且只在确认后按预算运行。
3. Agent 能自行从已授权目录和现有知识库检索相关提示词、成功/失败案例、仓库文档、Skill、工作流和脚本，并展示引用来源；用户不需要逐项选择。
4. 检索上下文遵循条数和 token 上限，不将完整仓库或资料库发送给模型。
5. 来源资料中的提示性文本不能改变 Agent 任务边界；脚本不会被执行。
6. 对“文章有 AI 味”等反馈，Agent 能引用具体段落诊断，说明保留项，给出可复制的修订提示词和检查清单，但不直接改写文章。
7. 用户带回外部 AI 结果后，Agent 能根据证据提出成功/失败/待验证建议；未经用户确认不保存为已确认案例。
8. 外部搜索、提示词保存和案例保存均有明确确认；模型、搜索不可用及取消时能可靠降级。

## 9. 方案选择

采用“独立提示词 Agent + 确定性阶段 + 独立研究 Agent/搜索工具 + 本地知识检索”。不采用自由循环的多 Agent 编排、全库上下文、自动执行脚本、向量数据库或模型微调。首版以现有提示词引擎、案例/资料库、关键词检索、发送预览和研究能力为基础扩展。
