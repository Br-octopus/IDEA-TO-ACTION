# 社媒研究工作流 Agent 设计

日期：2026-10-19  
状态：待用户审阅设计稿  
范围：设计，不包含实现

## 1. 背景与目标

当前应用已经具备可选搜索服务、本地资料库、发送预览、普通 JSON 备份和用户确认案例。下一阶段希望把“搜索资料”升级为一个可以研究国内外社媒信息的工作流 Agent，降低用户准备平台、登录、组织查询词、筛选结果和整理报告的难度。

本功能的定位是：

> 单研究 Agent + 多平台工具 + 确定性工作流。

研究 Agent 负责理解目标、生成计划和分析结果；平台工具负责搜索和提取；确定性工作流负责权限、顺序、预算、暂停和失败恢复。首版暂不拆分为多个 Agent。

首批支持：

- 小红书
- Reddit
- YouTube

输出同时包含：

1. 结构化研究报告。
2. 可筛选、可追溯的原始结果集。

## 2. 已确认的产品决策

- 第一阶段选择小红书、Reddit、YouTube 三个平台。
- 四种研究模板首版都支持：趋势与热点、用户痛点与口碑、内容与竞品研究、事实与方案核查。
- 用户先确认研究计划，之后 Agent 才能自动执行只读搜索、翻页、去重和整理。
- 平台同时支持 API 和真实浏览器两种连接方式。
- 没有 API 的平台直接使用真实浏览器。
- 有 API 的平台默认优先使用 API；API 失败、限流、结果不足或字段不完整时切换真实浏览器。
- 用户可以手动指定只用 API、只用浏览器或自动选择。
- 真实浏览器使用应用管理的独立平台 profile，默认可视化登录；高级选项允许用户主动导入已有浏览器会话。
- 不保存账号密码，不把 cookies、session token 或浏览器目录发送给模型。
- 默认只保存结构化摘要；用户勾选后才保存完整正文、截图或附件。
- 搜索和浏览器操作默认只读，不点赞、不评论、不发布、不关注、不绕过验证码或平台风控。
- 继续使用现有 `localStorage` 保存轻量工作区状态，不引入数据库。
- 较大的正文、截图和附件保存到 Electron 用户数据目录，状态中只保存附件元数据和相对路径。
- 任何需要新增平台、扩大研究范围或保存大量内容的行为，都需要用户确认。
- 如果未来出现平台数量、任务复杂度或角色分工明显增加，需要主动提醒用户评估是否拆成多 Agent；首版不主动引入多 Agent。

## 3. 非目标

- 首版不做多 Agent 协作。
- 首版不要求三个平台都提供 API。
- 不做自动登录、自动处理验证码或绕过访问限制。
- 不做点赞、评论、发布、关注、私信等写入操作。
- 不保证抓取所有平台内容，不把搜索不到等同于不存在。
- 不默认保存整页正文、图片、视频或评论区全部内容。
- 不把高热度、点赞数或推荐位直接视为事实证据。
- 不把单条用户观点直接升级为已验证知识。
- 不引入向量数据库、embedding 或云端整库索引。
- 不把社媒研究结果自动写入资料库，必须经过用户选择和确认。

## 4. 总体架构

```text
用户研究目标
    ↓
研究 Agent：理解目标、选择模板、生成计划
    ↓
用户确认研究计划
    ↓
确定性工作流：准备检查、预算、执行、暂停、重试
    ↓
平台工具层
    ├─ XiaohongshuAdapter
    ├─ RedditAdapter
    └─ YouTubeAdapter
        ├─ ApiAdapter（平台有 API 且已配置时）
        └─ BrowserAdapter（无 API、API 失败或结果不足时）
    ↓
结果标准化、去重、证据分级
    ↓
研究 Agent：跨平台分析和报告
    ↓
用户查看、筛选、保存
    ↓
本地研究任务和资料库
```

### 4.1 研究 Agent 的职责

研究 Agent 可以：

- 理解研究主题、对象、时间范围和目标。
- 选择四种研究模板之一。
- 生成平台分工和查询词列表。
- 在已批准的预算内扩展同义词、英文词和补充查询。
- 判断结果是否重复、冲突或证据不足。
- 生成结构化报告并关联原始结果。
- 标注未完成、待核验和相互矛盾的内容。

研究 Agent 不可以：

- 自行登录或读取凭证。
- 绕过验证码、风控或平台访问限制。
- 在用户未确认计划时开始搜索。
- 超出计划预算静默增加平台、时间范围或保存范围。
- 直接修改用户的原始资料。

### 4.2 平台工具的统一接口

每个平台工具向工作流提供统一能力，不让研究 Agent 依赖具体网页 DOM：

```text
getCapabilities()
checkReady()
prepareSession()
search(query, options)
fetchDetail(result)
captureEvidence(result, options)
close()
```

API 和真实浏览器适配器都实现同一组上层能力。平台没有某项能力时，返回明确的 `unsupported`，不能返回伪造空结果。

## 5. 平台准备中心

### 5.1 平台状态卡

每个平台显示独立状态卡：

```text
小红书
API：未配置
浏览器：已登录，可搜索
本次研究方式：自动选择
详情页：可用
评论：部分可用
截图：可用
最近检查：2026-10-19 21:30

[开始准备] [打开浏览器] [配置 API] [检查状态]
```

状态包括：

- 未准备
- 正在创建 profile
- 等待用户登录
- 正在检查
- 已登录，可搜索
- API 可用
- 登录过期
- 需要人工验证
- 搜索受限
- 连接失败
- 能力部分可用

### 5.2 真实浏览器准备

默认流程：

```text
选择平台
→ 创建或打开独立 profile
→ 打开真实可视化浏览器
→ 用户扫码或手动登录
→ 用户点击“我已完成登录”
→ 系统检查会话和搜索能力
→ 执行一次测试搜索
→ 显示可用能力
```

验证码、二次验证和风控页面由用户在可视化浏览器中完成。系统只等待用户完成，不自动破解或绕过。

### 5.3 API 准备

有 API 的平台显示独立的 API 设置：

- API 地址或平台预设。
- API key 或凭证输入。
- 连接测试。
- 支持的搜索能力。
- 速率限制和结果上限。
- 最近错误状态。

凭证继续使用 Electron 安全存储，不进入 `localStorage`、普通 JSON 备份、研究报告或模型上下文。

### 5.4 连接方式选择

每个平台支持三种选择：

- 只用 API。
- 只用真实浏览器。
- 自动选择。

自动选择规则：

1. 平台存在已配置且通过连接测试的 API 时先调用 API。
2. API 认证失败、超时、限流、字段不完整或结果低于计划最低数量时，记录原因。
3. 如果浏览器能力已准备，切换浏览器继续。
4. 如果浏览器未准备，暂停该平台并引导用户准备。
5. API 和浏览器结果都进入统一去重和证据分级流程。

切换必须显示在任务日志中，不能静默改变数据来源。

## 6. 研究计划与工作流

### 6.1 研究输入

- 研究主题或问题。
- 研究模板。
- 目标平台。
- 时间范围。
- 目标受众、地区或语言。
- 关注字段，例如痛点、标题、评论、价格、体验或争议。
- 排除词和内容类型。
- 研究深度：快速、标准、深入。
- 每个平台的连接方式。

### 6.2 研究计划

Agent 先生成：

```text
研究目标
研究类型
平台分工
查询词列表
时间和地区限制
筛选条件
预计结果数量
证据要求
预算和停止条件
```

用户确认后才进入执行状态。

### 6.3 确定性执行阶段

```text
检查平台能力
→ 执行第一轮查询
→ 获取搜索结果
→ 标准化字段
→ URL 和内容指纹去重
→ 只对候选结果获取详情
→ 提取正文/评论摘要或截图
→ 证据分级
→ 判断是否需要补搜
→ 生成研究报告
```

Agent 只能在已批准预算内补搜。以下行为需要重新确认：

- 增加新平台。
- 扩大时间范围或地区范围。
- 获取计划外的评论、正文、截图或附件。
- 保存超过当前任务大小限制的内容。
- 需要重新登录或切换到用户未准备的平台。

### 6.4 四种研究模板

#### 趋势与热点

- 关注时间范围和讨论频率。
- 区分平台热度、用户讨论和重复来源。
- 输出共同话题、平台差异和可能趋势。

#### 用户痛点与口碑

- 关注真实体验、抱怨、失败经历和重复问题。
- 区分个案、频繁出现的问题和未经证实的推测。
- 输出痛点分类、代表性证据和待核验事项。

#### 内容与竞品研究

- 关注标题、内容结构、卖点、评论反馈和平台差异。
- 不自动复制原文或生成侵权复刻内容。
- 输出内容模式、用户反应和可借鉴范围。

#### 事实与方案核查

- 跨平台寻找独立来源。
- 区分事实、用户观点、广告表达和推断。
- 输出支持、反对、冲突和未核验信息。

## 7. 结果标准化与报告

### 7.1 统一结果字段

```text
id
platform
url
title
author
publishedAt
capturedAt
searchQueries
summary
discussionSummary
publicMetrics
contentType
retrievalMethod: api | browser
evidenceStatus
marketingRisk
needsManualReview
attachmentIds
```

### 7.2 证据规则

- 单条社媒内容默认是用户观点或个案。
- 高热度不等于可靠事实。
- 多个平台出现相同说法只能标记“多个来源提到”，不能自动升级为事实成立。
- 广告、营销号、搬运、标题党和缺少原始依据的内容单独标记。
- 存在冲突时并列展示，不强行生成单一结论。
- 每条报告结论必须能展开查看关联原始结果。

### 7.3 报告结构

```text
核心发现
平台共同点
平台差异
高频痛点或内容模式
代表性案例
争议与相互矛盾信息
仍需核验的内容
下一步建议
```

报告旁边保留原始结果集，可按平台、查询词、时间、证据状态、保存状态筛选。

## 8. 存储与资料库

### 8.1 研究任务状态

研究任务保存在现有工作区状态中：

```text
id
topic
template
plan
platforms
connectionModes
status
budget
queries
resultIds
reportId
createdAt
updatedAt
```

状态包括：草稿、等待计划确认、等待平台准备、搜索中、等待补搜确认、报告已生成、等待保存、已保存、部分失败、已取消。

### 8.2 轻量数据与附件分离

轻量元数据、摘要、报告和用户选择保存在 `localStorage`。用户主动保存的完整正文、截图和附件写入 Electron 用户数据目录，状态中只保存附件 ID、类型、大小、来源结果 ID、相对路径和保存时间。

### 8.3 保存到资料库

研究结果不自动进入资料库。用户勾选后选择保存类型：

- 研究资料。
- 用户痛点。
- 竞品案例。
- 趋势观察。
- 待核验事实。

默认只保存结构化摘要、链接、平台、作者、发布时间、抓取时间、搜索词、核验状态、适用范围和局限。完整正文、截图或附件必须由用户主动勾选。

### 8.4 备份边界

完整工作区备份包含研究任务、研究计划、结果摘要、报告、用户选择和主动保存的附件；不包含浏览器 profile、cookies、session token、API key、密码和未保存的临时抓取内容。恢复后平台状态显示为“需要重新检查”，不假装会话仍有效。

## 9. 失败处理、权限和预算

### 9.1 失败类型

- 未登录：进入平台准备中心。
- 登录过期：暂停当前平台，保留已获得结果。
- 验证码或二次验证：要求用户在浏览器中完成。
- API 认证失败：记录错误，自动模式切换浏览器。
- API 限流或超时：记录原因，按自动模式切换浏览器。
- 页面结构变化：标记适配器异常，不返回伪造空结果。
- 单个平台失败：继续其他平台，报告标记部分完成。
- 全部平台失败：保留计划和查询词，生成可复制的手动研究指令。

### 9.2 预算

每个研究任务限制：

- 最大平台数。
- 每个平台查询词数量。
- 最大翻页数量。
- 最大详情页数量。
- 最大执行时间。
- 最大附件大小。
- 最大模型分析 token 数。

达到预算后停止并说明完成度。

### 9.3 用户控制

研究过程中可以暂停、取消、跳过平台、重新登录、修改查询词、删除结果、禁止保存附件、只保留某个平台结果或重新生成报告。模型外发继续经过现有发送预览和敏感信息门禁。

### 9.4 操作日志

只记录任务阶段、平台、连接方式、状态和错误类别，不记录密码、cookies 或完整私密页面内容。

## 10. 测试与验收

### 10.1 单元测试

- 查询计划字段和预算校验。
- API/浏览器适配器统一接口。
- 平台能力矩阵。
- API 失败到浏览器回退规则。
- 结果标准化和 URL/内容指纹去重。
- 证据状态和营销风险标记。
- 研究任务状态迁移。
- 附件元数据和备份清洗。

### 10.2 集成测试

- 可视化登录成功、失败和过期。
- 独立 profile 创建、复用和清除。
- API 配置成功、认证失败、限流和超时。
- API 结果不足时浏览器回退。
- 没有 API 的平台直接使用浏览器。
- 单个平台失败后其他平台继续。
- 用户取消后工作流不再执行后续步骤。
- 报告结论能回到原始结果。
- 默认不保存全文，用户选择后才保存正文或截图。
- 备份不包含 profile、cookies、session token 和 API key。

### 10.3 手动验收

在全新用户目录验证：

1. 小红书通过可视化浏览器登录并完成测试搜索。
2. Reddit 和 YouTube 分别测试 API、浏览器和自动回退。
3. API 失败时自动切换浏览器并在日志显示原因。
4. 研究计划确认后自动完成只读搜索。
5. 四种研究模板都能生成报告和原始结果集。
6. 验证码、登录过期、限流和断网时不会伪造结果。
7. 用户勾选后才保存完整正文或截图。
8. 重启应用后研究摘要、报告和附件索引仍可恢复。
9. 备份恢复不会恢复登录凭证，但会要求重新检查平台状态。

## 11. 参考方向

设计参考了以下项目公开展示的思路，实际实现前仍需单独核对许可证、平台规则和代码适用性：

- STORM：研究规划、迭代检索、证据引用和报告组织。
- DeerFlow：研究任务、工具调用、技能拆分和流程状态。
- GPT Researcher：多来源检索、研究报告和来源追溯。
- Open Deep Research：可配置研究流程和来源整理。
- Browser Use：真实浏览器会话、登录后浏览和工具控制。
- Crawl4AI：动态网页抓取、结构化输出和浏览器会话复用。
- Firecrawl：网页内容提取、标准化和爬取任务接口。
- Scrapling：多层级网页抓取和页面变化适应。
- LocoAgent：平台 Skill、真实浏览器会话和确定性工作流。
- xhs-cli / xhs-skill：小红书扫码登录、会话复用、登录检查和平台操作拆分。

参考项目只用于借鉴结构和工程思路，不直接复制平台绕过逻辑，不把第三方项目默认视为官方能力或稳定接口。
