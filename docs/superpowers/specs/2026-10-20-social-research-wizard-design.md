# 社媒研究分步向导设计

日期：2026-10-20
状态：已确认（用户批准分步向导方案；"暂停/取消放第 2 步"与"第 4 步置灰"均已确认）

## 背景

社媒研究页把研究目标、平台准备、研究计划、结果集、研究报告五个板块全部平铺，用户进来面对十几个按钮，没有流程感，不知道先做什么。

## 目标

页面只显示当前一步，形成 写目标 → 确认计划 → 查看结果 → 研究报告 的向导流程；平台准备折叠为状态摘要。

## 设计

### 步骤条

页面顶部显示四个步骤：① 研究目标 → ② 确认计划 → ③ 查看结果 → ④ 研究报告。已完成的步骤可点击回看；未到达的步骤置灰。当前步骤高亮。

### 各步骤内容

- 第 1 步 · 研究目标：目标输入、研究模板、平台选择、"生成研究计划"按钮。新用户默认落在此步。
- 第 2 步 · 确认计划：计划详情 + "确认并运行"/"暂停"/"取消"。运行中此步常驻显示进度。
- 第 3 步 · 查看结果：结果集、筛选器、深读与保存按钮。
- 第 4 步 · 研究报告：报告内容 + "带结果去提示词 Agent"。报告未生成时入口置灰（让用户知道有这一步）。
- 平台准备：默认收起为顶部一行状态摘要（如"4 个平台就绪"），点击展开完整面板。仅当某平台不可用并影响研究时自动展开并高亮。

### 自动流转

- 生成计划成功 → 自动进入第 2 步。
- 确认运行且结果开始产出 → 自动切换到第 3 步；仅第一次自动切换，之后不抢用户所在位置。
- 材料齐、报告生成 → 第 4 步显示 badge 提示，不强制跳转。

### 实现方式

- 纯前端重构 prototype/social-research-ui.js 的渲染逻辑，不改后端、schema、事件 ID。
- 现有五个 panel 的 DOM 与 ID 保留，按状态包进步骤容器控制显示/隐藏；事件绑定不变。
- 步骤状态由现有 task 状态（status、results、report）推导，不新增持久化字段。

### 错误处理

- 计划生成失败：留在第 1 步，显示原因。
- 运行失败：留在第 2 步，显示原因。
- 平台登录失效：第 3 步顶部显示提示条。

## 测试

现有 tests/social-research-ui.test.js 补充用例：状态 → 当前步骤的推导逻辑、自动流转只发生一次、平台摘要文案。完成后跑全量回归（npm run check + node --test）。

## 不做的事

- 不改研究工作流、API、schema。
- 不合并或拆分结果集/报告的功能。
