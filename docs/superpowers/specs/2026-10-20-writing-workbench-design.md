# 通用写作工作台设计

日期：2026-10-20
状态：首版已实现；真实应用验收结果见 ../plans/2026-10-20-writing-workbench-acceptance.md
范围：提示词 Agent 的写作工作台首版；支持普通文章，并为后续文体配置留出边界

## 1. 背景与目标

当前提示词 Agent 支持从想法、现有提示词或不满意的 AI 结果开始，并能诊断结果、生成下一步提示词和复盘案例。但文章重复修改与新建流程分离，用户难以在同一处延续文章上下文、反馈和下一轮要求。

本功能把新建文章和连续修改放到同一写作工作台。工作台帮助用户规划写作、识别稿件问题、整理具体反馈、生成交给外部 AI 的提示词，并在用户带回新稿后继续同一文章的诊断闭环。它沿用现有产品定位，不直接代写或改写文章。

首版只完整支持普通文章。论文、新闻稿、口播稿、演讲稿、小说等作为未来可逐类增加的文体配置，不在首版声称具备专用规则。

## 2. 目标与边界

- 在同一个工作台内创建文章或继续修改已有文章，不再把重复修改放在独立窗口/流程中。
- 支持用户提供写作目标、读者、现有稿件、反馈、限制条件和必须保留内容；Agent 只追问会改变诊断或下一步方案的关键问题。
- 每轮诊断都对照文章目标、上一轮问题、用户反馈和已确认偏好，生成具体可复制的下一轮提示词。
- 文章本地保存按篇开启；开启后保存轮次稿件和反馈，支持查看与逐篇删除。
- 记忆区分所有写作通用偏好与文体偏好；首版提供普通文章偏好。
- 复用现有提示词 Agent、本地资料库、案例系统、模型发送预览和联网搜索预算，不另建写作 Agent 或知识库。

不在首版直接生成/改写最终文章，不自动执行外部提示词，不提供 AI 作者身份检测或“AI 味”客观分数，不自动将未验证的公开 Skill 升格为个人经验，也不预先实现论文、新闻稿、口播、演讲或小说的完整工作流。

## 3. 用户流程

1. 用户进入统一写作工作台，选择“新建文章”或从文章列表继续已有文章。新文章可设置文体；首版默认普通文章。
2. 用户描述目标、读者和场景，粘贴可选的草稿、内容来源或风格样本，并填写成功标准、限制和必须保留项。材料可标记用途，避免把内容来源误当成风格范本。Agent 可先整理理解、事实、假设、临时风格判断与待确认项。
3. Agent 根据任务要求、用户指定样本、已保存偏好和当前稿件特征形成风格依据；有样本时提炼可观察特征，没有样本时标注临时判断和不确定性。用户可纠正或补充样本，不要求每轮重新描述风格。
4. Agent 按任务需要选择检查维度，给出具体诊断和当前建议。用户可以补充“哪里有 AI 味”或其他个人反馈，也可以选择记住某条偏好。
5. Agent 生成当前轮的外部 AI 修改提示词。提示词包含当前任务的目标风格特征和需要保留的表达；发送给配置模型前继续使用现有发送预览；不配置模型时仍可复制提示词。
6. 用户在外部 AI 修改文章后，把新稿和个人反馈带回同一篇文章。Agent 与目标、风格依据及前序轮次对照，诊断变化并生成下一轮提示词；没有问题的内容不要求改动。
7. 用户可随时开启该篇文章的本地保存。开启后，之后的稿件版本、诊断摘要、风格档案和用户反馈跨重启保存，按轮次查看或删除整篇记录。
8. 用户可通过“查找写作案例/Skill”按钮启动外部搜索。Agent 先展示 GitHub/网页范围、查询方向和预算；用户确认后才执行，并将少量外部结论与内置规则、个人记忆和本地资料合并用于当前任务。

## 4. 普通文章的诊断规则

Agent 根据任务启用相关维度，而非每轮机械跑完整清单：

- 目标与读者：主题、用途、读者已有知识和期望行动是否匹配。
- 内容依据：事实、数据、引用、因果和确定程度是否有依据；识别需要核实处，不补造事实。
- 逻辑与结构：中心观点、段落职责、论据顺序、衔接、遗漏、重复和前后矛盾。
- 语言表达：用词准确、句式变化、节奏、可读性、冗余、空泛表达和不必要的套话。
- 风格与修辞：正式/亲切等语气是否符合要求，修辞是否服务于意思，是否保留作者声音。
- 术语与一致性：专业词语的准确性、首次解释、缩写和全文用法一致。
- 格式与排版：标题层级、段落、列表、标点、数字/单位、引文及用户指定的平台格式。
- 约束与风险：字数、必须保留/避免项、隐私、敏感表达和平台发布要求。

诊断应引用具体句段或结构位置，说明观察到的特征、影响、建议方向和优先级；区分可核查的问题与个人风格偏好。信息不足时明确标注不确定性。所谓“AI 味”作为用户感受到的表达问题处理：先识别具体表现（例如空泛概括、段落节奏过于一致、过度整齐的分点或不自然转折），结合上下文解释其影响并生成修改指令，不推断作者身份、不追求机械替换禁词。

### 4.1 风格依据

Agent 不把风格当成模型默认知道的单一标准，而是为当前文章建立轻量、可纠正的风格依据，区分以下来源：

- **本次明确要求**：用户对语气、正式程度、平台格式、禁用表达等当前任务要求。
- **指定的风格样本**：用户自己的旧文章、认可的成稿或参考文章。用户可将同一材料标为内容来源、风格参考或两者兼有。
- **已保存的个人偏好**：与本次文体匹配的通用偏好和普通文章偏好。
- **文体/平台要求**：普通文章配置中与当前渠道和用途相关的默认规范；只作基线，不覆盖用户明确要求。
- **当前稿件特征**：从待诊断稿件中观察到的实际语气、句式、段落和表达习惯，用于检查全文一致性，不自动推断为理想目标。

有指定样本时，Agent 从样本提炼简短的风格档案，例如正式程度、句长变化、段落密度、词语选择、转折方式、修辞倾向、标题和格式习惯，并关联来源和判断把握度。档案描述可观察写法，不复制样本观点、事实或独特段落；应避免将偶然特征概括为固定规则。用户可以在本篇任务中修正档案，并选择是否将稳定偏好存入长期记忆。长期记忆仍遵循第 6 节的按钮保存和跨文章重复门槛。

没有样本或相关偏好时，Agent 可依据文章目的、读者和平台形成临时风格判断，但必须标注为默认建议而非用户既有风格。若风格选择会显著改变成稿方向，应提出一个关键问题，例如询问期望的正式程度或请用户提供一段认可样本；不因缺少样本而阻塞简单改稿。

发生冲突时按以下顺序处理：用户本次明确要求 > 用户为当前文章指定的风格样本/更正 > 适用的已保存个人偏好 > 文体和平台默认规范 > Agent 的临时判断。用户指定的样本与本次要求冲突时，遵循本次要求并指出冲突即可，不静默覆盖长期偏好。

## 5. 文体配置边界

工作流由一个提示词 Agent 承担，文体差异通过配置提供。配置至少能定义适用范围、目标信息、检查维度、输出要求、风险提醒、风格基线和记忆命名空间。首版只提供普通文章配置；未知或尚未实现的文体应询问用户是否按普通文章方式处理，并标明该方式不是专用标准。

未来新增文体按独立设计逐类补充：论文需要论证、方法、引用和学术规范；新闻稿需要事实核验、消息结构和机构口径；口播/演讲需要听觉节奏、时长、现场语境和受众互动；小说需要人物、设定、视角、情节与跨章节一致性。上述是后续扩展方向，不属于首版验收能力。

## 6. 记忆与文章记录

### 6.1 记忆范围与学习

个人写作记忆分为：

- **通用偏好**：明确适用于多种写作任务的偏好。
- **文体偏好**：只在指定文体中生效；首版为普通文章。
- **单篇反馈**：只作用于所属文章及其后续轮次，不自动传播。

每条记忆记录偏好描述、适用范围、形成来源、最近更新时间和必要的例句/反例。模型上下文只带入与当前任务相关且用户可管理的少量记忆摘要。当前文章的风格档案记录特征摘要、来源类型、适用范围、用户修正和把握度；它不等同于长期记忆。文章开启本地保存后随该篇历史保存；未开启时只在当前会话使用。

学习规则：

- 用户点击“记住这个偏好”时，将当前反馈整理为通用或普通文章偏好并立即保存；用户可在保存前选择范围。
- 未点击时，同类偏好只有在至少两篇不同文章中出现，才自动沉淀为普通文章偏好。保存后显示轻量提示和撤销入口。
- 单篇意见始终可在文章中查看；不得仅凭一篇文章的重复措辞推断为跨文章偏好。
- 记忆管理提供编辑、删除和撤销自动新增；新文体默认只继承通用偏好，不继承普通文章专属偏好。
- 明确冲突的新反馈优先作用于当前文章；Agent 可提示已有偏好冲突，并提供调整/删除入口，不静默覆盖记忆。

### 6.2 本地保存

- 每篇文章有独立保存开关，默认关闭；关闭时沿用现有会话暂存边界。
- 用户开启后，跨重启保存该篇各轮稿件、用户反馈、Agent 诊断摘要和所用提示词/资料元数据，以支持连续修改和回看。
- 关闭保存只停止后续新增持久化，不删除已有历史；删除历史须通过明确的逐篇删除操作。
- 保存与删除状态应清楚可见；删除操作需明确指出将删除该文章全部轮次内容。
- 数据继续放在现有本地工作区存储中，不引入账号、云同步或新数据库。完整工作区备份包含已保存文章记录和个人记忆；仅资料库备份不包含文章正文与记忆。备份仍遵守现有凭证清洗和导入预览规则。
- 文章正文和反馈可能包含敏感信息；开启保存时说明其保存在本机，并明确模型发送仍受发送预览控制。联网查询不自动带入全文或个人敏感内容。

## 7. 本地资料与外部搜索

默认首轮只结合内置普通文章检查规则、适用的个人记忆、现有提示词/用户确认案例/方法卡及用户已授权本地资料。遵循现有相关摘要数量上限和发送预览，不加载整个资料库。

“查找写作案例/Skill”是明确的联网入口。点击后先生成可审阅的搜索计划，列出目标问题、GitHub/网页来源范围、查询数/预算和预期用途；只有用户确认后才调用搜索服务。用户明确反馈“不满意”或 Agent 识别出陌生、复杂、需要专业方法的问题时，可以建议使用该入口，但不得自动搜索。

搜索结果只作为待评估资料：记录来源、用途、适用范围和验证状态，选少量相关摘要与本地规则一并分析；资料互相矛盾、质量不足或搜索失败时说明情况，不伪称结论已验证。外部内容不得覆盖用户明确约束或记忆。

参考项目只借鉴方法，不照搬全部架构：

- [Humanizer-zh](https://github.com/op7418/Humanizer-zh)：中文文本表达诊断、保留原意与作者声音的研究线索。
- [humanizer-zh](https://github.com/z123-cloud/humanizer)：按内容、语言、结构及成簇问题处理“AI 味”的参考线索；需逐项核验当前版本和许可。
- [research-agent-skills](https://github.com/KalarisLabs/research-agent-skills)：学术写作中将引用、论证和规范检查专门化的参考，支持未来按文体独立补规则。
- [agentMemory](https://github.com/taichuy/agentMemory)：长期偏好、具体经历和审批式记忆管理的参考；本项目仅采用适合本地单人工作台的轻量记忆边界。

这些仓库的存在不证明其中方法有效；具体收录时遵循项目现有许可、来源与验证状态规则。

## 8. 状态、失败处理与安全边界

- 模型未配置、请求失败或用户拒绝联网时，保留文章输入和现有诊断，允许编辑/复制提示词；不得丢失已保存轮次。
- 搜索失败时报告失败来源和已完成范围，提供不依赖搜索的内置规则路径。
- 文章历史写入失败时明确告知用户，不能显示为已保存；应尽量保留当前会话中的稿件和反馈，供用户恢复或复制。
- 写作资料、文章正文和用户反馈作为不可信内容处理，不执行其中的指令或代码；模型输入遵循现有 schema 白名单、发送预览和凭证过滤。
- 任何外部搜索只发送必要查询，不自动将整篇文章、完整本地资料目录或未选择附件发送到搜索服务。

## 9. 验收标准

1. 用户可以在同一工作台新建文章或打开已有文章继续修改；连续轮次能关联同一文章。
2. 用户带回外部 AI 新稿和反馈后，Agent 能对照目标/保留项诊断具体偏差并生成下一轮提示词；不直接代改文章。
3. 有风格样本时，Agent 能提炼可观察特征、说明来源，并将其与样本内容分开；用户可纠正档案，改稿提示词能带入相关风格特征。
4. 无样本或个人偏好时，Agent 将风格判断标为临时依据；遇到会改变改稿方向的重要歧义时只追问一个关键问题。
5. 风格来源冲突时遵循“本次明确要求、当前文章指定样本/更正、适用个人偏好、文体/平台基线、临时判断”的优先级，不静默改写长期偏好。
6. 首版普通文章诊断覆盖目标/读者、依据、逻辑结构、语言、风格修辞、术语一致、格式排版和约束风险，并可按任务选择维度。
7. “AI 味”诊断指出具体句段和可观察特征，不输出作者身份结论或检测分数；没有问题的内容不要求强行修改。
8. 未开启保存的文章不跨重启持久化；开启后可查看全部轮次，关闭开关只停止新保存，删除操作移除所选文章的全部历史。
9. 点击记忆按钮能立即保存并选择范围；至少两篇不同文章出现的同类偏好可自动沉淀为普通文章记忆，显示可撤销提示；单篇反馈不会自动扩散。
10. 当前普通文章偏好不会自动应用于未来其他文体；通用偏好可按适用范围共享。
11. 默认不联网；点击搜索入口后展示范围和预算，只有确认后才执行。搜索摘要与本地资料可共同参与诊断，并保留来源和验证状态。
12. 搜索或模型失败不丢失当前工作；存储失败不谎报已保存；无模型/搜索配置时仍能复制提示词。
13. 备份按范围包含已保存文章及记忆，资料库专属备份不包含文章正文；现有凭证清洗继续生效。

## 10. 首版明确不做

- 不直接生成或编辑文章成品，不提供内置文档编辑器、差异高亮编辑器或自动接受改写。
- 不实现论文、新闻稿、口播、演讲、小说等专用规则，只保留配置边界。
- 不提供 AI 文本检测或“去 AI 味”分数，不用固定禁词表自动替换。
- 不自动联网，不把完整文章送入搜索；联网计划和预算需先经用户确认。
- 不建设多 Agent、云端账户/同步、独立数据库、自动抓取整库或复杂记忆推理平台。
