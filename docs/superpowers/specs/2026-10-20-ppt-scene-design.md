# PPT 场景设计

日期：2026-10-20
状态：已确认
范围：提示词 Agent 的 PPT 专项方法；不包含实现计划

## 1. 定位与边界

PPT 场景是通用提示词 Agent 的领域方法，不是单独运行的 PPT 制作 Agent。它帮助用户澄清演示目标、研究制作方法、整理原始材料、规划故事线与逐页内容、选择外部制作路线，并生成可交给其他 AI 的提示词。它不会直接生成、编辑或导出最终 PPT。

用户可以在应用内预览其他 AI 生成的 HTML 页面或图片并添加标注。提示词 Agent 根据标注诊断问题、澄清用户意图并生成下一轮指令；不直接修改被导入的页面或图片。

本设计承接 [提示词 Agent 设计](2026-10-19-prompt-agent-design.md) 中的单 Agent、按阶段推进、本地知识检索、用户确认案例和外部搜索预算边界。

PPT 助手与研究 Agent 的关系是“领域工作流调用研究能力”：PPT 助手负责任务简报、内容规划、风格理解、路线选择和提示词生成；研究 Agent 负责按确认的研究计划搜索平台资料并返回结构化来源。两者不互相循环调用，也不新增一个自由运行的 PPT 制作 Agent。

## 2. 目标与输入

覆盖工作汇报、培训课件、学术报告、论文分享、产品介绍、路演、营销演示等类型。Agent 根据内容和目标识别类型，用户可随时修正，不要求先从固定模板中选择。

支持用户提供：

- 粗略想法、演示任务、已有大纲、文章或其他文字材料。
- 图片、PDF、`.ppt`、`.pptx` 等内容来源或风格参考。不同格式可以使用不同解析器，但用户看到同一套结果质量报告：可读取内容、已处理页面范围、提取失败项和代表页视觉检查结果。
- 页数、总字数、单页字数、标题长度、演讲备注时长、信息密度、逻辑结构、受众、演示目标、风格、必须保留/避免的内容等明确约束。
- 外部 AI 生成的 HTML 页面或图片，用于预览和标注反馈。
- 明确的搜索要求，包括“大量/全面搜索”、限定搜索平台/网站/仓库/频道、日期范围、关键词，以及必须查或排除的来源。
- 明确指定的网页、视频、图片、PDF、PPT/PPTX、单个文件或本地文件夹，作为必须检查的资料目标。
- 目标 AI（可选）：例如 ChatGPT、Claude、Gemini、Cursor、PPT 工具或其他模型；未选择时生成通用提示词。选择后，助手根据该工具是否能读文件、看图片、写 HTML、生成 PPTX 或运行脚本来调整提示词；未知工具允许用户补充能力，不能假设它支持未确认的操作。

每份文件都可标记为“内容来源”“风格/排版参考”“两者兼有”或“无关”。Agent 可先按内容和视觉特征建议分类，并允许用户调整。作为风格参考时，分析布局、字体层级、颜色、留白、信息密度和页面类型；作为内容来源时，提取主题、论点、证据、数据、限制和必须保留项。不得把参考文件的视觉风格误当成用户必须照搬的内容。

对于文本、PDF、PPT/PPTX 和图片，读取能力取决于对应解析器。无法可靠提取的页面或对象应明确标记，并请求用户补充文本、截图或指出重点；不得据不完整提取伪造内容。

指定来源的处理方式按格式选择：图片提取可读文字并分析视觉内容；PDF/PPT/PPTX 提取文本、页面结构并在需要时查看渲染页；视频优先使用可获得的字幕/转录，再按主题抽查关键画面；本地文件夹只遍历用户明确选择或授权的范围，并按支持的文件类型筛选。长文件分段或按页处理，超出解析器限制时显示未处理范围。目录检索遵循通用提示词 Agent 的排除规则，不进入凭证、依赖、构建产物和二进制仓库目录。

对 `.ppt`、`.pptx`、PDF 和图片，先在本机提取所有可读页面文字，再按页/章节交给模型做语义筛选。不同格式可以使用不同解析器，但用户看到同一套结果质量报告：可读取内容、已处理页面范围、提取失败项、代表页视觉检查成功或失败，以及未处理范围。

## 3. 结果结构

Agent 的核心交付物是可编辑的内容规划，不是 PPT 文件：

1. **任务简报**：目标、听众、使用场景、听众需要理解或采取的行动、时长、页数、字数、证据、风格、交付形式、目标 AI 和待确认假设。
2. **临时规划**：根据用户想法先生成临时故事线、页数建议和大纲，未验证内容必须明确标记。
3. **资料与风格结果**：内容来源、风格参考、相关页面、来源依据、解析范围、失败项和模型筛选理由。
4. **资料增强版大纲**：基于定向搜索和用户确认后的材料修订故事线、页面职责、证据映射和未纳入内容说明。
5. **风格规则卡**：分开记录参考文件观察到的事实和结合当前目标后的建议规则；每条规则带来源或推理依据，并支持锁定、优先遵守、可调整和禁止使用。每份风格参考还可以标记为必须遵守、主要参考、灵感参考或禁止模仿。
6. **逐页文稿初稿**：每页标题/结论、页面短文案、演讲者讲稿或备注、视觉与版式说明、证据来源及前后页衔接。页面文案与演讲备注分开，避免把文章段落直接铺到幻灯片。
7. **制作路线建议**：推荐输出形式、路线理由、成本、限制、可编辑性和所需材料。
8. **外部 AI 提示词**：阶段提示词和完整提示词都支持；默认生成阶段提示词，也可按节点暂停或连续执行。
9. **复盘与验收建议**：针对 HTML、图片或 PPT 结果，指出具体位置、观察到的问题、可能意图、建议、验收等级和下一条提示词。大纲和逐页内容支持直接编辑、聊天提问修改，以及局部或全部重新生成。

字数、页数和信息密度约束应区分硬性要求与偏好。约束包括总字数、每页字数、标题长度、演讲备注时长和页面信息密度。若要求互相冲突，例如短时长、很多页和大量逐页文字同时出现，Agent 应说明冲突并提出压缩、拆页或移入备注的可选调整，不静默忽略约束。

## 4. 制作路线选择

Agent 根据可编辑性、视觉精度、修改方式、交付场景和用户指定工具，在以下路线中比较并推荐。路线是规划建议，不代表本工具会执行转换。

| 路线 | 适用条件 | 主要限制 |
|---|---|---|
| 原生可编辑 PPT | 用户优先要求 PowerPoint 内直接修改文字、图表和形状 | 复杂视觉效果可能需要简化；提示词要明确可编辑对象和版式规范 |
| 图片视觉稿后重建为 PPT | 用户优先追求高完成度视觉稿，并愿意在后续重建文本、图表和形状 | 整页图直接铺入 PPT 虽保留外观，但内容不可独立编辑；重建会有识别和位置误差，需逐页核验 |
| HTML 作为最终演示 | 需要快速迭代、网页呈现或 HTML 动效/交互 | 取决于播放设备和浏览器环境，不等同于 PowerPoint 文件 |
| HTML 转可编辑 PPT | 用户同时需要 HTML 迭代和 PowerPoint 可编辑交付 | CSS、字体、分页、动画和复杂元素可能无法忠实转换；必须将转换限制写入提示词和验收项 |

用户可以指定路线；指定后 Agent 仍需提醒与交付要求冲突的部分。对于风格参考，Agent 先输出简短的“风格/排版摘要”供用户校正，再用于大纲后的逐页视觉说明，避免过早细化设计。

用户没有特别说明时，最终交付目标默认为可编辑 PPT。HTML 或图片可以作为中间设计、视觉稿和反馈材料；只有用户明确接受时，才把不可编辑图片或纯 HTML 作为最终交付。

## 5. PPT 工作流程

1. **识别任务和材料**：判断用户在推进新想法、根据文件制作演示规划，还是诊断现有 AI 结果；识别各文件用途与明确约束。
2. **生成任务简报**：先生成可编辑简报，标出用户明确要求、助手推断和待确认项；用户可直接编辑或确认。
3. **生成临时规划**：基于用户想法和任务简报，先生成临时故事线、页数建议和大纲；临时事实和推断不得伪装成已验证来源。
4. **本机高召回初筛**：对用户选择的文件夹先列出支持格式，按文件名、目录、标题、页码和少量文字找候选；本机排序只负责尽量不漏候选，不丢弃未入选文件。
5. **模型语义复筛**：把候选摘要和片段合并成一次发送预览，用户确认后由模型按页或章节结合任务目标判断相关性、材料角色和优先级。信息不足时再申请指定文件或页面的更多文字、截图或缩略图。
6. **定向研究**：根据临时规划和复筛结果自动选择本地 Skill、工作流、脚本、教程、案例和外部资料。用户指定的仓库、网站、视频、图片、文件或文件夹必须检查；外部资料先展示搜索范围、候选来源和摘要。指定来源无法访问或解析失败时，明确显示失败原因；相似替代来源必须由用户确认后才能采用。
7. **解析内容与参考**：从内容来源提取论点、事实、数据、证据和限制；从风格参考提取视觉规则。内容相关性以文字为主，风格分析默认查看封面、目录、章节页、正文、图表/表格、图片页和结尾等代表页，必要时扩展到逐页视觉分析。
8. **生成资料增强版规划**：依据目标和听众自动推荐叙事结构并说明理由；用户可以改选或自定义结构。检查逻辑推进、观点与证据关系、必要内容和重复内容；按演讲时长、信息量和用户限制推荐页数，并解释估算假设。
9. **核对大纲和来源**：把大纲映射回原始材料，列出已保留要点、未纳入要点及原因、缺少证据的主张和需要用户确认的事实。没有可靠来源的数字、事实、案例或结论标为“待补证据”，用户可以继续临时草稿或暂停补证。文件内筛选按页/章节保留范围，所有引用保留页码；被筛掉的页面仍可查看和恢复。来源呈现方式由助手按场景建议放在页脚、演讲备注、参考文献页或来源附录，用户可以修改。
10. **生成逐页内容初稿**：为每页写清页面职责、标题/主结论、精简文案、演讲备注、引用/证据、视觉表达方向和前后页衔接。检查前后页衔接、单页负载、总页数、字数和信息密度约束。
11. **生成制作路线和提示词**：比较原生可编辑 PPT、HTML、图片重建和 HTML 转 PPT 等路线，先给推荐路线、理由、风险和所需材料，再生成阶段提示词或完整提示词。
12. **导入结果并行反馈**：导入 HTML、图片、本地页面、网页地址或应用内浏览器页面后先做轻量预检，同时允许用户标注。提交标注后执行结合用户意图的完整逐页验收。
13. **意图澄清、重跑与沉淀**：模糊反馈先提出可能意图；当前阶段最多识别 3 个会改变方案的问题，但界面一次只问 1 个，前一个答案使后续问题失去意义时立即停止。用户可重跑选中页面/文件、当前阶段或从相关性判断开始的全部流程，并附带不满意原因。每次重跑保留版本、差异和运行依据；只有用户点击保存的资料、偏好或成功/失败案例才进入个人资料库。
14. **文件变化处理**：原文件继续保留在原位置，应用保存文件标识、校验值、摘要和引用片段。文件移动或内容变化时只重新定位/解析受影响文件，相关摘要和大纲引用标为过期；展示新旧依据，用户确认后才更新受影响段落，其他未变化材料保留原结果。

## 6. 资料检索与案例规则

Agent 根据当前阶段自动决定资料类型，候选包括：

- PPT 文稿与故事线写作教程、信息组织和演讲方法。
- 文章写作、论证和内容编辑资料，用于提升来源材料的提炼、逻辑与表达；不直接把文章写作规则机械套到幻灯片文案。
- GitHub 上的 Agent/Skill、工作流、提示词、脚本、课程资料、示例项目和案例。
- 用户授权的本地资料、已保存提示词及已确认的成功/失败案例。
- 任务确有需要时的社媒讨论或其他外部资料，并标明来源类型和可信度限制。
- 用户明确指定的视频、图片、PDF、PPT/PPTX、网页和本地文件夹中的资料。

资料选择第一优先级是对当前任务是否有用。模型复筛结合任务目标、页面上下文、材料角色和适用场景判断；本机文件名、关键词或向量相似度只能用于召回候选，不能作为最终裁决。许可证和使用限制可作为来源信息保留，但第一版不把它们作为自动筛选门槛。读取外部仓库时，只取当前问题相关的 README 段落、Skill 步骤、脚本说明、测试或案例，不把整个仓库送进模型上下文，也不执行下载到的脚本。

公开样例、项目自述、用户真实使用结果是不同证据等级。样例只能证明项目展示过该产物；项目自述的成功/失败故事必须标为“来源自述、未独立验证”；只有有结果依据且经用户确认的本地复盘，才可作为已验证经验。失败经验应记录触发条件和适用边界，不能泛化为所有 PPT 的规则。

本轮 GitHub 调研可作为初始候选资料：

- [slide-maker](https://github.com/addsumtech/slides_maker)：MIT；参考读取来源、内容规划与视觉设计分步、故事线确认、独立审查和多场景展示。项目采用多 Agent 并生成成品，其 token/维护成本不作为本产品默认方案。
- [PPT Agent Skill](https://github.com/Akxan/ppt-agent-skill)：MIT；参考需求、搜集资料、大纲和逐页策划步骤及失败模式分类。固定长问卷和直接生成文件不照搬。
- [ImageGen PPTX Pipeline](https://github.com/eddyzzl/imagegen-pptx-pipeline)：MIT；参考图片视觉稿、逐页确认、可编辑对象重建和渲染核验的路线。其复杂生成流水线不纳入提示词 Agent 执行范围。
- [Image to Editable PPTX](https://github.com/algerchen2024/image-to-editable-pptx)：MIT；参考从扁平图片重建可编辑 PPT 对象的工作流和公开示例。
- [html-to-pptx](https://github.com/yuna78/html-to-pptx)：MIT；参考 HTML 到 PowerPoint 原生对象转换，以及分页、文字布局、动画等已知限制。
- [ppt-skills](https://github.com/xu-jin-cs/ppt-skills)：CC BY-NC-SA 4.0；参考从 PPT/截图反推风格和排版规则。该许可不允许商业使用，不能直接复用代码或文案；仅研究可独立表述的方法。

以上候选来自仓库说明和公开样例，不表示其内容经过独立质量评测。后续正式采纳资料时应重新核对当前版本、具体文件和许可。

本地知识资料和外部资料都采用“候选摘要/片段 → 模型语义判断 → 用户可排除 → 按需补充内容”的方式。助手应展示自动选中的来源、解决的问题、采用和舍弃的内容；用户可以排除来源后重新生成。页面相关性报告采用分层解释：纳入页面显示简短理由和来源，排除页面显示简短原因，不确定页面展开依据、缺口和恢复方式。多份风格参考先提取共同风格，冲突项单独列出；冲突会影响最终风格时询问主参考。研究完成后，用户可通过按钮把来源、提取出的规则或案例保存到个人资料库；未点击保存的内容只属于当前任务。

## 7. HTML 与图片标注

- 首版支持在应用内预览用户导入的 HTML 页面和图片，并附加点位或区域评论。
- 同时支持导入本地文件/文件夹、打开本地开发服务器页面、输入网页地址和选择应用内浏览器当前页面；这些材料统一转成可标注版本。
- HTML 标注应尽可能关联页面元素；无法稳定定位元素时退化为页面坐标。图片评论关联原图和标注区域。
- 标注支持框选/指向、文字说明和问题类型，例如内容、逻辑、证据、风格、排版、格式和可读性。
- 标注绑定输入文件版本或内容摘要；用户替换文件后提示重新检查过期标注，不把旧坐标套到新版本。
- 导入 HTML 在隔离环境预览，不获得桌面应用权限，不读取应用凭证或本机任意文件；默认限制页面网络访问。预览失败时保留源文件并提供截图或文本的替代反馈方式。
- Agent 可以总结、分类和解释标注，但不会直接改写 HTML、图片或 PPT。PPT/PPTX 的应用内逐页预览与直接标注不属于首版范围。
- 导入后先做轻量预检，用户可以同时添加标注；提交标注后再做完整验收。验收包含通用基础标准和场景专属标准，并按必须修复、建议优化、可接受差异分级。

## 8. Token、隐私与失败处理

- 本地检索优先，但本机只做高召回候选；模型语义复筛使用整批发送预览，预算由助手按任务规模自动安排，达到上限时暂停并显示已评估/未评估文件，可继续处理。
- 默认只发送候选摘要和代表性片段；摘要不足时再申请更多正文。内容相关性判断按需发送视觉页，风格分析默认发送代表页缩略图，必要时扩展到逐页视觉分析。
- 普通任务的外部搜索沿用通用 Agent 默认预算（最多 3 个查询、5 个来源）；需要超出时先展示范围和预算并确认。若用户明确要求“大量/全面搜索”或已指定本次必须查找的来源，则视为对该研究范围的明确授权：Agent 展示预计查询/来源范围、分批方案和可用工具限制后开始，不再重复询问是否搜索；用户仍可修改范围、暂停或取消。若搜索服务自身有硬性限制或需要产生额外费用，先说明限制或费用再继续。
- 指定本地文件或目录时，只处理用户明确选定/授权的路径；不因“搜索文件夹”而扩大到整个磁盘或未授权目录。指定在线视频、图片或文件但无法访问时，展示失败来源和原因，并允许用户上传本地副本或提供替代链接。
- 不将完整 PPT/PDF、全量 HTML 或用户私人内容默认发送到云端。外发前显示将发送的文本、选页/截图和引用资料，并允许删减。
- 原始 PPT、PDF、图片和其他导入文件默认保留在原位置；任务只保存文件标识、校验值、摘要、引用片段和页码。备份默认不包含原文件，用户可以单独选择纳入附件副本。完整本机提取文本不作为长期任务内容保存。
- 文件无法读取、页面渲染失败、搜索不可用或解析不完整时，保留草稿，清楚标出缺口，允许用户粘贴文本或补充截图；不得声称已完成完整审查。
- 文件移动或内容变化时只处理变化文件；受影响的引用先标为过期，展示新旧依据并等待用户确认后再更新大纲。
- 不自动存储上传文件为公开知识，不自动把未确认的建议或外部案例升级为已验证经验。
- 每次模型判断记录任务要求、候选页面/片段、视觉页、参考资料、提示词版本和时间；界面默认显示摘要，详细运行依据可展开。
- 用户修正相关性、页面范围、分类或风格规则时，默认只影响当前任务；点击保存后才成为个人偏好或成功/失败案例。重跑保留旧版本，可对比和恢复。
- 提示词生成支持阶段版和完整版本；阶段版默认。完整版本支持连续执行或按简报、资料、大纲、制作、验收等节点暂停确认。
- 阶段版和完整版本由同一份已确认的任务简报、资料、风格规则、路线和验收标准生成，避免两种提示词内容不一致。
- 完整提示词和阶段提示词都自动带入已确认的任务约束、来源和验收标准；目标 AI 未知时使用通用版并标出需要替换的能力项。

## 9. 首版验收标准

1. 助手能从想法或内容源文件开始，区分材料用途并生成有来源依据的大纲；用户可调整分类和保留项。
2. 助手能结合目标、听众、时长及字数/页数限制推荐页数，并指出互相冲突的要求。
3. 助手能给出逐页内容初稿，明确页面结论、证据、视觉说明和可选演讲备注；不会将长文章直接分页粘贴。
4. 助手能比较图片稿重建、HTML 成品、HTML 转 PPT、原生可编辑 PPT 等路线，说明可编辑性和转换风险，再生成适配所选路线的提示词。
5. 助手能自主检索相关本地及外部提示词、Skill、Agent、工作流、脚本、课程、案例和文章资料，展示来源、用途、采用/舍弃内容和验证状态；不要求用户逐一指定资料。
6. 用户明确要求大量搜索或指定必查来源时，系统按扩展计划开展搜索，显示来源覆盖、进度、访问失败和预算/工具限制；不再要求重复确认搜索意图。
7. 对指定视频、图片、PDF、`.ppt`、`.pptx` 和授权文件夹，系统按格式选择解析器，但使用同一套质量报告；报告包含可读取内容、已处理页面范围、提取失败、代表页视觉检查成功或失败，以及无法访问的来源。
8. 用户可在应用内预览并标注外部 AI 生成的 HTML 和图片；助手能把位置和意见转化为具体诊断及下一步修改提示词。
9. 成功、失败和待验证经验均带证据及适用条件；未获用户确认的经验不会标成已验证。
10. 整个过程不直接生成/修改最终 PPT，不执行外部仓库脚本，也不把完整知识库、文件或聊天历史反复发送给模型。
11. 本机相关性排序只负责高召回；模型可以按页/章节结合任务语义复筛，用户可以修改分类、恢复范围、选择重跑范围并查看判断依据。
12. 任务目标、听众、用途、页数或风格改变后，只重新运行受影响的模型判断，保留本机解析结果；用户明确选择时才执行更大范围重跑。
13. 导入的 HTML 或图片结果可先标注再验收，也可在轻量预检期间并行标注；PPT/PPTX 可导出为图片后进入同一反馈流程。标注会作为完整验收的高优先级用户意图。
14. 任务简报和逐页大纲可直接编辑，也可通过聊天提出修改问题，支持局部更新或全部重新生成；修改只影响依赖它的后续结果。
15. 每份风格参考支持必须遵守、主要参考、灵感参考和禁止模仿四种优先级；冲突参考不会被静默混合。
16. 页面相关性报告提供简短默认说明和可展开的详细依据；模型不使用没有依据的精确置信百分比。

## 10. 当前不做

- 不由提示词 Agent 直接生成、编辑或导出 PPT、HTML 或图片成品。
- 不首版内置图片生成器、HTML 制作器、PPTX 转换器或自由循环的多 Agent 工作团队。
- 不首版支持应用内逐页预览和标注 PPT/PPTX；用户可将需要反馈的页面导出为图片后标注。
- 不默认读取或发送整份长文件；解析结果和外发内容按页面/片段选择。
- 不把某个仓库的设计风格、课程观点或项目自述当作通用事实；需保留来源、局限和验证状态。

## 11. 与实施计划的关系

本设计稿只定义产品行为、数据边界和验收原则，具体实现拆分到以下计划：

- [PPT 内容规划与制作提示词](../plans/2026-10-20-ppt-content-planning.md)：任务简报、临时规划、资料增强版大纲、逐页文稿、制作路线和阶段/完整提示词。
- [PPT 资料搜索与文件解析](../plans/2026-10-20-ppt-source-research.md)：本机高召回候选、模型语义复筛、指定来源、文件/页面解析、发送预览和预算续跑。
- [PPT HTML 与图片反馈工作台](../plans/2026-10-20-ppt-visual-feedback.md)：导入预览、位置标注、并行轻量预检、完整验收、反馈诊断和版本重跑。

三份计划应复用现有提示词 Agent、研究 Agent、授权目录索引、模型发送预览和任务存储，不新增重复的全局检索器、自由循环 Agent 或成品生成器。
