# 写作工作台：结构化文档阶段规格

日期：2026-10-21
上位设计：`2026-10-20-writing-domain-expansion-design.md` 第 5–17 节
依赖：普通文章基线、共用核心 A/B/C、学术 A–D 已完成各自 D 盘开发版验收；复用现有材料、基础包、任务单元、问题、提示词版本、路线、保存和备份机制。
状态：实施依据

## 1. 目标与阶段边界

把蓝图“结构化文档”阶段列出的九类用途接入现有写作工作台：长篇研究文章、技术文档、商务文档、新闻/机构新闻稿、教程与课程、简历与求职、邮件、公文、法律文书。每类必须具有自己的适用范围、任务类型、输入要求、专属规则/提示词、路线或检查项、证据边界和代表任务；仅能选择文体或复用普通文章诊断/改稿不算完成。

长篇研究文章属于普通文章能力的扩展，不等于学术论文或系统综述。重点是跨章节规划、章节任务和材料范围、跨节术语/论点/证据追踪，以及将问题关联到产生它的结果版本并在新版本复核。学术研究内容沿用学术工作区和既有学术专项，不把结构化文档包当成学术替代入口。

在一个结构化文档工作区内，用户可建立/继续作品，选择明确任务，录入或选择材料及用途，选用可追溯的领域包，生成可编辑/复制的任务提示词，带回外部结果，定位候选问题并继续或复核。复杂任务可采用包内路线；简单邮件等任务保留最短路径。保存默认关闭，沿用现有历史、版本、材料预算和备份隐私边界。

本阶段以 D 盘浏览器开发版的代表任务可验收作为阶段门槛。Electron 桌面壳及安装/便携包另行记录；真机测试按用户要求暂缓。阶段不因真机暂缓而降低浏览器开发版验收要求。

## 2. 与现有工作台的关系

- 继续使用 `writingArticles`、`writingArticles[].rounds`、工作区单元/问题/路线快照、`knowledgeEntries`、现有基础包目录、材料入口、存储和工作区备份；不新建平行项目数据库或第二套材料库。
- 领域身份写入现有 `genre`，任务写入轮次 `taskType`；沿用 schema 白名单规范化、稳定 ID、版本号、来源和验证状态。旧 `article`、`academic-paper` 记录保持原行为。不得把用户现有工作区静默改成新文体。
- 复用核心 C 的章节/片段单元、问题显式状态流转、提示词版本、旧轮分支、路线来源快照和材料单元范围。专业包版本和实际采用条目必须进入轮次快照，以便停用/删除/更新包后仍可理解旧提示词。
- 复用核心 B 的来源定位、解析/未读取状态、用途区分、失败保留、附件提示及 3 份/每份 1200 字上下文预算。超限必须提示拆分或减选，不得静默截断关键约束。
- 复用共用核心 A 的包身份、来源许可说明、启用与验证状态、导入预览和历史快照规则。自定义包可启用不代表专业验证；缺少核对或案例的条目保持未验证。
- 在专业内容层分开构建九个领域配置/包。共享控件和数据契约可以复用，任务模板、方法、证据规则和验收标准不得互相冒名替代。

## 3. 领域任务矩阵

| 文体/领域 | 本阶段最小任务集合 | 专属输入与材料 | 必须实际检查/保留的边界 |
| --- | --- | --- | --- |
| 长篇研究文章 | 作品简报/全篇提纲、分节规划、分节诊断与改稿、跨节复核 | 读者、研究/写作目标、篇幅、章节职责、章节间关系、事实材料、作者样本、需跨节追踪的论点/术语/来源 | 单元范围正确；跨节关系可追溯；分节材料不泄漏到其他节；作者风格与事实来源分离；旧问题只在用户复核后关闭 |
| 技术文档 | 操作步骤、API/接口说明、设计说明、故障排查/恢复提示词 | 产品/组件与版本、环境、前置条件、角色/权限、输入、步骤、预期结果、错误现象/日志、恢复条件、接口资料 | 版本/环境及条件明确；动作顺序和可观察结果完整；错误与恢复路径不臆造；代码、命令及接口行为须由用户材料或实际验证支持 |
| 商务文档 | 报告、方案/计划、商业说明、营销内容的规划、诊断与定向改稿 | 组织/场景、受众、决策或目标行动、产品/服务事实、数据来源、品牌样本、约束和有效期 | 事实与主张有来源；目标行动和执行条件清楚；风格样本不成为产品事实；预测、承诺和成效数据不得补造；营销效果不作保证 |
| 新闻/机构新闻稿 | 事实表/消息结构、采访材料整理、稿件诊断/改稿、发布前核对提示词 | 事件时间线、采访者/来源、原始引语、可公开身份、图片/资料说明、机构口径、发布时间和修订状态 | 事实、引语、背景、推断和评论分开；引语不改写成原话；时间、归属和未证实项可定位；机构口径需由用户提供并与事实分开 |
| 教程与课程 | 学习目标与课程/教程规划、课节/步骤、示例和练习设计、学习者检查 | 学习者、先备知识、可观察学习目标、时长、示例/环境、练习、反馈方式、完成条件 | 顺序和难度递进；示例对应目标；练习可观察地检验目标；答案/反馈范围明确；不宣称已通过真实学习者测试，除非有记录 |
| 简历与求职 | 经历盘点、岗位适配、简历要点/项目经历、求职信诊断与定向改写提示词 | 用户确认的真实经历/成果/指标、岗位描述、目标职位/地区、格式要求、求职信语境 | 不虚构职责、年限、学历、指标或技能；岗位关键词映射到真实证据；可标记待用户核实，不自动升级经历事实 |
| 邮件 | 请求、答复、跟进、告知/协调邮件的起草提示词、改稿和发送前检查 | 收件人关系/角色、目的、往来上下文、必须传达事实、期限、行动项、语气和披露边界 | 目的和请求清晰；行动人/期限可辨；引用往来不改变原意；不替用户发送，不虚构承诺或代为披露敏感内容 |
| 公文 | 按用户指定文种进行材料整理、结构规划、措辞检查提示词 | 文种、发文主体/对象、组织层级、事项依据、时点、用户提供的现行格式/制度/模板 | 文种与行文关系须由用户确认；规范有来源、版本、适用组织和时点；模板仅作格式材料；不宣称普遍合规或可直接签发 |
| 法律文书 | 事实材料分类、用户指定文书结构辅助、待核对清单和律师审校提示词 | 法域/地区、适用时点、程序/文书类型、当事方角色、用户提供事实/文件/来源、保密限制 | 事实、主张、证据和待证事项分开；引法/程序规则必须绑定可核来源和时点；明确缺失信息及需执业专业人士审阅；不提供法律意见、结果预测或适格性保证 |

法律、公文任务的要求可能因法域、组织、文种和时点变化；包内容必须记录适用条件和来源版本。来源未经核验时只能作为用户材料或待查线索，不能显示为现行规则。

## 4. 领域包与提示词内容契约

每个领域建立独立、版本化的内置文体包；包内可以有多个专项任务/路线。包至少具备：

1. 稳定包 ID、名称、文体、版本、内容结构版本、支持的任务类型、启用状态和验证状态。
2. 适用/不适用条件、必填/可选输入、关键澄清问题、默认值和必须停下等待用户决定的歧义。
3. 专属材料及用途规则，指出哪些材料是事实/证据、风格样本、要求模板、反馈或背景；记录当前轮真正采用的 ID、位置、版本、解析状态和附件要求。
4. 任务步骤的目的、输入、输出、可检查完成条件、跳过条件、缺项退回条件及来源 ID。单步任务可明确声明不需要路线。
5. 任务类型对应的提示词模块、字段组合、结构/格式要求、语气/术语规则、证据规则、常见失误和修复方向。
6. 有来源的专业要求标明出处、具体条目、版本/日期、许可、适用范围、限制及验证状态。自拟建议需标“临时建议”或“原创操作建议”，不得冒充规范。
7. 至少一个代表案例/固定模拟结果及预期的应用状态变化。案例仅能验证范围内的流程/接线，不自动证明专业结论或真实模型质量。

不适用的内容要说明理由并链接到适用的通用/共用能力；不得用空字段掩盖缺项。方法包可共享任务框架和校验工具，但九个领域各自定义内容、路线与示例。默认每轮只加载适用、启用且被选中的少量条目，不拼入整个包库。

## 5. 字段、证据状态与提示词规则

- 沿用现有工作区字段 `genre`、`goal`、`audience`、`platform`、`preserveItems`、`dimensions`、`constraints`、`successCriteria`、`draft`、`packSelections`、`sourceArticleId`、`research`；仅为确实需要的结构化输入增加有长度/数量上限的白名单字段。字段落在领域任务扩展对象或最小领域字段中由实施时依照现有 schema 选择，不把全部行业字段塞入每个工作区。
- `taskType` 必须稳定且具领域语义；不得让所有领域只落到 `diagnosis`/`revision`。通用 `diagnosis`、`revision` 可作为共享能力，但领域任务提示词必须额外消费本领域输入、输出要求与风险约束。
- 材料/摘录来源状态沿用 `unverified`、`source-reviewed`、`user-confirmed` 等现有状态；包验证沿用 `unverified`、`source-reviewed`、`case-validated`。不得将“用户选择”“包启用”“提示词已复制”自动解释为来源已核验、专业已验证或模型已执行。
- 每轮快照必须保存任务类型、实际采用的包及条目/来源版本、所选单元摘要、材料 ID/定位/用途/读取状态、生成提示词版本；结果来源不明时维持未关联状态。
- 用户带回的结果先作为外部结果原文或候选；机器诊断为候选问题，只有用户显式接受/修改/拒绝/标记复核后才改变问题状态。新稿不能自动解决旧问题。
- 提示词只声明实际提供的输入。对未读取附件、缺失来源、截取文本、版本不明、需要用户验证的事实明确提示；禁止将前缀截取称为摘要，将风格材料当作事实依据，或伪造已完成步骤。
- 当前无模型时仍可编辑、复制提示词并回填固定案例；模型质量和专业结论不得因此被宣称通过。

## 6. 任务入口和界面行为

- 新建工作区时可选择九类中的文体，并显示简洁的适用说明；既有工作区保留原文体和原任务，不因新增能力自动迁移。
- 工作台提供任务类型选择/切换；切换时先提示哪些输入将保留、哪些领域字段不适用，并由用户明确确认，不删除历史轮次、材料和问题。新任务若实质上属于其他文体，建议另建工作区。
- 仍允许用户直接粘贴目标和文本开始；根据领域任务显示必需澄清项。简单邮件可在最短步骤直接产出提示词；法律/公文等关键适用范围缺失时，不能生成声称满足规范的专业提示词，应生成补充信息/专业审校提示词并呈现缺项。
- 任务包选择区显示推荐原因、适用范围、版本、来源/验证状态和实际生效条目。无可用专业包时可走通用提示词，并显著说明未获得该领域专用支持。
- 复杂任务显示当前步骤和简短路线；步骤确认、跳过、受阻和用户提供结果均沿用核心 C 的显式状态。路线调整不修改原包版本。
- 材料区使用核心 B 的统一卡片、用途、预算和错误状态；单元范围控制跨节材料。提示词预览与复制内容必须完全一致，并显示未采用材料和外部附件要求。
- 结果区支持粘贴外部结果、关联提示词版本、查看差异、形成候选问题、人工状态流转、跨轮复核及从旧轮建立新分支。
- UI 桌面、390px 窄屏和键盘代表路径可用；加载/保存/解析/调用失败均保留输入并明确报告。

## 7. 数据、隐私与兼容

- 项目保存默认关闭。关闭期间的本次会话可继续操作，但不得持久化新轮；开启后按现有约定保存工作区及所需版本快照。材料保存到资料库仍须单独明确操作。
- 项目删除按现有范围确认并删除其历史快照；仅停用/移除包不能删除历史轮次。历史保存当时采用条目的必要快照，用户删除对应历史后不保留幽灵副本。
- 工作区完整备份需按现有白名单保留领域任务、材料定位、轮次、包/来源快照和问题关联；资料库备份继续排除正文、反馈和写作历史。绝对本机路径、目录授权、密钥、未保存附件原文不得进入数据或导出。
- 新 schema 字段限长、限数并过滤未知字段；旧文章/学术工作区、旧轮次、旧备份不含新字段时正常读取，补默认值但不伪造记录。存储/备份变更只有在白名单确需扩展时才做，并用往返测试证明。
- 导入第三方包仍先预览来源、许可、适用范围、版本和冲突；不执行包内脚本或安装命令。
- 搜索/模型/解析请求沿用现有预览、授权和失败处理。不得因新增领域包而自动上传全文、发送未选材料或打开网络搜索。

## 8. 分阶段实施切片

按“可独立使用的一组任务”逐批交付；每批完成对应领域完整任务闭环和应用验收后再进入下一批。所有九类均在本阶段总范围内，不得把后两批只做成静态下拉项。

### 切片一：长篇研究文章 + 技术文档

先做共同领域任务契约与提示词路由，再交付两类各自独立的工作流。长篇研究文章验证跨节单元、来源/术语和未解决问题复核；技术文档验证环境/版本、前置条件、步骤、预期结果和故障恢复。完成后两类均有内置包、来源映射、提示词、结果回填、诊断/复核、历史保存兼容和代表用例。

### 切片二：商务文档 + 新闻/机构新闻稿 + 教程与课程

分别交付商务事实/受众/行动目标、新闻事实/引语/时间和教程学习目标/示例/练习的独立字段、提示词与核对路线。三类都要在提示词中消费各自输入、回填候选后可定位和复核；不可共用同一“文章润色”结果验收。

### 切片三：简历与求职 + 邮件 + 公文 + 法律文书

分别交付真实经历与岗位映射、收件关系/往来/行动项、组织/文种要求和法域/时点/事实分类。对求职、事务邮件提供短路径；公文和法律关键适用信息不足时提供缺项/审校路径。必须通过不虚构事实、发送边界、现行来源和专业审校边界检查。

三切片共享一个最小、可扩展但非通用化的字段/包装载机制；不建设插件市场、任意脚本运行时、完整文档编辑器或自动代写系统。

## 9. 明确不实现/不宣称

- 不把该阶段做成富文本编辑器、自动发布/发送工具、法务/人力/新闻审签系统或自动化内容生产代理。
- 不声称技术文档中的命令/接口/实现已通过实际运行；没有用户环境或执行证据时只生成检查步骤。
- 不声称商务预测、销售转化、营销效果或新闻事实真实；应用只追踪用户材料及待核验状态。
- 不声称教程已对真实学习者有效，除非完成并留存用户测试证据。
- 不替用户确认简历经历或指标；不替用户发送邮件；不推断未提供的沟通承诺。
- 不提供法律意见、法律结论、诉讼策略或结果预测，不确认文书效力、程序适格或当前法律状态；法律文书功能仅支持用户提供材料的分类、结构化写作提示词、来源核对清单和执业专业人士审阅。
- 不宣称公文格式/程序对所有机关或时间有效；必须由用户指定组织/文种/时点并提供或核验适用规范。
- 不宣称本阶段完成社媒、视频、播客、演讲、小说或剧本；这些属于其他蓝图阶段。
- 不把内置包写入 docs 就视为应用已支持；必须进入运行包目录和实际打包路径，并完成各领域应用任务。
- 不因固定模拟回填通过而宣称外部模型输出质量、专业判断正确性或真实部署通过。

## 10. 验收标准

### 10.1 数据与共用机制

1. 九个文体均可新建独立工作区；旧普通文章和学术工作区可回读、继续生成原行为的提示词。
2. 每类至少有清晰区分的领域任务类型和实际使用的内置包/条目；包的版本、来源、许可说明、适用条件、验证状态可查看，未审查内容不显示已审查。
3. 工作区、轮次、单元、材料、问题、路线和包版本之间的 ID/快照关系可检查；关闭保存不开新历史，开启后刷新可恢复；备份往返保持关系和隐私边界。
4. 未知字段、超限内容、凭证、绝对路径、未授权附件经 schema/备份后不进入持久化/导出；旧备份仍可恢复。
5. 单元和材料范围限制实际提示词内容；超限、解析失败、未读取、未提供来源和外部附件要求清晰可见，不伪装为完整读取。
6. 提示词编辑、复制、结果回填和提示词版本关联可用；未关联来源保持明确未关联；复制不表示发送或执行。
7. 问题与原结果版本关联，机器诊断先产生候选；新版本复核后由用户决定状态，不自动关闭。

### 10.2 九类代表性应用路径

每个领域至少完成“新建/继续 → 输入领域要求与材料 → 选择本领域包和任务 → 预览/复制专属提示词 → 粘贴固定模拟外部结果 → 查看有定位的候选问题 → 人工确认/修订后生成下一步提示词 → 保存/刷新/版本回看”的代表闭环；短任务可减少路线步骤，但不能省略领域输入和边界。

| 领域 | 应用验收必须证明 |
| --- | --- |
| 长篇研究文章 | 两个以上章节分别采用材料；生成跨节规划/复核；章节约束和证据进入提示词；旧问题在新轮显式复核；作者样本只作为风格用途 |
| 技术文档 | 提供版本/环境、前置条件、操作和预期结果；故障材料形成恢复检查提示词；未知命令/行为被标为待运行验证 |
| 商务文档 | 受众、业务目标、行动和产品事实进入提示词；风格样本不带入事实；无证据指标保持待核实 |
| 新闻/机构新闻稿 | 固定素材含不同时间、来源和引语；结果可区分事实/观点/归属并指出待核内容；不把未核实口径变成事实 |
| 教程与课程 | 学习目标、先备知识、示例、练习和完成检查在路线中对应；完成状态由用户确认，模拟案例不代表学习者测试 |
| 简历与求职 | 岗位描述逐项映射用户提供经历；缺失指标/职责不补造；可把候选改写带回并核对事实保真 |
| 邮件 | 根据给定往来生成不同目的的邮件提示词，突出收件关系、行动人和期限；应用不执行发送、无来源承诺需确认 |
| 公文 | 必须选择具体组织/文种/时点及要求来源；缺失或冲突时明确受阻/待核验，不显示通用合规结论 |
| 法律文书 | 法域/时点/文种缺失时走补充信息路径；固定材料中事实/主张/证据分开；提示专业人士审阅，不给法律结论或效力保证 |

### 10.3 质量门槛与验收记录

- 每切片运行新增/受影响单测与对应工作台、包、存储/备份专项；适当时运行 `pnpm check` 和 `git diff --check`。测试覆盖契约，不替代应用验收。
- 在 D 盘浏览器开发版执行本切片代表场景，检查刷新恢复、旧数据兼容、390×844 窄屏、键盘操作、控制台错误和实际提示词内容。模拟结果须标明仅验证数据/流程接线。
- 更新本规格对应的实施计划执行记录和单独验收记录；由于本阶段当前约定只创建规格/计划，此阶段后续实现者负责新增验收记录并更新蓝图状态，本规格不预先改写上位蓝图。
- 真机测试暂缓并明确标为未验证，不阻断 D 盘浏览器开发版任务验收；Electron 壳、安装/便携产物、真实模型/解析器和真实用户测试分别记录，不能与浏览器验收合并宣称通过。
- 只有九类代表路径全部在应用中运行、内置包进入打包路径且工作区兼容/隐私门槛通过，才可把结构化文档阶段标为可验收。单个已通过切片不得使整个阶段状态提前变为完成。
