# 写作工作台视听与社媒阶段规格

日期：2026-10-21
上位设计：`docs/superpowers/specs/2026-10-20-writing-domain-expansion-design.md` 第 5—17 节
依赖：共用核心 A/B/C、材料入口与来源、基础包管理，以及学术 A—D 已完成当前阶段验收
状态：供实施依据

## 1. 目标与边界

在统一写作工作台中交付五类可单独使用的专属任务：

1. 社媒图文：单条内容、图文组/轮播、系列内容及已有内容的平台化改编。
2. 短视频：短视频选题、分段脚本、镜头/画面提示和已有视频脚本优化。
3. 口播：单人讲述、讲解、产品/观点介绍及口语化改稿。
4. 播客：单人节目、多人对谈、采访提纲/问题及节目脚本优化。
5. 演讲：面向特定听众和场合的演讲结构、讲稿提示词、现场表达及演讲稿优化。

工作台仍交付可编辑、可复制、可带回结果继续优化的提示词与任务记录；外部 AI 负责按提示词生成正文、脚本或讲稿。应用不自动替用户发布内容、录音录像、执行平台操作或证明内容符合平台规则。平台名称、场景标签、风格样本、模型建议、播放/互动数据都不能证明平台合规、事实正确或内容有效。

本阶段沿用现有原生 JavaScript、DOM、Electron、写作 schema/coordinator/UI、基础包、材料、轮次、保存与工作区备份。不建设社媒发布器、平台 API、自动抓取/趋势系统、内容日历服务、视频/音频编辑器、自动转写、全文编辑器、账号连接、云数据库或新模型服务。若现有能力不能读取某类附件，保留材料条目及失败/未读取状态，允许手动摘录，不宣称已处理。

## 2. 基线与复用约束

当前正式文体只有普通文章与学术论文/学位论文。工作台已有按文体配置的 schema、任务类型、基础包选择、材料用途、来源快照、提示词版本、外部结果带回、问题/路线、保存和备份机制；写作项目保存默认关闭。材料摘录与提示词有长度/数量限制，扩展时不得静默截断、把未选择材料带入提示词，或破坏旧文章/学术项目。

本阶段以现有 `writingArticles` 工作区和轮次为载体，增加明确的社媒/视听文体与任务契约；遵循实际代码布局，复用既有模块，不创建通用插件框架、服务端平台适配层或平行存储。兼容旧工作区：缺少新字段时保持原文体、任务与默认行为；已有文章和学术轮次不得被重新解释为新文体。

## 3. 任务模型与采集字段

每一轮必须有一个明确任务类型。所有字段均可编辑；缺少非关键字段时以“未提供”进入提示词，不阻止用户直接开始。只有会改变产物或安全边界的关键歧义才提示用户补充，仍允许生成标明假设的起步提示词。

### 3.1 共用字段

| 字段 | 规则与提示词用途 |
| --- | --- |
| 文体与任务类型 | 明确五类之一及本轮动作（起草、规划、改编、诊断、定向优化）；历史轮保留生成时类型。 |
| 平台/场景 | 用户选择平台或填写场景、内容形态、活动/栏目；保存用户原始写法。未提供平台要求时不得补写平台规则。 |
| 目标与行动 | 本条内容要传达什么、读者/听众看完后需要理解或采取什么行动；不默认要求营销转化。 |
| 受众 | 对象、熟悉程度、语言/地域语境及必要的排除对象；未提供时不推测人口统计属性。 |
| 时长/篇幅 | 按任务使用目标时长、字数、段数或组数。估时只能作为创作规划，不承诺实际口播时长或平台限制。 |
| 格式/结构 | 用户指定的字段、分段、字幕、镜头、对白、舞台提示、标题/正文/标签等；平台格式要求需关联来源与核对状态。 |
| 风格样本 | 仅按用户选定范围提炼表达方式；样本中的主张、数据、引语不得转作事实来源。用户本轮更正优先于样本与记忆。 |
| 材料/事实来源 | 选择内容/事实、风格、要求/规则、反例或反馈材料，保留来源标识、版本/日期、位置、用途和读取/核验状态。 |
| 约束与保留项 | 必须出现、不得出现、可改范围、品牌/角色/术语约束；冲突可见，不能静默丢弃。 |
| 带回结果 | 保存外部结果原文及其来源提示词版本；用户可附实际表现数据、观众反馈或修改意见，所有外部结论与数据保留“用户提供/未独立核验”状态。 |

### 3.2 专属输入、输出与检查

| 任务 | 专属输入 | 提示词要求的外部产物 | 带回后检查重点 |
| --- | --- | --- | --- |
| 社媒图文 | 单条/轮播/系列；平台与内容形态；标题、正文、图文页/卡片数、标签或行动项格式；系列内各条关系 | 逐条给出内容结构与可复制文本；轮播按页标注，系列标注条目顺序；标签仅在用户要求时生成 | 平台/格式要求是否有来源和时点；事实与来源是否对应；风格/事实用途是否混淆；各条重复或前后矛盾；格式是否符合用户给定要求 |
| 短视频 | 平台/分发场景、目标时长、受众、主题；开场方向、镜头/画面/字幕/旁白字段、节奏或段落要求 | 按时间段或场次输出脚本，区分口播、画面、字幕、音效/转场等用户所需轨道；给出估算时长及其假设 | 目标时长与分段估算是否自洽；开场、信息顺序、画面与旁白是否匹配；无来源的性能/算法断言须标为假设；实际表现数据只按用户提供记录 |
| 口播 | 独白/讲解/介绍等场景；目标时长；说话人身份或角色、对听众关系；语速、停顿、情绪和可说性偏好 | 输出口语化、可朗读的文本，可按段给时长/停顿/重音提示；用户未要求时不加镜头或多人角色 | 朗读顺畅、句长、术语解释、节奏、语气与说话人一致；时长为估算；不将脚本流畅度当作事实核验 |
| 播客 | 单人/多人/采访；节目/栏目场景、目标时长、主持人与嘉宾角色/说话人；段落、提问次序、互动与引用材料 | 输出节目结构或对白脚本，逐句标注说话人；采访问题应开放且可追问，区分主持人提示与嘉宾未提供的回答；标记引用和音频提示（如用户需要） | 发言归属明确、对话自然、段落衔接、时长估算；不为真实嘉宾编造观点/回答/经历，不把未提供的引语当成事实 |
| 演讲 | 场合、听众与熟悉程度、说话人/演讲者、目标时长、现场/线上、互动与行动目标；正式度和节奏 | 输出开场、论点/段落、过渡、结尾及可选现场提示；分段估时并标注需演讲者核实的个人经历、数据与引语 | 论点与事实来源可追溯；听众理解路径、节奏、现场互动适配；经历和承诺未由演讲者确认前保持占位；估时不等于实际时长 |

所有任务的改编和优化都必须保留用户指定的含义、事实和约束；指出不确定/矛盾项，不能通过增强语气把猜测写成事实。

## 4. 平台规则、事实与可追溯来源

### 4.1 来源记录和使用

每条使用的专业方法、平台要求、品牌要求或事实依据，至少关联：稳定来源 ID、来源名称/发布方、具体文件/网页/条目或原文定位、版本或发布日期（未知时明确缺失）、访问/提供日期、URL 或本地材料位置、适用平台/场景/对象、读取状态、核验状态、许可信息（适用时）、采用理由和限制。用户提供的来源、内置包公开参考、模型建议和个人偏好须能区分。提示词与带回结果保存实际采用的来源/基础包快照，历史不依赖当前可变包内容。

平台名称本身不是规则来源。只有用户明确提供并选择了规则材料、版本和适用范围时，提示词才能把它表述为“用户指定的待遵循要求”；来源已读取也不等于要求仍然有效或应用已判定合规。来源缺版本、未读取、冲突或无法访问时，明确标为未核对/有冲突，并可生成“请按该来源核对”的提示词。任何界面、提示词、诊断和验收记录不得出现“已符合平台政策/算法”“平台保证推荐/流量”等无证据结论。

事实材料与风格样本、平台要求、个人偏好分开选用。每条事实性内容可关联一个或多个材料/来源及原文位置；无来源内容标为用户提供、待核实或创作性表达。应用只记录来源与用户/外部模型提出的对应关系，不自动认证事实真实或来源支持结论。未读取附件、仅有标题/摘要、手工复制内容或查询摘要都不得描述成已核验全文。模型建议作为待确认候选，不能改写用户确认状态。

### 4.2 专业基础包

新增至少一个视听与社媒内置基础包，含任务类型、适用/不适用范围、需求采集、材料用途、原创提示词骨架、可选路线、输出结构、风格规则、事实/平台边界、可观察检查项、失败修复方向、正反例及来源/验证记录。可按社媒图文、短视频/口播、播客、演讲拆分条目，但同一阶段可沿用现有包管理结构，不要求建立多包框架。

包内每项方法和检查规则关联来源或明确标“原创启发性建议”；记录来源具体位置、版本/摘要、读取日期、许可审查、适用范围和局限。未经实际案例复核的内容标为待审查/未验证；启用不等于验证。平台规则作为易变资料，不硬编码为永久通用限制，不将第三方推广指标或算法技巧作为已证实规律。

## 5. 工作台流程与提示词

### 5.1 基本流程

用户选择任务 → 填写或粘贴目标 → 选择平台/场景、受众和任务所需参数 → 选择事实材料、风格样本及要求来源 → 查看范围、未读取/未核验/冲突提示 → 生成可编辑提示词 → 复制给外部 AI → 带回结果并关联实际提示词版本 → 查看静态检查/候选问题 → 用户确认后优化或开始新轮。

简短任务不强制填写全量字段、不强制创建复杂路线；多平台改编、系列内容、多人节目等复杂任务才显示简短可编辑路线与当前步骤。路线来自当前选用且适用的基础包，逐步标明方法/规则来源、输入、产出、检查、可跳过条件和缺项退回条件。临时建议须明确标为临时建议。

### 5.2 提示词生成契约

生成的提示词需：

- 清楚标注文体、任务类型、平台/场景和目标；每个缺失字段标“未提供”，只在用户许可的前提下采用显式假设。
- 将受众、时长/篇幅、说话人、节奏、格式、风格样本、事实材料、平台/品牌要求、约束和反馈分区列出，并保留材料 ID/标题/位置/状态。
- 区分事实依据、要求来源、风格样本和创意建议；不可把风格或要求材料当事实证据。
- 若要求平台规则或事实核对，明确要求外部 AI 提供逐项来源/位置、标注无法核实之处；外部回答只形成待用户检查的候选，提示词本身不构成核验。
- 不虚构平台政策、算法机制、热度数据、用户反馈、说话人身份、真实经历、采访回答、引语、产品能力或其他事实；缺信息时用待补占位符或提出关键问题。
- 明确产品只生成提示词；输出正文、脚本、讲稿、文案和发布行为由外部工具/用户完成。
- 在工作台现有长度/材料预算内完整保留关键约束和来源。超限时说明超限与具体材料范围，允许用户缩减/分批；不得静默截断后继续宣称完整。

### 5.3 结果带回与诊断

外部结果保存原文、任务类型、关联的提示词版本（不确定时标为未关联）、所选材料与来源快照、用户反馈/实际表现数据及其来源状态。提示词复制只记录复制动作，不等于已发送、发布或执行。

可提供本地静态观察，例如字段缺失、分段时长合计、说话人标签未定义、引用标记无对应来源、用户要求与输出格式不匹配、超出用户设定字数。静态观察不得等同于事实核验、平台合规审查、效果预测或专业判断。模型诊断只在用户主动发起并使用现有发送预览/确认机制后运行；无模型或调用失败时保留输入和本地提示词，显示“模型诊断未执行”，允许手工检查与复制。

## 6. 本机保存、备份与失效边界

- 沿用写作项目保存默认关闭和现有本机保存开关。开启后新字段、来源/包快照、提示词版本、带回结果与确认状态按现有写作工作区保存；暂停保存不删除已保存历史。
- 完整工作区备份保留新文体和任务历史；资料库备份继续排除正文、外部结果、反馈和写作历史。备份导入替换/合并使用现有校验、去重和路径/凭证清理规则。
- 不把平台账户凭证、cookies、个人本机绝对路径、未选附件或未保存附件内容写入提示词、历史或备份。链接和文件仍遵循材料授权与实际读取范围。
- 原文体和旧轮次可读取、复制、比较、续建；删除任务不误删其引用的资料库来源。来源变更或不可用时保留旧快照并提示差异。
- 保存、备份、模型、材料读取任一失败时明确报告失败阶段，保留用户输入和可复制提示词，不伪装成功或覆盖较新的轮次。

## 7. 验收标准

### 7.1 自动化与静态验收

1. schema 测试覆盖五类文体/任务类型、字段枚举和上限、旧数据兼容、未知字段与敏感路径/凭证清理。
2. 基础包测试覆盖任务适用范围、来源定位/版本/许可/状态、条目来源关联、内置包实际进入运行时目录及版本快照；未验证案例不被显示为已验证。
3. 提示词测试为五类任务逐项验证专属字段实际进入输出，材料按用途分区，风格观点不进入事实，未选/未读取材料不被当作已采用，规则与事实均保留来源状态；缺项和不确定性不被补造。
4. 提示词超限不静默丢失关键约束、来源或末尾反馈；分批/缩减后提示词版本准确保存。
5. 协调器、存储和备份测试覆盖生成/复制/外部结果带回/提示词版本关联/从历史开新轮、开关保存、备份往返及旧数据读取；迟到结果不能覆盖新轮次。
6. UI 测试覆盖五类任务的实际控件与操作、材料用途/来源状态、提示词预览和复制、结果带回、错误保稿、键盘操作及小视口无横向溢出。
7. 跑本阶段定向测试、写作工作台/基础包/存储/备份回归、项目 `pnpm check` 和 `git diff --check`。不以这些检查代替应用操作验收。

### 7.2 五类代表性应用路径

每条路径均使用隔离的合成材料及模拟外部结果，除非用户另行授权，不发送真实账号数据、私有内容或未选附件。

| 任务 | 必须在应用中走通的路径 |
| --- | --- |
| 社媒图文 | 建立单条或轮播任务；指定平台/场景、受众、格式、目标与一条事实来源及一份风格样本；确认生成提示词分开标识来源和样本；带回模拟图文，定位一项事实待核查/格式待确认项并生成优化提示词。 |
| 短视频 | 建立指定平台和目标时长的分段脚本；填写受众、开场方向、节奏、口播/画面/字幕格式及事实材料；验证各轨道和时长假设进入提示词；带回模拟脚本并核对估时与素材来源状态。 |
| 口播 | 建立单人讲解/介绍；填写说话人、听众、时长、语速/停顿和风格样本；提示词要求口语化但不扩写事实；带回模拟稿，完成静态可说性/时长检查并保留待核实事实。 |
| 播客 | 建立主持人与嘉宾的采访/对谈；提供说话人角色、栏目场景、时长、段落/节奏、问题材料和来源；验证脚本按说话人区分且不替真实嘉宾编造回答；带回模拟结果并提出一条人工确认的优化要求。 |
| 演讲 | 建立指定场合和听众的演讲；填写演讲者、目标时长、互动、节奏、事实材料与个人风格样本；验证占位经历/来源保留；带回模拟讲稿并按段落结构、估时和事实待核状态复核。 |

### 7.3 真实应用与环境边界

- 使用 D 盘主项目启动的应用，优先在 Electron 中完成五条路径；可用浏览器开发版完成应用路径，但结论须明确标出实际运行载体。采用隔离的 Electron 用户数据或临时工作区，避免污染日常项目。
- 每条路径实际操作任务选择、参数输入、材料/来源选择、提示词查看/复制、结果带回和再次生成；开启保存后刷新，检查来源、任务类型、提示词版本和结果关系恢复；同时验证默认关闭/暂停行为。
- 在桌面和 390×844 窄屏检查关键控件无横向溢出；用键盘完成任务选择、表单、材料选择、生成、复制/结果带回和错误提示阅读。检查页面错误、控制台错误/警告及模型/网络请求是否符合预期。
- 模型未配置时，五类提示词生成、编辑、复制、结果手工带回和本地可观察检查仍可完成；深度诊断显示未执行，不把模拟响应写成真实模型成功。真实模型效果、真机测试、Windows 安装包/便携版分别记录，不以模拟或浏览器视口代替。
- 验收记录列出每个要求的通过/受限/未验证状态、具体操作证据、截图/状态证据位置、定向测试结果和剩余限制。完成阶段后才更新上位蓝图状态；不得在本规格阶段将其标为已实现。

## 8. 上位蓝图映射

本规格落实第 5 节的社媒图文、短视频/口播、播客和演讲领域任务；第 6—7 节的领域基础包、来源许可与验证记录；第 8—9 节的任务入口和资料用途；第 11—13 节的可追溯判断、版本和上下文范围；第 14—15 节的窄屏/键盘、失败降级、授权与不可信材料边界；第 16—17 节的分阶段交付和代表任务应用验收。共用能力按 A01—A25 实际涉及项映射验收，不能以提示词生成成功替代来源、材料范围、保存、键盘或应用路径验收。

## 9. 当前设计假设

1. 五类任务继续处于同一个写作工作台和项目/轮次模型中，任务区按所选类型显示专属字段；不另建“社媒智能体”或平台自动化产品。
2. “平台/场景”由用户选择或填写，首阶段不承诺任何平台的固定规则预置；平台要求优先作为用户提供的有版本来源材料处理。
3. 不增加新依赖或外部 API；无法解析的音视频附件可手动摘录并如实显示未解析状态。
4. 估时与内容诊断是提示词/静态检查建议，不构成准确时长、传播效果、事实正确或合规保证。
5. 真实模型、真实平台规则有效性、真机和安装版可作为用户后续实施的测试；阶段仍须先达到无真实模型情况下的开发版可验收状态。
