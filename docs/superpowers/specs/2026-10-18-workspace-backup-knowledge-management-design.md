# 工作区备份与资料库增强设计

日期：2026-10-18
状态：设计已确认，等待生成实现计划

## 1. 背景与目标

当前应用使用浏览器 `localStorage` 保存项目、提示词、案例、资料条目和选择状态，并通过 `knowledgeEntries` 在运行时建立统一的本地资料索引。

本次优化不立即引入 SQLite、向量数据库或 embedding。目标是在现有存储和资料索引基础上，补齐以下能力：

1. 完整工作区备份、仅资料库导出、导入预览、替换、合并和自动备份。
2. 资料来源感知的编辑、删除、隐藏、收藏、置顶和最近使用管理。
3. 不增加运行时依赖的中文搜索增强。
4. 发送预览中的字符/token 统计、敏感信息检测和外发确认。
5. 案例证据、适用边界和版本历史。

## 2. 设计原则

- **先增强现有系统**：继续使用当前状态迁移和 `knowledgeEntries` 结构，不为了功能增加数据库。
- **来源与索引分离**：资料库条目是统一索引，不等同于原始项目、提示词、案例或方法卡。
- **用户确认优先**：资料是否验证、案例是否复用、内容是否外发，都不能由系统静默决定。
- **可恢复**：导入、替换、合并、清空和批量删除前先自动备份。
- **少传内容**：搜索本地完成；只有用户选择的摘要进入发送预览和模型上下文。
- **可替换边界**：未来需要 SQLite 或语义检索时，只替换存储或检索实现，不改变用户操作契约。

## 3. 总体架构

本次功能拆成五个模块，共用现有工作区状态：

1. **工作区备份**：负责导出、导入、校验、替换、合并和自动备份。
2. **资料库管理**：负责来源感知的编辑、删除、隐藏、收藏、置顶和最近使用。
3. **本地搜索增强**：负责别名、同义词、中文短语拆分、命中解释和无结果建议。
4. **发送安全预览**：负责内容分层、字符/token 估算、敏感信息检测和确认。
5. **案例版本管理**：负责证据、适用边界、复盘历史和当前版本索引。

整体数据流：

```text
本地工作区状态
  -> 统一资料索引
  -> 用户筛选、查看、编辑或选择
  -> 发送预览
  -> 用户确认后可选外发
```

当前不引入数据库。资料规模明显增长后，优先评估 SQLite/FTS5；只有关键词检索持续漏召回且满足本地运行条件时，才评估 embedding。

## 4. 工作区备份

### 4.1 导出范围

支持两种 JSON 导出：

- `workspace`：项目、提示词、案例、资料库、收藏、最近使用、当前筛选和选择状态。
- `knowledge-base`：资料条目、资料元数据和必要的案例关联，不包含完整项目工作区。

备份文件使用普通 JSON，便于查看、迁移和手动修复。文件必须包含：

```json
{
  "format": "forward-step-workspace",
  "schemaVersion": 1,
  "appVersion": "0.1.0",
  "exportedAt": "2026-10-18T12:00:00.000Z",
  "scope": "workspace",
  "counts": {},
  "data": {}
}
```

导出前递归剔除模型 API Key、搜索 API Key 和其他凭证字段。导出界面必须提示：备份可能包含项目内容、提示词、案例证据和用户原文。

### 4.2 导入流程

导入不直接写入当前状态，流程固定为：

1. 读取并解析 JSON。
2. 校验 `format`、`schemaVersion`、`scope` 和核心数据类型。
3. 显示项目、提示词、案例、资料数量及冲突数量。
4. 自动备份当前工作区。
5. 用户选择“替换”或“合并”。
6. 写入成功后显示新增、覆盖、跳过和冲突统计。

替换适用于重装恢复。合并适用于把旧资料或其他工作区资料加入当前工作区。合并以稳定 `id` 去重，冲突默认保留当前数据并报告冲突。

### 4.3 自动备份

在以下操作前自动备份：

- 导入
- 替换
- 合并
- 清空资料
- 批量删除

每天首次启动额外备份一次，保留最近 5 份。Electron 桌面版写入用户数据目录；浏览器开发模式提供下载备份，不写入项目目录。

### 4.4 错误处理

- 非 JSON、格式不匹配或核心字段损坏：拒绝导入，当前数据不变。
- 旧版本：先迁移再预览。
- 新版本：拒绝导入并说明需要升级应用。
- 写入失败：保持当前数据不变，保留导入前备份。
- 替换、清空和批量删除：必须二次确认。

## 5. 资料库管理

### 5.1 索引元数据

在现有资料条目基础上增加索引元数据：

```text
sourceKind       manual / prompt / case / method-card / reference
sourceId         原始数据 ID
hiddenAt         从资料库移除的时间，可为空
favorite         是否收藏
pinned           是否置顶
lastUsedAt       最近使用时间，可为空
customAliases    用户自定义别名
```

这些字段只描述资料索引，不覆盖原始项目、提示词、案例或方法卡。

### 5.2 编辑和删除

- 手动资料可直接编辑和删除。
- 提示词通过原提示词编辑。
- 案例通过原案例或案例版本编辑。
- 方法卡通过方法卡编辑。
- 公开资料编辑来源摘要和资料字段。
- “从资料库移除”只设置 `hiddenAt`，不删除原始数据。
- “删除原始数据”才会删除对应来源及其关联索引。

批量操作支持批量收藏、批量隐藏和批量恢复索引。批量删除只允许作用于手动资料，并且必须先自动备份和二次确认。

### 5.3 收藏和最近使用

- 收藏和置顶状态持久化，不设数量上限。
- 用户搜索、查看详情或把资料加入发送预览时更新 `lastUsedAt`。
- 最近使用默认保留 20 条记录。
- 界面提供“收藏”和“最近使用”快速筛选。

## 6. 中文搜索增强

搜索流程：

```text
原始查询
  -> 清理和标准化
  -> 同义词、别名扩展
  -> 中文短语和双字词拆分
  -> 搜索标题、关键词、摘要、方法和局限
  -> 记录命中词与命中字段
  -> 加权排序并高亮结果
```

首版只使用本地规则，不引入运行时依赖。内置词典包含：

```text
提示词 <-> prompt
复核 <-> review
验收 <-> 测试
计划 <-> 方案
案例 <-> 示例
失败 <-> 问题
```

用户可以添加自定义别名。排序优先级为标题、关键词、可借鉴方法、摘要、局限/正文摘录。每条结果显示命中字段和命中词。

无结果时，从资料标题和关键词中生成本地相近词建议，不调用模型。

## 7. 发送边界与安全预览

发送面板分为三层：

1. 基础提示词。
2. 用户选择的本地资料摘要。
3. 用户粘贴的外部内容。

每一层显示来源。预览顶部显示预计字符数、近似 token 数、资料数量、外部原文数量和疑似敏感信息数量。

本地规则检测以下风险：

- 常见 API Key
- 密码、token、secret、api_key 配置行
- 手机号、邮箱和身份证号
- 私钥头部
- 数据库连接字符串
- Authorization Header

普通风险高亮并允许用户编辑、删除或继续发送。API Key、密码、私钥和数据库密码等高风险内容必须明确确认后才能发送。系统不自动替换原文。

删除一条资料后，发送文本、字符统计和 token 估算同步减少。模型请求失败时保留发送面板、用户编辑内容和资料选择，不自动重试或清空。

## 8. 案例版本和质量

### 8.1 版本结构

保留当前案例字段，增加：

```text
currentVersion
versionHistory
evidence
applicableWhen
notApplicableWhen
reviewCount
lastReviewedAt
```

第一次确认形成 v1。修改结论、证据、经验或下一条提示词时，保留旧版本并生成新版本。当前版本是默认生效版本。

### 8.2 检索和复用

- 搜索默认只使用当前版本。
- 历史版本只在详情和版本对比界面显示。
- 重新复盘同一案例默认生成新版本，不生成重复案例。
- 案例资料卡同步当前版本。
- 用户可以标记案例为“暂不复用”，但保留历史记录。

每个确认案例应尽量记录：发生了什么、依据是什么、什么有效、什么偏离、下一次怎么做、适用场景和不适用场景。

### 8.3 删除

删除原始案例前自动备份并二次确认，同时移除其当前资料卡索引。历史版本随案例一起保留在备份中，不能单独成为默认搜索结果。

## 9. 使用场景

### 场景一：重装后恢复工作区

用户先导出完整工作区 JSON。重装后导入文件，系统显示项目、提示词、案例和资料数量，自动备份当前空工作区，用户选择“替换”，恢复原有工作状态和资料选择。

### 场景二：把旧资料加入当前工作区

用户导入仅资料库 JSON，系统显示新增和冲突数量，自动备份当前资料，用户选择“合并”。同 ID 条目保留当前版本，新资料进入统一索引。

### 场景三：维护资料库

用户搜索“复核 prompt”，系统通过别名命中“提示词复核”。用户将常用方法收藏；查看详情或加入发送预览后，该条资料进入最近使用。手动资料可直接编辑，公开资料则通过来源字段修改。

### 场景四：控制模型外发

用户选择三条摘要后，发送预览显示资料来源、字符数和近似 token 数。检测到粘贴内容包含邮箱和疑似 API Key，邮箱被提醒，API Key 要求明确确认。用户删除敏感段落后再发送。

### 场景五：修正一次失败经验

用户打开失败案例，发现 v1 没有记录第二次测试结果。创建 v2，补充证据、适用范围和变更原因。搜索默认显示 v2，用户仍可查看 v1 与 v2 的差异。

## 10. 测试和验收

### 备份

- 完整工作区导出包含所有业务数据但不含凭证。
- 仅资料库导出不包含无关项目内容。
- 导入预览能显示数量和冲突。
- 替换和合并行为正确。
- 导入、清空和批量删除前会生成自动备份。
- 损坏文件不会改变当前数据。

### 资料库

- 手动资料可编辑和删除。
- 派生资料编辑入口指向原始来源。
- 隐藏索引不会删除原始数据。
- 收藏、置顶和最近使用可持久化。
- 批量操作不会越过来源删除边界。

### 搜索

- 同义词和别名可以命中目标资料。
- 中文短语拆分不会破坏现有精确搜索。
- 结果包含命中词和命中字段。
- 无结果时只生成本地建议。

### 发送安全

- 字符和 token 估算随资料选择变化。
- 风险内容被高亮并显示来源。
- 高风险内容未确认时不能发送。
- 请求失败保留草稿和发送面板。

### 案例

- 首次确认生成 v1。
- 修改案例生成新版本，不覆盖历史。
- 搜索默认只使用当前版本。
- 案例资料卡与当前版本保持一致。

## 11. 非目标

- 本次不引入 SQLite、向量数据库或 embedding 依赖。
- 本次不自动抓取全网资料。
- 本次不自动发送用户未选择的内容。
- 本次不做云同步、账号系统或多用户协作。
- 本次不做自动修改文章、PPT、代码等最终成果。
