# 写作工作台与提示词 Agent 分步向导设计

日期：2026-10-23

## 问题

写作工作台和提示词 Agent 在一个页面里平铺十几个功能区块。用户进入页面后不知道第一步做什么、什么时候做什么。两个模块的功能本身可用（现有测试全部通过），问题是信息架构。

## 目标

- 每个屏幕只显示当前步骤的内容，用户不需要在一屏里找入口。
- 步骤条显示全部阶段和就绪状态，已解锁步骤随时可以点回去修改。
- 复用社媒研究页已经验证过的向导样式与交互规则，保持全应用一致。

## 范围

- 第一阶段：写作工作台（`prototype/writing-workbench-ui.js`）。
- 第二阶段：提示词 Agent（`prototype/prompt-agent-ui.js`）复用同一套模式。
- 不改变协调器、schema、提示词生成逻辑；只重排 UI。

## 写作工作台四步向导

### 步骤划分

| 步骤 | 名称 | 内容（现有区块） | 解锁条件 |
|---|---|---|---|
| 1 | 文章目标 | 文章列表、标题、文体、目标、受众、平台、成功标准、保留项、约束、诊断维度、文体专属信息、基础包勾选、长文规划区（大纲/设定/章节） | 始终可用 |
| 2 | 参考材料 | 材料粘贴/导入/资料库选择、公开链接、风格档案、用户纠正、研究检索 | 已有文章（工作区存在） |
| 3 | 初检与提示词 | 本地初检、诊断、下一轮提示词、模型诊断、写作路线 | 已有文章 |
| 4 | 带回结果 | 外部新稿、反馈、来源提示词版本、偏好候选、显式记忆 | 已有文章且有提示词版本 |

### 步骤条与页面结构

页面顶部放四个步骤按钮，样式与社媒研究一致（`.social-wizard-steps` / `.social-wizard-step`）：

1. 文章目标
2. 参考材料
3. 初检与提示词
4. 带回结果（就绪徽标：存在提示词版本时显示）

每步内容包在 `<div class="social-wizard-panel" id="writing-wizard-stage-N" hidden>` 中，同一时刻只显示一个。步骤 2、3、4 解锁后可自由往返。

### 自动前进规则

- 新建文章成功 → 自动进入步骤 2。
- 回带结果成功 → 自动回到步骤 3（新的一轮）。
- 删除文章 → 回到步骤 1，2-4 重新锁定。
- 用户手动切换步骤后，自动前进不再覆盖用户选择，直到下一次明确的成功事件（新建/回带）。

### 高级折叠区

以下低频内容收进页面底部「高级」`<details>`，不占步骤：

- 删除整篇文章按钮
- 本机保存开关与状态
- 导出提示词历史 / 导出工作区备份
- 全部写作记忆管理
- 专业基础包管理器
- 历史轮次

其中历史轮次在步骤 4 中提供指向链接（点击展开高级区并滚动到位）。

## 提示词 Agent 分步向导（第二阶段）

同一套样式与规则，三步：

| 步骤 | 名称 | 内容 | 解锁条件 |
|---|---|---|---|
| 1 | 任务描述 | 场景选择（任务/写作/PPT）、任务输入 | 始终可用 |
| 2 | 提示词生成 | 生成的提示词、诊断、外部结果回填 | 已生成提示词 |
| 3 | 复核与迭代 | 复核记录、历史轮次 | 存在复核记录或历史 |

详细交互在第一阶段完成后按同一模式细化并补充到本文档。

## 错误与边界

- 步骤 2-4 在无文章时显示锁定状态（按钮 disabled，文案说明需要先在第 1 步新建文章）。
- 材料读取中锁定跨步骤按钮，与现有 `processingMaterials` 行为一致。
- `busy`（本地初检/模型请求进行中）时允许查看其他步骤，但修改目标、回带结果按钮禁用，与现状一致。
- 刷新页面后恢复到派生的当前步骤（有文章则至少步骤 2），不依赖额外持久化字段。

## 测试计划

- 现有 DOM 测试改为通过 `#writing-wizard-stage-N` 容器查询元素；全部通过。
- `tests/prompt-agent-integration.test.js` 在第二阶段同样补向导测试。
- `npm run check` 与全量 `node --test` 通过。

## 非目标

- 不合并或删除任何现有功能。
- 不改动提示词内容与协调器逻辑。
- 不做移动端专属新布局；现有响应式样式继续生效。
