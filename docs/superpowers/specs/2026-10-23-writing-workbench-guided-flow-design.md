# 写作工作台分步引导设计

日期：2026-10-23

状态：原有四步流程已实现；2026-10-23 确认全文件夹检索与可选 Jev 判断设计，待评审。

## 1. 目标

把写作工作台从信息密集的单页表单改为按任务推进的引导流程。用户进入后能明确知道先做什么、Agent 会判断什么、何时需要用户确认，以及如何把外部 AI 的结果带回来继续修改。

本工作台服务所有文章类型，包括普通文章、手册、论文、小说、营销内容、邮件、演讲稿等。应用的主要交付仍是可编辑、可复制的提示词；不要求应用直接代写正文。

“新建规划”和“写作工作台”解决不同阶段的问题：“新建规划”用于目标尚未理清、需要先梳理研究和执行路线的复杂任务；“写作工作台”用于目标已有大致方向、准备形成并迭代写作提示词的任务。工作台内的新写作和文章改写走同一套完整流程，复杂度和后续步骤没有区别：两者都要确认材料、分析任务、确认文体与规则、生成提示词并带回结果。两者只在起始输入上不同：新写作从目标开始；改写先提供原文，再描述改写目标。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 文章类型 | 用户用自然语言描述任务；Agent 推荐文体和任务类型，用户确认或修改 |
| 任务模式 | 工作台首屏提供“新写作”和“文章改写”选择；两者共用全部后续流程，新写作不需要原文，改写必须先提供原文。二者没有轻重流程之分 |
| 与新建规划的关系 | “新建规划”用于需要先梳理目标、研究和执行路线的复杂写作；已有大致目标、准备形成写作提示词时进入工作台。新写作不因没有原文而被排除在工作台之外 |
| 页面边界 | 写作工作台、通用提示词 Agent、学术论文工作台是独立页面和导航入口；写作与提示词 Agent 不互相作为内部场景，学术文献/综述/投稿模块不挂在写作页或通用 Agent 页下 |
| 首屏输入 | 新写作直接描述写作目标；改写先提供待改原文，再描述改写目标。两类任务都可添加文件、文件夹或工作空间 |
| 工作空间 | 可临时添加本次文件夹，也可选择已保存的常用工作空间 |
| 文件范围 | 文件夹/工作空间与额外导入文件合并；工作台在本机逐个扫描全部可读候选的全文，按任务检索带路径和位置的相关片段，再交主模型判断；不把整个目录或所有全文上传 |
| 全文检索边界 | 全文只在本机逐文件扫描，不把全文持久化或长期保留在内存；只保留有界检索索引、命中片段和定位。每次扫描显示范围、进度、可读/排除/未扫描数量；模型可在有界轮次内请求追加检索 |
| 材料选择范围 | 模型可从任意数量的候选文件中检索和推荐；不设 3/5 份文件数上限，实际送入模型的片段按相关性及当前模型上下文预算控制。用户仍可查看依据并确认/移除材料 |
| Jev 配置 | 在现有模型设置中单独配置 Jev 服务地址、模型名和凭证；凭证沿用服务端安全配置机制。未配置时任务开关禁用；主模型设置保持独立 |
| Jev | 每次任务可选启用，默认关闭；仅辅助候选片段排序、文体/任务等有界分类，不读取文件、不生成最终提示词。开启时 Jev 先处理有界检索结果，主模型再复核证据并生成最终判断/提示词；Jev 失败或结果不确定时主模型独立完成这些工作 |
| 中文评估 | 不预设 Jev 的中文质量或整体提速效果；用代表性中文任务样本对比启用/关闭结果，再决定是否推荐默认启用。需要评估材料命中质量、分类质量、端到端耗时与请求成本 |
| 待改原文 | 与参考材料分区。长手册可单独从 TXT、MD、DOCX 或 PDF 文件导入；支持整本处理提示词，或提取目录后选择章节。原文不计入参考材料数量上限 |
| 原文解析边界 | 复用现有本机解析器：DOCX/PDF 文件最大 20 MB，PDF 最多 100 页，提取文本最多 30,000 字符；超限时保留文件名和用户输入，提示改用更小文件或按章节拆分。整本处理仍可提示外部 AI 使用原附件 |
| 目录候选呈现 | 默认展示可读取、可索引的候选材料及全文检索命中；构建产物、临时文件和不支持的文件默认过滤或折叠。用紧凑列表分页呈现，不逐项铺开格式错误信息 |
| 参考材料上限 | 不按文件份数限制候选搜索或最终推荐；按检索片段总量和实际模型上下文预算控制。待改原文仍与参考材料分开，不参与项目资料检索预算 |
| 规则包 | 参考材料与“软著内容”等专业规则包可以同时选择；规则包不占用材料数量上限，并按自身适用范围生效 |
| 需求信息 | Agent 先识别任务所需信息和缺口，只显示本任务需要的内容；用户可以修改判断和建议值 |
| 文体专业性 | 按确认后的文体加载对应规则和字段，不让所有文体共用一张大表单 |
| 阶段导航 | 默认沿引导流程前进；已经完成的阶段可返回修改 |
| 结果闭环 | 用户把外部 AI 的结果贴回工作台，再生成检查或下一轮修改提示词 |

## 3. 主流程

```text
选择任务：新写作 / 文章改写
        ↓
新写作：描述写作目标；文章改写：导入/粘贴待改原文 → 选择整本处理或指定章节 → 描述改写目标
        ↓
两种模式共用：添加文件夹/工作空间及额外参考文件 → 本机全文检索 → 查看并确认相关材料
        ↓
（用户可选 Jev）对有界候选片段排序/分类
        ↓
主模型复核证据、必要时请求追加检索 → 用户确认材料与判断并生成提示词
        ↓
选择可叠加的参考材料与专业规则包，确认本任务必需的信息与约束
        ↓
生成、检查并复制提示词
        ↓
粘贴外部 AI 结果 → 生成复核或下一轮提示词
```

用户可从已完成的步骤返回修改。修改目标、文体或材料后，界面提示哪些后续结果可能需要重新生成；不静默保留与新输入不一致的提示词或分析。

## 4. 页面步骤与交互

四步使用同一任务页面和固定进度条，页面主体每次只呈现当前步骤。进度条显示“描述任务、确认方向、生成提示词、带回结果”；已完成步骤可点击返回，当前步骤有明确的标题、说明和一个主按钮。每步的次要动作保持轻量，不再同时铺开后续所有表单。

### 第一步：提供原文、描述目标并添加材料

**页面目标：** 首屏提供“新写作”和“文章改写”选择。新写作用户直接说明想写什么；改写用户先提供要处理的原文，再说明希望怎样改。模式差异只决定原文是否必填，之后共用材料、任务分析、方向确认、提示词和结果回填步骤。需要先梳理目标、研究和执行路线的复杂写作仍从“新建规划”进入；该入口不替代工作台的新写作模式。用户不需要预先理解文体分类或填写通用问卷。

**页面内容：**

1. 新写作模式直接显示写作目标；文章改写模式显示独立的“待改原文”区域，可粘贴短文或从文件导入长文档，随后填写“希望怎么改”。长文档导入显示文件名、解析状态和可用目录，不要求用户把全文粘进文本框。检查模式可引用已有文本，并由 Agent 判断任务类型。
2. 待改原文提供两种处理范围：**整本处理**生成要求外部 AI 按章节分批工作的提示词；**选择章节**从可识别的标题/目录提取章节供用户勾选，再生成限定章节范围的提示词。DOCX/PDF 复用本机解析能力，单文件最大 20 MB，PDF 最多 100 页，提取最多 30,000 字符；超出边界时明确提示，不宣称已读取全文。解析文本和目录用于本地预览与任务判断，不把整本原文塞进分析请求或复制出的提示词。整本与选章模式都要求用户在外部 AI 中附上原文件；提示词带上所选章节标题和可用的页码/位置。目录未识别或解析不完整时，保留文件和改写目标，允许手动填写章节标题/范围，或切换整本处理。
3. “参考材料”独立成区，提供选文件、临时添加文件夹、选择已保存工作空间三个入口。工作空间入口也允许保存新选的文件夹供以后使用。常用工作空间显示已保存的名称；浏览器需重新选择文件夹时，核对根目录名和已保存的相对路径/文件版本，确认后才恢复勾选，避免误用同名目录。操作手册若同时位于代码目录，可从待改原文区单独导入，不依赖它在代码候选列表中的排序或格式支持。
4. 文件夹或工作空间索引与额外参考文件累加显示，不互相替换。重复文件按来源标识/相对路径去重。用户提交任务后，工作台对所有支持且未触发安全排除的候选逐个进行本机全文扫描，按任务描述、文件名/路径及模型请求的检索词查找片段；全文不上传、不持久化，也不把全目录全文同时保留在内存。扫描采用有界处理并及时释放单文件全文，只保留检索所需的有界索引、命中片段及文件定位。常见构建目录、压缩产物（如 `.min.js`）、临时文件和不支持格式默认过滤或折叠；提供搜索和“显示已过滤文件”入口，用户可恢复误过滤文件。沿用现有最多 10,000 个文件的扫描上限；触及单文件大小或文件数边界、取消或读取失败时显示已扫描范围和未扫描提示，不静默遗漏。
5. 页面以纵向分区卡片呈现“待改原文”和“辅助参考材料”，避免把超长原文框与文件目录混成一块。候选以紧凑行展示文件名、相对路径、扫描/推荐状态和依据；摘录按需展开，移除操作放在行内，不为每个文件重复铺开错误段落和大按钮。列表按每页 20 项分页。初始展示扫描进度、已扫描/可读/排除/未扫描数量和命中的材料；搜索覆盖全部已扫描全文，而非仅当前页或已选文件。候选数量不限制模型检索范围；发送给模型的相关片段按相关性和上下文预算裁剪，并保留来源定位。用户可确认或移除建议材料；不再显示“最多 3/5 份”限制。扫描中、没有可读文件、无命中、存在过滤项等状态以汇总说明和对应操作呈现；过滤项默认折叠。
6. 底部主按钮为“确认材料并分析任务”。没有参考文件时仍可继续；系统只提醒本次分析不会参考项目文件。仅粘贴原文也可继续改写。

**交互顺序：** 新写作先录入目标；改写先导入/粘贴原文，选择整本或章节范围，再描述目标。两种模式随后共用全文检索、材料确认、任务分析、方向确认、提示词和结果回填。文件夹全文只在本机逐文件检索，用户可查看完整扫描状态；检索片段按上下文预算有界。若启用 Jev，先将任务摘要和有界命中片段交给 Jev 排序/分类，再由主模型复核证据；未启用时由主模型直接完成判断。主模型可在有限检索轮次内要求补充查询词或读取命中位置。只将实际命中的有界片段发送给已启用的模型，不发送全目录或完整全文。Jev 每次可选且默认关闭，需独立配置；主模型始终负责证据综合、最终文体/任务判断与提示词生成。中文样本验证前不推荐默认启用。用户可查看来源和判断依据并确认/移除材料，不设 3/5 份文件硬上限，最终上下文按模型预算控制。长原文与辅助材料分别管理：待改手册全文不进入任务分析或复制出的提示词。整本与选章提示词均说明需要附上原文件，选章提示词附带章节标题及解析得到的页码/位置；无法解析位置时清楚标记为“位置未识别”，不伪造页码。文件解析、目录识别或扫描达到上限时显示具体状态，不丢失原文、改写目标和检索进度，并提供重试、重新选择或手动指定章节的入口。

#### 全文件夹检索与模型复核

1. **本机全文扫描：** 对已授权文件夹中可读取的支持格式逐个扫描全文。沿用安全排除规则、现有文本格式及每文件 1 MB 上限、10,000 文件上限；不新增未经验证的总字节数硬限制。全文只在处理单个文件时短暂驻留，不写入 localStorage、任务记录或服务端日志；文件处理后立即释放正文。扫描需分批让出浏览器主线程，可取消，并显示进度、已完成范围和未扫描原因。
2. **有界检索：** 使用任务描述、路径/文件名和全文命中定位相关段落。系统仅保留有界的倒排/关键词索引与命中片段，不缓存全量文档正文。中文按词语及连续字片段建立可检索项，英文和代码按词项检索；不得因分词缺失而退回仅搜抽样摘录。每条片段附文件 ID、相对路径和行号/页码等实际可得位置。
3. **模型检索循环：** 先用用户任务文本进行本机检索，再把命中片段及文件清单交主模型复核。主模型可按固定结构提出追加搜索词或对特定命中文件请求更多邻近片段；宿主应用只在用户本次授权的候选集合中执行读取，限制追加轮次与累计输入预算。模型不得自行访问浏览器、磁盘或未授权路径。达到轮次/预算上限时返回当前证据并明确说明检索范围。
4. **材料确认：** 模型结果包含候选文件、相关片段、位置、与任务的关联理由和不确定项。用户可展开原文命中片段、确认或移除候选。文件数量不构成硬上限；将实际选定的片段按主模型上下文预算发送到最终分析。若预算不足，按相关度和跨文件覆盖度裁剪并说明哪些材料未进入当前分析，不把未送达模型的材料标成已分析。
5. **Jev 可选判断：** 设置页有独立 Jev 服务配置，复用应用现有的服务端凭证保护方式；配置项包括服务地址、模型名和凭证。未配置或测试连接不可用时，任务开关禁用并显示原因。每次任务的“使用 Jev 辅助判断”默认关闭，开关旁明确说明启用后任务摘要和命中片段会发送到已配置的 Jev 服务。启用后仅将任务摘要及有界候选片段交给 Jev 做候选排序和预设分类（如文体、任务类型、材料关联度）；不得让 Jev 读取文件、执行搜索或生成最终提示词。主模型仍生成最终判断和提示词。Jev 不可用、超时、输出不合法、低置信或与证据矛盾时，显示原因并回退主模型，不阻断任务。
6. **中文效果验证：** 使用可复现的中文任务/文件夹样本，分别记录 Jev 关闭与开启时的材料相关性命中、任务/文体分类、错误推荐、最终提示词依据忠实度与可执行性（人工盲评）、端到端耗时及请求成本；评估样本须标注正确材料、类别及提示词评价标准。未经此评估不宣称 Jev 更快、更有效或能提升最终提示词质量，也不默认开启。

参考 Jev 的官方 Agent Skill 与社区工作流时，仅借鉴“宿主保留执行和权限、Jev 处理有界结构化决策”的分工；不直接把面向编码 Agent 的技能当作浏览器文件系统实现。官方项目入口：[jev-model-ai](https://github.com/jevmodel/jev-model-ai)；可供工作流对照的示例：[marcodicesare-dev/jev-skill](https://github.com/marcodicesare-dev/jev-skill)。这些仓库说明集成模式，不构成中文质量或本项目收益的证据。

### 第二步：确认方向

**页面目标：** 让用户看懂 Agent 对任务的理解，并有机会纠正。

**页面内容：**

1. 顶部用一句话复述任务，例如“根据项目实际功能，检查并改进操作手册”。
2. 用可编辑的选择控件显示“推荐文体”和“任务类型”，例如“操作/技术文档”和“依据项目资料优化现有文章”。旁边简述推荐依据，支持展开查看。
3. 下方只显示当前任务需要的补充项。Agent 可从文章或材料中预填；每项标记为“来自材料”“Agent 建议”或“需要你确认”。
4. 把真正阻止后续提示词准确生成的问题放在“还需要确认”区域；其他字段折叠在“更多设置”中或采用明确标注的默认值。
5. 展示本次将使用的材料摘要，可返回第一步调整材料。
6. 提供与参考材料并列、可独立选择的专业规则包区域。“软著内容”规则包可在普通文章或操作/技术文档等适配文体下由用户主动选择；它不替代或排斥参考文件，也不计入 3 份直接参考材料上限。默认不因用户提到软著而静默启用；显示包名和简短适用说明，用户可随时取消。
7. 主按钮为“确认，生成提示词”；次按钮为“返回修改目标”。

**确认规则：** 文体和任务类型始终由用户确认后才进入下一步。用户可接受 Agent 建议，也可手动更改。参考材料与规则包是两种独立输入，可同时启用；规则包按明确的兼容文体/任务元数据决定可选范围。若模型不可用或无法判断，直接显示可搜索的文体选择和简短说明，其他已填内容保留。

### 第三步：生成提示词

**页面目标：** 交付可直接使用、可自行修改的提示词，并让用户知道它依据什么生成。

**页面内容：**

1. 主体是可编辑的提示词文本区，默认完整展开，支持复制。
2. 提示词上方显示确认后的文体、任务类型；旁边提供“修改任务设置”返回第二步。
3. 提示词下方用紧凑摘要分别列出采用的参考材料和规则包。二者可同时出现在提示词依据中；材料可展开查看，规则包显示名称和适用范围，避免默认占据主要阅读区域。
4. 主按钮为“复制提示词”，另提供“我已在其他 AI 中使用”进入结果回填；若产品已有模型直连能力，沿用已有调用方式和发送预览，不在本设计中新增调用行为。
5. 用户编辑提示词后，保留其版本；若返回修改目标或材料，提示当前提示词基于旧信息，可选择更新生成或保留为手动版本。

### 第四步：带回结果

**页面目标：** 让外部 AI 结果回到同一任务，形成可继续的改稿闭环。

**页面内容：**

1. 页面顶部简要回顾任务目标和已使用提示词，支持展开查看。
2. 一个明显的粘贴区用于带回外部 AI 输出；可选附加“这次结果哪里不满意”的反馈。
3. 主按钮为“检查这份结果”。执行后在同一页显示检查结果，问题按影响排序并尽量定位到原文片段；区分事实/材料缺口、结构问题和表达问题，不把建议伪装成已核实事实。检查使用已确认的任务和材料；结果内容仅在用户触发检查后发送给配置的模型。
4. 用户可勾选本轮要处理的问题或补充反馈；主按钮随后显示“生成下一轮修改提示词”。此操作把本轮结果和反馈作为新一轮输入，提示词进入第三步预览，并保留本轮检查结果。
5. 提供“本轮完成”结束操作；结束后可从任务历史继续，不强迫用户进入下一轮。

### 阶段回退与状态变化

- 点击进度条中的已完成阶段可返回；未完成阶段不可跳过必要确认直接标成完成。
- 修改目标会使任务判断、提示词和结果检查标记为“可能过期”；修改材料会使引用这些材料的分析与提示词标记为“需要更新”。
- 对过期内容提供明确的“重新分析/重新生成”和“保留当前版本”操作，不自动覆盖用户手动修改过的提示词。
- 每一步保留未完成输入；切换步骤或遇到临时错误不清空文本。

## 5. 通用与文体专属信息

通用步骤只收集目标、文章/材料和必要约束。确认文体后，再显示对应的专属信息，例如：

- 操作手册：软件版本、目标读者、实际功能依据。
- 学术论文：研究类型、学科、目标期刊或学校要求。
- 小说：视角、人物设定、连续性约束。
- 社媒内容：平台、受众、篇幅或格式限制。

Agent 可以根据已有材料预填或建议这些信息；每项建议都能编辑。缺少非必要信息不阻断流程。

## 6. 状态与错误处理

- 文件无法读取：显示具体文件和原因，允许移除、重选或继续使用其他材料。
- 全文扫描达到文件数/单文件大小上限、用户取消或浏览器读取失败：显示本次已扫描、未扫描和不可读数量/范围；允许缩小范围或继续使用当前命中。未扫描部分不得显示为“不相关”或“已读”。
- 全文搜索无命中或命中不足：允许主模型提出追加检索词并在有界轮次内重搜；仍无证据时明确标记证据不足，用户可手动搜索、选文件或继续不带项目材料。
- 浏览器刷新、关闭或取消扫描：不恢复未保存的全文或索引；保留已保存的任务文字和已确认材料元数据，并提示重新选择文件夹后重新扫描。
- Jev 不可用、超时、返回结构错误或置信不足：保留主模型路径并继续；界面说明本次未采用 Jev 判断，不伪称已完成双模型校验。
- Jev 未配置或配置无效：设置页提供独立配置/连接检查入口；任务页禁用 Jev 开关并说明需先配置，主模型写作流程仍可使用。
- Jev 与主模型结论冲突：展示双方各自对应的证据片段和不确定点，由主模型依据原文证据复核，最终由用户确认；不得自动隐藏冲突或将 Jev 结论作为事实。
- 原文格式不支持或解析超限：说明当前支持 TXT、MD、DOCX、PDF；DOCX/PDF 最大 20 MB、PDF 最多 100 页、可提取文本最多 30,000 字符。保留其他输入，允许重选文件或手动输入章节范围；扫描版 PDF OCR 结果须标明需人工核对。
- 目录提取不完整：明确标识已识别的章节和未识别状态；用户可手动补充标题/范围或切换整本处理，不把不完整目录显示成完整目录。
- 目录文件数达到 10,000 上限：显示扫描未完成提示和范围；允许缩小文件夹或改用搜索/手动导入，不把未扫描部分当作无关文件。
- 本地文件对象在刷新或关闭页面后无法恢复：任务创建后可继续使用已保存的解析预览、文件名、指纹和章节选择；需要原附件时提示用户重新选择，并在目标 AI 中附上文件，不持久化浏览器文件句柄。任务创建前若页面刷新，提示重新导入原文，并避免声称浏览器可恢复未保存的文件对象。
- 工作空间权限失效：提供重新选择/授权入口，并保留待改原文、任务描述和其他已填写内容。
- 重新选择的文件夹与常用工作空间记录不匹配：不自动恢复文件勾选；显示不匹配原因，允许重新选择正确目录或按临时目录开始。
- Agent 判断失败或模型不可用：允许手动确认文体和任务类型后继续。
- 任务信息仍有歧义：指出具体不确定项，允许用户修改；不得悄悄补造事实。
- 修改前序步骤：标记受影响的后续判断或提示词需要更新，保留用户可恢复的已有输入。

## 7. 验收标准

1. 新用户进入工作台可选择新写作或文章改写；新写作只要求描述目标，改写可粘贴或导入待改原文，再选择整本处理或指定章节并描述目标。长手册无需全文粘贴；整本提示词要求分章节处理并提醒附上原文件。两者之后共用参考材料确认、任务分析、方向确认、提示词生成和结果回填步骤。
2. “新建规划”清楚说明其适用场景是需要先梳理目标、研究和执行路线的复杂写作；不把一般新写作误导为必须先规划，也不把新写作排除在写作工作台之外。
3. 用户可以临时添加文件夹，也可以复用已保存工作空间。
4. 待改原文与参考材料在界面和数据用途上分开。原文可从文件导入；长文支持整本处理和先提取目录再选章节。原文不占参考材料名额，提示词明确整本处理需要在外部 AI 中附上原文件。
5. 待改原文支持 TXT、MD、DOCX、PDF 文件导入；DOCX/PDF 复用现有解析上限并在超限、OCR 或目录识别不完整时明确提示。整本和选章提示词都要求外部 AI 附上原件，选章范围使用已识别的标题/位置，不伪造定位。
6. 文件夹/工作空间与额外导入参考文件合并；对所有支持、可读且未安全排除的候选进行本机全文扫描，不只搜索最多 5 行/1200 字样本。全文不上传、不持久化；处理后只保留有界索引、命中片段及定位。扫描数量/资源边界、可读/排除/未扫描状态可见；达到 10,000 文件或其他上限时不把未扫描内容判为无关。
7. 主模型可对命中片段复核并发起有界追加搜索；材料候选不设 3/5 份文件硬限制，最终送入分析的片段按相关性和模型上下文预算控制。每个结论可追溯到实际命中的文件路径和位置，未发送或未扫描的材料不标为已分析。
8. 用户可单独配置 Jev 服务，并在每次任务选择是否启用辅助候选排序/文体与任务分类，默认关闭。未配置时开关禁用。Jev 不读取文件、不执行文件工具、不生成最终提示词；主模型负责最终综合、生成，用户确认结果。Jev 失败或不确定时可靠回退主模型，不阻断流程。
9. 提供代表性中文样本的 Jev 开/关对比评估，记录材料相关性、文体/任务分类、错误推荐、提示词依据忠实度与可执行性、耗时和成本；未经本项目评估不得声称其更快或提升提示词质量，也不默认启用。
10. Agent 能推荐文体和任务类型，用户能确认或手动修改。
11. 不同文体只显示当前任务需要的信息；不出现要求所有用户填写的大型通用表单。
12. 用户可以返回修改已完成步骤，后续结果会提示是否需要更新。
13. 用户可复制提示词、粘贴外部结果，并继续生成复核或修改提示词。
14. 模型不可用时，仍能手动选择文体并继续，不丢失已输入内容。
15. “软著内容”规则包可与参考材料同时使用，在普通文章、操作/技术文档等兼容文体下可由用户显式选择；规则包不受材料文件数限制，也不会因任务文字自动启用。

## 8. 范围边界

- 本次设计解决流程与信息呈现，不改变写作工作台的核心定位和既有提示词能力。
- 本设计不要求新增自动正文写作、自动发布或自动修改原始项目文件的能力。
- 工作空间是材料来源入口；本设计不要求把它改造成完整项目管理或文件管理系统。
- 长文档能力用于生成外部 AI 可执行的整本分章节或指定章节改写提示词；不新增工作台直接代写整本手册的能力。超长原文由用户在目标 AI 中作为附件提供。
- 目录提取以标题样式/明确目录项和页码为依据；不保证从扫描版、复杂排版或缺少标题结构的文件中完整识别章节，必须提供手动指定范围的降级路径。
- 原附件本体不跨浏览器会话持久化；任务创建后只保存继续任务所需的元数据、已解析的有限预览和章节选择。任务创建前刷新需重新导入原文。用户在外部 AI 中仍需自行附上原始文件。
- 候选过滤以本机文件名、路径、扩展名和已知生成目录/文件模式为依据；完整可读文件只在本机扫描，不将整个目录或全量全文上传模型。
- 浏览器不保留可跨会话恢复的文件夹授权；索引仅为当前扫描服务，持久化任务不得写入全文或未确认的全部摘录。
- 沿用现有支持格式、单文件 1 MB 和 10,000 文件边界；扫描需让出主线程并可取消。触及边界或中断时在界面标出未扫描范围。
- 本次不接入自动向量化/外部 embedding 服务，也不把 Jev 当作文件搜索、内容生成或权限执行器；若词项检索效果不足，先依设计中的追加搜索与用户确认降级，不扩展到新的检索服务。

## 9. 自审

- 首屏是否明确：明确，改写先给原文再说明目标；新写作直接说目标，并可添加参考材料。
- 用户是否保有控制权：明确，材料清单和 Agent 的文体/任务建议都需用户确认或可编辑。
- 是否适用于多种文章：明确，通过通用步骤加文体专属信息，不把所有文章套进同一组字段。
- 是否控制材料范围：明确，用户选择授权文件夹后工作台仅在本机逐个全文扫描；主模型只收到有界相关片段，Jev 开关默认关闭，不上传全目录全文。
- 是否形成闭环：明确，提示词复制后可带回外部结果继续复核和改写。
- 不同来源是否能叠加：明确，文件夹/工作空间和额外单文件、多文件合并；参考材料与专业规则包可同时使用。
- 原文与参考材料是否易混淆：明确，待改原文单独导入；项目材料来自授权文件夹的全文检索，候选不设固定文件数上限，发送量受上下文预算控制。
- 代码目录候选是否易读：明确，默认过滤或折叠噪声文件，使用紧凑列表、按需展开摘录和过滤项入口。
- 长手册是否必须粘贴全文：否，允许文件导入；整本模式通过外部附件和分章节提示词处理，选章模式先提取目录。
- 原文解析边界是否明确：明确，列出支持格式、现有体积/页数/提取长度限制及扫描版 OCR 的核对提示。
- 目录候选是否会因规模再次难看：不会逐项渲染；分页 20 项、显示扫描进度和总量；全文逐文件扫描、及时释放正文，过滤项可恢复，扫描上限和截断均有提示。
- 页面是否仍会像截图一样堆满重复卡片和错误文字：不会，原文与辅助材料纵向分区；候选用紧凑行、每页 20 项，状态与过滤文件按组汇总。
- 提示词是否可能因选章而失去原文：明确提示整本/选章都要附原件，并输出选定章节标题和可用位置。
- 是否可能过度复杂：后续实现应按需显示专属字段，避免把所有步骤内容同时铺在一个页面。
- Jev 是否被当成万能模型：否，只承担独立配置后可选的有界排序/分类；读取、证据综合和最终提示词分别由本机检索、主模型及用户确认完成，中文表现通过项目样本评估，任务页说明哪些内容会发给 Jev。
- 全文扫描是否可能耗尽浏览器内存：设计要求逐文件扫描、释放正文并限制文件大小和数量，不缓存全量内容；扫描可取消并报告未扫描范围。
- 现有材料数量限制是否自相矛盾：已移除文件数 3/5 硬限制；UI 确认流程仍保留，实际输入按上下文预算约束。
