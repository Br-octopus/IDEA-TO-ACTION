# 写作工作台分步引导设计

日期：2026-10-23

状态：核心功能与定向回归已完成；2026-10-24 已完成大目录性能评估，中文辅助模型质量对照仍待真实配置和标注样本，辅助判断继续默认关闭。

- 定向回归已通过：提示词测试 46/46、工作台协调器测试 70/70、工作台 UI 测试 74/74。
- 全量验证已通过：`pnpm check` 通过；`pnpm test` 共 1,094 项，1,093 项通过、0 项失败、1 项因当前 Windows 环境无法创建文件符号链接而跳过。该跳过项不涉及写作工作台逻辑。
- 大目录性能已评估：10,000 文件索引约 17ms；优化前全文扫描约 154,532ms，优化后约 4,660ms；完整扫描 10,000/10,000，命中 2,439 个文件。当前实现每处理 32 个文件让出一次浏览器主线程，并保留可取消和进度状态。按当前原型范围，该结果可接受，不新增总字节硬限制或持久全文索引。
- 中文效果对照尚未完成：当前没有可复现的真实 System One/Decisions、OpenAI 兼容 Jev 中转或通用辅助模型配置，也没有带正确材料、文体/任务标签和盲评标准的中文样本集。不得用合成调用或单元测试代替质量、耗时和成本结论；第 7 节第 15 项保持待验收，辅助判断默认关闭。
- 材料数量规则已统一：用户材料和模型候选不再按 3/5 份硬截断，实际发送仍受完整消息 token 预算和请求体字节预算控制；超预算时保留可见状态，强约束无法容纳时明确要求精简。

## 1. 目标

把写作工作台从信息密集的单页表单改为按任务推进的引导流程。用户进入后能明确知道先做什么、Agent 会判断什么、何时需要用户确认，以及如何把外部 AI 的结果带回来继续修改。

本工作台服务所有文章类型，包括普通文章、手册、论文、小说、营销内容、邮件、演讲稿等。应用的主要交付仍是可编辑、可复制的提示词；不要求应用直接代写正文。

“新建规划”和“写作工作台”解决不同阶段的问题：“新建规划”用于目标尚未理清、需要先梳理研究和执行路线的复杂任务；“写作工作台”用于目标已有大致方向、准备形成并迭代写作提示词的任务。工作台内的新写作和文章改写走同一套完整流程，复杂度和后续步骤没有区别：两者都要确认材料、分析任务、确认文体与规则、生成提示词并带回结果。两者只在起始输入上不同：新写作从目标开始；改写先提供原文，再描述改写目标。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 文章类型 | 用户用自然语言描述任务；Agent 推荐文体和任务类型，用户确认或修改 |
| 任务模式 | 工作台首屏提供“新写作”和“文章改写”选择；两者共用全部后续流程，新写作不需要原文，改写必须先提供原文。二者没有轻重流程之分 |
| 与新建规划的关系 | “新建规划”用于需要先梳理目标、研究和执行路线的复杂写作；已有大致目标、准备形成写作提示词时进入工作台。新写作不因没有原文而被排除在工作台之外 |
| 页面边界 | 写作工作台、通用提示词 Agent、学术论文工作台是独立页面和导航入口；写作与提示词 Agent 不互相作为内部场景，学术文献/综述/投稿模块不挂在写作页或通用 Agent 页下 |
| 首屏输入 | 新写作直接描述写作目标；改写先提供待改原文，再描述改写目标。两类任务都可添加文件、文件夹或工作空间 |
| 工作空间 | 可临时添加本次文件夹，也可选择已保存的常用工作空间 |
| 文件范围 | 文件夹/工作空间与额外导入文件合并；工作台在本机逐个扫描全部可读候选的全文，按任务检索带路径和位置的相关片段，再交主模型判断；不把整个目录或所有全文上传 |
| 全文检索边界 | 全文只在本机逐文件扫描，不把全文持久化或长期保留在内存；每轮搜索仅保留有界命中片段和定位，不建立全目录全文索引。每次扫描显示范围、进度、可读/排除/未扫描数量；模型可在有界轮次内请求追加检索 |
| 材料选择范围 | 模型可从任意数量的候选文件中检索和推荐；不设 3/5 份文件数上限，实际送入模型的片段按相关性及当前模型上下文预算控制。用户仍可查看依据并确认/移除材料 |
| 材料状态与推荐 | 本机扫描、检索命中、模型推荐、用户手动选择、实际发送、模型已复核是不同状态，界面不得混称“已分析”。本机相关度只用于排序；主模型须根据命中片段和定位复核推荐。推荐必须映射到本轮实际发送且含有效摘录的候选 ID，界面展示的证据不得超过实际发给主模型的预算裁剪摘录；无效、未发送或无证据的 ID 不得成为推荐。用户手动选择优先保留。任务有可用检索词但无命中时不自动纳入无关文件；任务信息不足或没有检索词时也不自动全选候选，提示用户补充目标、手动选择或继续无材料。 |
| 上下文预算 | 依主模型配置的输入 token 预算控制检索摘录；未配置可用上下文时采用应用的保守默认预算。另遵守服务端请求体上限；超限时按相关度与文件覆盖度缩减片段并提示未纳入项，不宣称已分析 |
| 主模型配置 | 沿用项目现有 OpenAI 兼容聊天接口，可分别配置中转站 Base URL、模型名和 API Key；密钥沿用服务端安全配置，不写入任务记录或日志。官方 OpenAI 和兼容中转站均可作为主模型服务，具体模型能力及上下文上限以配置和服务商实际响应为准 |
| Jev/辅助判断配置 | 辅助判断器单独配置服务商、协议/API 模式、Base URL、模型 ID 和凭证，与主模型设置隔离。支持 TypeSafe System One 官方接口、明确支持 Jev/Decisions 请求契约的中转站，以及 OpenAI 兼容聊天接口中转站（如图示的 Base URL + API Key + model 配置）；用户选择“OpenAI 兼容中转站中的 Jev 模型”并填写服务商给出的模型 ID/别名，即可尝试按 OpenAI Chat Completions 调用。普通 GPT 等模型也可用作通用辅助判断模型。连接测试只能验证服务端点与响应格式，不能鉴定模型身份；界面显示用户配置的模型类型和 ID，不将自由生成的分数当作 Jev 校准概率。凭证沿用服务端安全配置机制；未配置可用服务时相应选项禁用 |
| Jev/辅助判断 | 每次任务可选启用，默认关闭；只对有界输入做结构化分类/评分，不读取文件、不生成解释或最终提示词。System One/Decisions 服务采用 Choice/Score/Noul 类型化问题；OpenAI 兼容接口（包括经中转站调用的 Jev 模型）采用严格 JSON 输出并由应用校验。主模型仍负责证据复核与自然语言输出。辅助评分只作可见排序信号，不单独排除材料；失败或不确定时回退主模型 |
| 辅助判断成本边界 | 本机仍扫描全部授权候选，文件数量不设上限；Jev/辅助模型候选数不设固定上限，实际评估数量由完整协议请求累计 4,000 tokens 预算决定，同时最多 3 个并发请求。预算外或请求失败的候选保留在材料列表并明确标为“未由辅助模型评估”，主模型仍按自身预算复核 |
| 中文评估 | 不预设 Jev 中文质量或整体提速效果。用代表性中文样本分别评估 System One/Decisions、OpenAI 兼容 Jev 中转和通用辅助模型，避免把协议与模型差异混在一起；评估材料命中、分类、提示词质量、未评估候选比例、端到端耗时与请求成本，再决定是否推荐默认启用 |
| 待改原文 | 与参考材料分区。长手册可单独从 TXT、MD、DOCX 或 PDF 文件导入；支持整本处理提示词，或提取目录后选择章节。原文不计入参考材料数量上限 |
| 原文解析边界 | 复用现有本机解析器：DOCX/PDF 文件最大 20 MB，PDF 最多 100 页，提取文本最多 30,000 字符；超限时保留文件名和用户输入，提示改用更小文件或按章节拆分。整本处理仍可提示外部 AI 使用原附件 |
| 目录候选呈现 | 默认展示可读取、可索引的候选材料及全文检索命中；构建产物、临时文件和不支持的文件默认过滤或折叠。用紧凑列表分页呈现，不逐项铺开格式错误信息 |
| 参考材料上限 | 不按文件份数限制候选搜索或最终推荐；按检索片段总量和实际模型上下文预算控制。待改原文仍与参考材料分开，不参与项目资料检索预算 |
| 模型输入预算 | 主模型每次请求按完整序列化消息估算输入 token，覆盖系统指令、任务信息、历史/重复上下文、路径与定位、命中摘录及辅助评估摘要；应用默认输入预算为 8,000 tokens，并为模型输出预留空间。辅助模型 4,000 tokens 是独立预算，不与主模型预算互相抵扣。token 估算与服务端请求体字节限制分别校验；响应含 usage 时仅用于校准，不替代发送前限制。超限按相关性与跨文件覆盖度裁剪；必要信息无法保留时应明确失败并让用户精简，不得静默截断强约束。 |
| 规则包 | 参考材料与“软著内容”等专业规则包可以同时选择；规则包不占用材料数量上限，并按自身适用范围生效 |
| 需求信息 | Agent 先识别任务所需信息和缺口，只显示本任务需要的内容；用户可以修改判断和建议值 |
| 文体专业性 | 按确认后的文体加载对应规则和字段，不让所有文体共用一张大表单 |
| 阶段导航 | 默认沿引导流程前进；已经完成的阶段可返回修改 |
| 结果闭环 | 用户把外部 AI 的结果贴回工作台，再生成检查或下一轮修改提示词 |

## 3. 主流程

```text
选择任务：新写作 / 文章改写
        ↓
新写作：描述写作目标；文章改写：导入/粘贴待改原文 → 选择整本处理或指定章节 → 描述改写目标
        ↓
两种模式共用：添加文件夹/工作空间及额外参考文件 → 本机全文检索 → 查看并确认相关材料
        ↓
（用户可选 Jev/辅助判断器）评估本机检索候选，候选数量不限，完整协议请求累计不超过 4,000 tokens，最多 3 个并发请求；预算外候选标为未评估
        ↓
主模型复核证据、必要时请求追加检索 → 用户确认材料与判断并生成提示词
        ↓
选择可叠加的参考材料与专业规则包，确认本任务必需的信息与约束
        ↓
生成、检查并复制提示词
        ↓
粘贴外部 AI 结果 → 生成复核或下一轮提示词
```

用户可从已完成的步骤返回修改。修改目标、文体或材料后，界面提示哪些后续结果可能需要重新生成；不静默保留与新输入不一致的提示词或分析。重新分析开始时清除上一次的模型建议、证据和推荐勾选，避免失败时展示旧任务推荐；用户手动选择的参考材料和原文输入保留。推荐证据始终对应本轮实际发送给主模型的片段，预算裁剪后的内容必须按实际发送版本展示。

## 4. 页面步骤与交互

四步使用同一任务页面和固定进度条，页面主体每次只呈现当前步骤。进度条显示“描述任务、确认方向、生成提示词、带回结果”；已完成步骤可点击返回，当前步骤有明确的标题、说明和一个主按钮。每步的次要动作保持轻量，不再同时铺开后续所有表单。

### 第一步：提供原文、描述目标并添加材料

**页面目标：** 首屏提供“新写作”和“文章改写”选择。新写作用户直接说明想写什么；改写用户先提供要处理的原文，再说明希望怎样改。模式差异只决定原文是否必填，之后共用材料、任务分析、方向确认、提示词和结果回填步骤。需要先梳理目标、研究和执行路线的复杂写作仍从“新建规划”进入；该入口不替代工作台的新写作模式。用户不需要预先理解文体分类或填写通用问卷。

**页面内容：**

1. 新写作模式直接显示写作目标；文章改写模式显示独立的“待改原文”区域，可粘贴短文或从文件导入长文档，随后填写“希望怎么改”。长文档导入显示文件名、解析状态和可用目录，不要求用户把全文粘进文本框。检查模式可引用已有文本，并由 Agent 判断任务类型。主模型使用项目现有 OpenAI 兼容配置，支持填写官方服务或兼容中转站提供的 Base URL、模型名和 API Key。辅助判断另设服务商配置，可选择 System One/Decisions 兼容服务或 OpenAI 兼容聊天中转站；用户可明确选择“复用主模型 Base URL 和 API Key”，并单独填写辅助模型 ID，也可配置另一组连接信息。主、辅助配置不自动同步。若中转站提供 Jev 模型，填写其模型 ID/别名即可通过 OpenAI Chat Completions 模式调用。设置与任务页显示服务商、模型 ID、协议模式及连接状态；连接测试只验证服务可访问且输出符合格式，不宣称能证明第三方实际运行的模型身份。
2. 待改原文提供两种处理范围：**整本处理**生成要求外部 AI 按章节分批工作的提示词；**选择章节**从可识别的标题/目录提取章节供用户勾选，再生成限定章节范围的提示词。DOCX/PDF 复用本机解析能力，单文件最大 20 MB，PDF 最多 100 页，提取最多 30,000 字符；超出边界时明确提示，不宣称已读取全文。解析文本和目录用于本地预览与任务判断，不把整本原文塞进分析请求或复制出的提示词。整本与选章模式都要求用户在外部 AI 中附上原文件；提示词带上所选章节标题和可用的页码/位置。目录未识别或解析不完整时，保留文件和改写目标，允许手动填写章节标题/范围，或切换整本处理。
3. “参考材料”独立成区，提供选文件、临时添加文件夹、选择已保存工作空间三个入口。工作空间入口也允许保存新选的文件夹供以后使用。常用工作空间显示已保存的名称；浏览器需重新选择文件夹时，核对根目录名和已保存的相对路径/文件版本，确认后才恢复勾选，避免误用同名目录。操作手册若同时位于代码目录，可从待改原文区单独导入，不依赖它在代码候选列表中的排序或格式支持。
4. 文件夹或工作空间索引与额外参考文件累加显示，不互相替换。重复文件按来源标识/相对路径去重。用户提交任务后，工作台对所有支持且未触发安全排除的候选逐个进行本机全文扫描，按任务描述、文件名/路径及模型请求的检索词查找片段；全文不上传、不持久化，也不把全目录全文同时保留在内存。扫描采用有界处理并及时释放单文件全文，不建立持久或全目录索引，只保留预算内命中片段及文件定位。常见构建目录、压缩产物（如 `.min.js`）、临时文件和不支持格式默认过滤或折叠；提供搜索和“显示已过滤文件”入口，用户可恢复误过滤文件。沿用现有最多 10,000 个文件的扫描上限；触及单文件大小或文件数边界、取消或读取失败时显示已扫描范围和未扫描提示，不静默遗漏。
5. 页面以纵向分区卡片呈现“待改原文”和“辅助参考材料”，避免把超长原文框与文件目录混成一块。候选以紧凑行展示文件名、相对路径、扫描/推荐状态和依据；摘录按需展开，移除操作放在行内，不为每个文件重复铺开错误段落和大按钮。列表按每页 20 项分页。初始展示扫描进度、已扫描/可读/排除/未扫描数量和命中的材料；搜索覆盖全部已扫描全文，而非仅当前页或已选文件。候选数量不限制模型检索范围；发送给模型的相关片段按相关性和上下文预算裁剪，并保留来源定位。用户可确认或移除建议材料；不再显示“最多 3/5 份”限制。扫描中、没有可读文件、无命中、存在过滤项等状态以汇总说明和对应操作呈现；过滤项默认折叠。
6. 底部主按钮为“确认材料并分析任务”。没有参考文件时仍可继续；系统只提醒本次分析不会参考项目文件。仅粘贴原文也可继续改写。

**交互顺序：** 新写作先录入目标；改写先导入/粘贴原文，选择整本或章节范围，再描述目标。两种模式随后共用全文检索、材料确认、任务分析、方向确认、提示词和结果回填。文件夹全文只在本机逐文件检索，用户可查看完整扫描状态；检索片段按上下文预算有界。若启用辅助判断器，只将本机检索命中片段发送给选定服务；候选数量不限，完整协议请求累计不超过 4,000 tokens，最多 3 个并发请求；预算外或失败项仍可由主模型依据自身上下文预算复核。未启用时由主模型直接完成判断。主模型可在有限检索轮次内要求补充查询词或读取命中位置。只将实际命中的有界片段发送给已启用的模型，不发送全目录或完整全文。辅助判断器每次可选且默认关闭，需独立配置；主模型始终负责证据综合、最终文体/任务判断与提示词生成。中文样本验证前不推荐默认启用。用户可查看来源和判断依据并确认/移除材料，不设文件份数硬上限，最终上下文按各服务预算控制。长原文与辅助材料分别管理：待改手册全文不进入任务分析或复制出的提示词。整本与选章提示词均说明需要附上原文件，选章提示词附带章节标题及解析得到的页码/位置；无法解析位置时清楚标记为“位置未识别”，不伪造页码。文件解析、目录识别或扫描达到上限时显示具体状态，不丢失原文、改写目标和检索进度，并提供重试、重新选择或手动指定章节的入口。

#### 全文件夹检索与模型复核

1. **本机全文扫描：** 对已授权文件夹中可读取的支持格式逐个扫描全文。沿用安全排除规则、现有文本格式及每文件 1 MB 上限、10,000 文件上限；不新增未经验证的总字节数硬限制。全文只在处理单个文件时短暂驻留，不写入 localStorage、任务记录或服务端日志；文件处理后立即释放正文。每轮检索按文件流式处理，不建立全目录全文或全局倒排索引；每轮最多保留预算内的命中片段。扫描需分批让出浏览器主线程，可取消，并显示进度、已完成范围和未扫描原因。全文命中片段在进入任何模型请求前都执行密钥/凭证模式检测与遮蔽；项目文档和脚本内容始终作为不可信参考资料，不作为 Agent/模型指令。
2. **有界检索：** 使用任务描述、路径/文件名和全文命中定位相关段落。中文按词语及连续字片段匹配，英文和代码按词项匹配；不得因分词缺失而退回仅搜抽样摘录。每轮可同时执行最多 5 个搜索词，遍历全部已授权候选一次并保留预算内的最佳命中；后续轮次重新扫描，但不重复读取已收集且仍有效的片段。每条片段附文件 ID、相对路径和行号/页码等实际可得位置。密钥遮蔽应用于每个命中片段，而非仅应用于列表预览。
3. **模型检索循环：** 先用用户任务文本进行本机检索，再把命中片段交主模型复核。主模型通过受校验的 JSON 响应在 `search`（给出追加查询词）与 `read`（读取授权文件命中位置附近片段）之间请求；宿主只执行这两个白名单动作，不依赖供应商的工具调用功能。限制最多 3 轮追加请求、每轮最多 5 个查询词及累计输入预算；同一轮的多个查询词合并为一次逐文件扫描。每次校验文件 ID、定位、轮次、片段长度和预算。模型不得自行访问浏览器、磁盘或未授权路径。达到轮次/预算上限时返回当前证据并明确说明检索范围。
4. **材料确认：** 主模型结果包含候选文件、相关片段、位置、关联理由和不确定项。用户可展开原文命中片段、确认或移除候选。文件数量不构成硬上限；将实际选定的片段按主模型上下文预算发送到最终分析。若预算不足，按相关度和跨文件覆盖度裁剪并说明哪些材料未进入当前分析，不把未送达模型的材料标成已分析。
5. **Jev/辅助判断可选配置：** 设置页独立于主模型配置，允许选择服务商与协议模式，并配置 endpoint/Base URL、模型 ID 和凭证。内置 System One 直连模式默认地址为 `https://jevmodel.net/v1/systemone`、模型为 `jev-latest`；支持遵循 Jev/Decisions 请求契约的中转站模式。也支持 OpenAI 兼容聊天中转站配置（Base URL、API Key、模型 ID/别名）；用户可显式复用主模型的 Base URL 和 API Key，但辅助模型 ID 单独填写，或填写另一组连接信息。用户可选择“OpenAI 兼容中转站中的 Jev 模型”并填写服务商给出的模型 ID。应用只验证请求可达和 JSON 结构，不声称能验证第三方实际模型身份；界面展示用户选择的辅助类型、服务商、模型 ID 和协议模式。普通 GPT 等模型标为通用辅助判断器。聊天接口要求结构化 JSON 输出并由宿主校验；通用模型的置信度不视为已校准概率。连接测试只发送最小测试请求，不带入任务或文件片段；结果分别显示“连接成功/失败”“结构化响应有效/无效”和已配置的模型 ID。不得仅凭 Base URL 可填写就假设服务兼容。每次任务的“使用辅助模型判断”默认关闭，开关旁披露任务摘要、命中片段、服务商和模型 ID。辅助服务不读取文件、不执行搜索、不生成最终提示词；具体证据由界面显示命中片段，解释和最终判断由主模型给出。辅助模型不设候选数量上限，任务总输入预算默认 4,000 tokens，最多 3 个并发请求；实际评估数量由完整协议请求预算决定，其余候选标记为“未评估”，不会从材料列表或主模型复核中移除。候选相关性排序只基于本机检索到的片段，不将辅助分数设为材料准入门槛，也不静默丢弃检索结果。服务不可用、超时、输出不合法或判断冲突时记录服务状态并回退主模型，不阻断任务，也不自动切换到另一第三方服务。System One/Decisions 服务的概率/置信度只按其服务协议解释；普通聊天模型输出不经校准，不用于自动排除材料或触发高影响动作。
6. **中文效果验证：** 使用代表性且有对比度的中文任务/文件夹样本，按相同任务比较辅助判断关闭与开启，分开记录 System One/Decisions Jev、OpenAI 兼容 Jev 中转和通用辅助模型结果，避免把协议差异误当成模型质量差异。记录材料相关性命中、任务/文体分类、提示词依据忠实度与可执行性（盲评）、预算外候选比例、端到端耗时、成本及服务失败；样本须标注正确材料、类别和提示词评价标准。Jev 对多个候选的评估按 API 契约逐个候选构造 state，不把互不相关候选拼成一个 state；候选数量不限，完整协议请求累计预算为 4,000 tokens，并发最多 3 个。先以影子/对照评估验证再作为正式选项；未经本项目评估不宣称更快、更有效或提升提示词质量。

参考 Jev 的官方 [API/Agent Skill 说明](https://github.com/jevmodel/jev-model-ai)、[OpenRouter Decisions API 接入指南](https://openrouter.ai/docs/guides/community/jev-tutorial) 与社区 [技能](https://github.com/marcodicesare-dev/jev-skill/blob/main/SKILL.md)、[API 契约](https://github.com/marcodicesare-dev/jev-skill/blob/main/reference/api.md)、[档案检索工作流](https://github.com/marcodicesare-dev/jev-skill/blob/main/reference/field-guide-playbook.md)、[设计陷阱](https://github.com/marcodicesare-dev/jev-skill/blob/main/reference/pitfalls.md)。只借鉴“宿主保留执行和权限、Jev 输出有界结构化决策”的分工；档案检索示例要求按候选证据核验，并明确性能数据是特定任务结果，不可直接外推。本项目需自行验证中文、材料排序和提示词质量。

### 第二步：确认方向

**页面目标：** 让用户看懂 Agent 对任务的理解，并有机会纠正。

**页面内容：**

1. 顶部用一句话复述任务，例如“根据项目实际功能，检查并改进操作手册”。
2. 用可编辑的选择控件显示“推荐文体”和“任务类型”，例如“操作/技术文档”和“依据项目资料优化现有文章”。旁边简述推荐依据，支持展开查看。
3. 下方只显示当前任务需要的补充项。Agent 可从文章或材料中预填；每项标记为“来自材料”“Agent 建议”或“需要你确认”。
4. 把真正阻止后续提示词准确生成的问题放在“还需要确认”区域；其他字段折叠在“更多设置”中或采用明确标注的默认值。
5. 展示本次将使用的材料摘要，可返回第一步调整材料。
6. 提供与参考材料并列、可独立选择的专业规则包区域。“软著内容”规则包可在普通文章或操作/技术文档等适配文体下由用户主动选择；它不替代或排斥参考文件，也不受材料文件数量限制。默认不因用户提到软著而静默启用；显示包名和简短适用说明，用户可随时取消。
7. 主按钮为“确认，生成提示词”；次按钮为“返回修改目标”。

**确认规则：** 文体和任务类型始终由用户确认后才进入下一步。用户可接受 Agent 建议，也可手动更改。参考材料与规则包是两种独立输入，可同时启用；规则包按明确的兼容文体/任务元数据决定可选范围。若模型不可用或无法判断，直接显示可搜索的文体选择和简短说明，其他已填内容保留。

### 第三步：生成提示词

**页面目标：** 交付可直接使用、可自行修改的提示词，并让用户知道它依据什么生成。

**页面内容：**

1. 主体是可编辑的提示词文本区，默认完整展开，支持复制。
2. 提示词上方显示确认后的文体、任务类型；旁边提供“修改任务设置”返回第二步。
3. 提示词下方用紧凑摘要分别列出采用的参考材料和规则包。二者可同时出现在提示词依据中；材料可展开查看，规则包显示名称和适用范围，避免默认占据主要阅读区域。
4. 主按钮为“复制提示词”，另提供“我已在其他 AI 中使用”进入结果回填；若产品已有模型直连能力，沿用已有调用方式和发送预览，不在本设计中新增调用行为。
5. 用户编辑提示词后，保留其版本；若返回修改目标或材料，提示当前提示词基于旧信息，可选择更新生成或保留为手动版本。

### 第四步：带回结果

**页面目标：** 让外部 AI 结果回到同一任务，形成可继续的改稿闭环。

**页面内容：**

1. 页面顶部简要回顾任务目标和已使用提示词，支持展开查看。
2. 一个明显的粘贴区用于带回外部 AI 输出；可选附加“这次结果哪里不满意”的反馈。
3. 主按钮为“检查这份结果”。执行后在同一页显示检查结果，问题按影响排序并尽量定位到原文片段；区分事实/材料缺口、结构问题和表达问题，不把建议伪装成已核实事实。检查使用已确认的任务和材料；结果内容仅在用户触发检查后发送给配置的模型。
4. 用户可勾选本轮要处理的问题或补充反馈；主按钮随后显示“生成下一轮修改提示词”。此操作把本轮结果和反馈作为新一轮输入，提示词进入第三步预览，并保留本轮检查结果。
5. 提供“本轮完成”结束操作；结束后可从任务历史继续，不强迫用户进入下一轮。

### 阶段回退与状态变化

- 点击进度条中的已完成阶段可返回；未完成阶段不可跳过必要确认直接标成完成。
- 修改目标会使任务判断、提示词和结果检查标记为“可能过期”；修改材料会使引用这些材料的分析与提示词标记为“需要更新”。
- 对过期内容提供明确的“重新分析/重新生成”和“保留当前版本”操作，不自动覆盖用户手动修改过的提示词。
- 每一步保留未完成输入；切换步骤或遇到临时错误不清空文本。

## 5. 通用与文体专属信息

通用步骤只收集目标、文章/材料和必要约束。确认文体后，再显示对应的专属信息，例如：

- 操作手册：软件版本、目标读者、实际功能依据。
- 学术论文：研究类型、学科、目标期刊或学校要求。
- 小说：视角、人物设定、连续性约束。
- 社媒内容：平台、受众、篇幅或格式限制。

Agent 可以根据已有材料预填或建议这些信息；每项建议都能编辑。缺少非必要信息不阻断流程。

## 6. 状态与错误处理

- 文件无法读取：显示具体文件和原因，允许移除、重选或继续使用其他材料。
- 全文扫描达到文件数/单文件大小上限、用户取消或浏览器读取失败：显示本次已扫描、未扫描和不可读数量/范围；允许缩小范围或继续使用当前命中。未扫描部分不得显示为“不相关”或“已读”。
- 全文搜索无命中或命中不足：允许主模型提出追加检索词并在有界轮次内重搜；仍无证据时明确标记证据不足，用户可手动搜索、选文件或继续不带项目材料。
- 主模型追加检索响应不是合法 JSON、请求包含未知动作/文件 ID/定位或超过查询轮次：不执行请求，保留当前证据并提示可手动搜索或继续。
- 检索命中疑似密钥/凭证：发往主模型或 Jev 前按行遮蔽；界面预览也显示遮蔽结果。无法可靠遮蔽时不发送该片段并说明。
- 主模型上下文或服务端请求体超限：按相关度与跨文件覆盖度缩减片段，最多重试一次；显示未纳入分析的文件/片段，不静默当作已分析。
- 浏览器刷新、关闭或取消扫描：不恢复未保存的全文或索引；保留已保存的任务文字和已确认材料元数据，并提示重新选择文件夹后重新扫描。
- Jev/辅助判断服务不可用、超时、返回结构错误或预算耗尽：保留主模型路径并继续；界面说明本次未采用或仅部分采用辅助判断，不伪称已完成完整双模型校验。
- Jev 未配置或配置无效：设置页提供独立配置/连接检查入口；任务页禁用 Jev 开关并说明需先配置，主模型写作流程仍可使用。
- OpenAI 兼容辅助判断服务未配置、连接失败或不支持结构化输出：指出 Base URL、模型 ID 或响应格式问题；不发送任务材料，不自动改用主模型以外的其他服务，仍可继续不启用辅助判断。
- 辅助判断累计请求达到 4,000 tokens 预算或请求失败：显示实际评估数量与未评估数量；未评估候选仍可由主模型判断，不能标成“不相关”。候选不按固定数量截断，实际数量由完整协议请求预算决定。
- Jev 与主模型结论冲突：展示双方各自对应的证据片段和不确定点，由主模型依据原文证据复核，最终由用户确认；不得自动隐藏冲突或将 Jev 结论作为事实。
- 原文格式不支持或解析超限：说明当前支持 TXT、MD、DOCX、PDF；DOCX/PDF 最大 20 MB、PDF 最多 100 页、可提取文本最多 30,000 字符。保留其他输入，允许重选文件或手动输入章节范围；扫描版 PDF OCR 结果须标明需人工核对。
- 目录提取不完整：明确标识已识别的章节和未识别状态；用户可手动补充标题/范围或切换整本处理，不把不完整目录显示成完整目录。
- 目录文件数达到 10,000 上限：显示扫描未完成提示和范围；允许缩小文件夹或改用搜索/手动导入，不把未扫描部分当作无关文件。
- 本地文件对象在刷新或关闭页面后无法恢复：任务创建后可继续使用已保存的解析预览、文件名、指纹和章节选择；需要原附件时提示用户重新选择，并在目标 AI 中附上文件，不持久化浏览器文件句柄。任务创建前若页面刷新，提示重新导入原文，并避免声称浏览器可恢复未保存的文件对象。
- 工作空间权限失效：提供重新选择/授权入口，并保留待改原文、任务描述和其他已填写内容。
- 重新选择的文件夹与常用工作空间记录不匹配：不自动恢复文件勾选；显示不匹配原因，允许重新选择正确目录或按临时目录开始。
- Agent 判断失败或模型不可用：允许手动确认文体和任务类型后继续。
- 任务信息仍有歧义：指出具体不确定项，允许用户修改；不得悄悄补造事实。
- 修改前序步骤：标记受影响的后续判断或提示词需要更新，保留用户可恢复的已有输入。

## 7. 验收标准

1. 新用户进入工作台可选择新写作或文章改写；新写作只要求描述目标，改写可粘贴或导入待改原文，再选择整本处理或指定章节并描述目标。长手册无需全文粘贴；整本提示词要求分章节处理并提醒附上原文件。两者之后共用参考材料确认、任务分析、方向确认、提示词生成和结果回填步骤。
2. “新建规划”清楚说明其适用场景是需要先梳理目标、研究和执行路线的复杂写作；不把一般新写作误导为必须先规划，也不把新写作排除在写作工作台之外。
3. 用户可以临时添加文件夹，也可以复用已保存工作空间。
4. 待改原文与参考材料在界面和数据用途上分开。原文可从文件导入；长文支持整本处理和先提取目录再选章节。原文不占参考材料名额，提示词明确整本处理需要在外部 AI 中附上原文件。
5. 待改原文支持 TXT、MD、DOCX、PDF 文件导入；DOCX/PDF 复用现有解析上限并在超限、OCR 或目录识别不完整时明确提示。整本和选章提示词都要求外部 AI 附上原件，选章范围使用已识别的标题/位置，不伪造定位。
6. 文件夹/工作空间与额外导入参考文件合并；对所有支持、可读且未安全排除的候选进行本机全文扫描，不只搜索最多 5 行/1200 字样本。全文不上传、不持久化；逐文件扫描后释放正文，不建立全目录索引，只保留预算内命中片段及定位。扫描数量/资源边界、可读/排除/未扫描状态可见；达到 10,000 文件或其他上限时不把未扫描内容判为无关。
7. 主模型可对命中片段复核并发起有界追加搜索；材料候选不设 3/5 份文件硬限制，最终送入分析的片段按相关性和模型上下文预算控制。每个推荐可追溯到本轮实际发送的摘录、文件路径和位置；推荐 ID 必须来自实际发送且有证据的候选，未发送或未扫描的材料不标为已分析。重新分析失败不残留上轮模型推荐，但保留用户手动选择。
8. 主模型检索循环通过 JSON 白名单请求追加 `search`/`read`；文件 ID、定位、查询轮次、每轮查询数和累计预算均经验证。非法或超限请求不执行，保留手动搜索/继续路径。
9. 有上下文预算设置或保守默认值；发送请求符合输入 token 与服务端字节限制。超限缩减、重试和未纳入片段提示可验证，不把未发送材料标为已分析。
10. 每条发往主模型或 Jev 的命中片段都先经过密钥/凭证遮蔽；资料正文明确作为不可信内容，不能覆盖系统指令。密钥无法可靠遮蔽时不发出。
11. 用户可单独配置辅助判断服务，并在每次任务选择是否启用，默认关闭。支持 System One/Decisions 接口，以及 OpenAI 兼容接口调用中转站提供的 Jev 模型或其他通用辅助模型；按配置协议调用并校验响应，界面按模型 ID/服务商区分模型身份，不将不同模型的分数/概率混为一谈。未配置时对应选项禁用。辅助服务只返回有限结构化结果；主模型负责最终综合与提示词，用户确认结果。辅助服务失败或不确定时回退主模型，不阻断流程。
12. OpenAI 兼容辅助判断配置可显式复用主模型 Base URL/API Key 或单独配置；辅助模型 ID 独立设置。连接检查不发送任务材料，只验证可达性和响应结构，并明确不验证第三方模型的真实身份。
13. Jev/辅助模型候选数不设固定上限，输入预算默认为 4,000 tokens，并发请求最多 3 个；预算外部分明确标记未评估且不从主模型候选中移除。
14. Jev 候选评分不会自动丢弃本机检索结果；多个无关候选不拼成一个 state；阈值/概率未经本项目标注集校准前不自动排除资料。
15. 提供代表性中文样本的 Jev 开/关对比评估，记录材料相关性、文体/任务分类、错误推荐、提示词依据忠实度与可执行性、耗时和成本；未经本项目评估不得声称其更快或提升提示词质量，也不默认启用。
16. Agent 能推荐文体和任务类型，用户能确认或手动修改。
17. 不同文体只显示当前任务需要的信息；不出现要求所有用户填写的大型通用表单。
18. 用户可以返回修改已完成步骤，后续结果会提示是否需要更新。
19. 用户可复制提示词、粘贴外部结果，并继续生成复核或修改提示词。
20. 模型不可用时，仍能手动选择文体并继续，不丢失已输入内容。
21. 主模型可配置 OpenAI 兼容服务的 Base URL、模型名和 API Key，支持官方服务及兼容中转站；辅助判断另有服务配置，可使用 TypeSafe System One、支持 Jev/Decisions 契约的中转站，或 OpenAI 兼容中转站提供的 Jev/通用判断模型。两套配置互不隐式复用，可由用户分别填写相同连接信息。
22. “软著内容”规则包可与参考材料同时使用，在普通文章、操作/技术文档等兼容文体下可由用户显式选择；规则包不受材料文件数限制，也不会因任务文字自动启用。

## 8. 范围边界

- 本次设计解决流程与信息呈现，不改变写作工作台的核心定位和既有提示词能力。
- 本设计不要求新增自动正文写作、自动发布或自动修改原始项目文件的能力。
- 工作空间是材料来源入口；本设计不要求把它改造成完整项目管理或文件管理系统。
- 长文档能力用于生成外部 AI 可执行的整本分章节或指定章节改写提示词；不新增工作台直接代写整本手册的能力。超长原文由用户在目标 AI 中作为附件提供。
- 目录提取以标题样式/明确目录项和页码为依据；不保证从扫描版、复杂排版或缺少标题结构的文件中完整识别章节，必须提供手动指定范围的降级路径。
- 原附件本体不跨浏览器会话持久化；任务创建后只保存继续任务所需的元数据、已解析的有限预览和章节选择。任务创建前刷新需重新导入原文。用户在外部 AI 中仍需自行附上原始文件。
- 候选过滤以本机文件名、路径、扩展名和已知生成目录/文件模式为依据；完整可读文件只在本机扫描，不将整个目录或全量全文上传模型。
- 浏览器不保留可跨会话恢复的文件夹授权；检索不建立持久索引，持久化任务不得写入全文或未确认的全部摘录。
- 沿用现有支持格式、单文件 1 MB 和 10,000 文件边界；扫描需让出主线程并可取消。触及边界或中断时在界面标出未扫描范围。
- 主模型检索循环只在已授权目录执行固定的 `search`/`read` 白名单动作；最大 3 轮追加请求、每轮最多 5 个查询词，服务端不暴露任意文件路径读取能力。
- 主模型输入 token 预算由用户设置；缺省 8,000 tokens，另外校验服务端最大请求体。对超限请求只允许一次按相关性收缩后重试。
- 辅助判断服务支持独立的 TypeSafe System One 直连和遵循 Jev/Decisions 契约的中转站；OpenRouter 等服务的路由/API 路径按其实际 API 契约配置，不默认套用 `/chat/completions`。
- 允许把 OpenAI 兼容聊天中转站配置为辅助判断器，通过模型 ID/别名选择中转站提供的 Jev 模型或通用模型；必须以 JSON Schema/严格 JSON 约束和本地 schema 校验响应。只有模型确为 Jev 时才标注为 Jev；通用模型不宣称提供 Jev 类型化或校准概率能力。
- 辅助判断可显式复用主模型的 Base URL/API Key，但模型 ID 和使用开关独立；允许显式引用已有连接配置，不得静默沿用或自动同步。辅助连接测试不得包含用户任务或文件内容，也不得把第三方模型 ID 的自述当成身份认证。
- Jev/辅助模型单次任务候选数不设固定上限，总输入预算 4,000 tokens、并发请求最多 3 个；预算外候选保留供主模型评估，界面显示未评估状态和数量。
- 自定义模型地址复用现有校验规则：外部地址使用 HTTPS，本机回环地址允许 HTTP；拒绝 URL 内嵌凭证、查询参数和片段。API Key 只通过授权请求头发送，不放入 URL、错误信息或日志；跨源重定向不得转发凭证。
- 主模型沿用 OpenAI 兼容聊天接口，允许配置官方服务或兼容中转站的 Base URL、模型名和 API Key；中转站的模型能力、上下文上限及隐私处理由其实际服务决定，界面不得把未经验证的能力当作保证。主模型与辅助判断器分别管理 endpoint/模型 ID/使用开关；用户可明确复用同一连接配置，也可提供独立连接，只有显式启用时才向辅助服务发送任务信息。
- 模型和 Jev 请求正文、API 凭证不得写入日志/任务持久化；发送给 Jev 的数据必须由用户在本次任务显式启用，且界面披露内容范围。
- 本次不接入自动向量化/外部 embedding 服务，也不把 Jev 当作文件搜索、内容生成或权限执行器；若词项检索效果不足，先依设计中的追加搜索与用户确认降级，不扩展到新的检索服务。

## 10. 资源按需调用扩展

规则包只保存可快速判断的规则和资源元数据。原始 skill、脚本、模板和示例保留在受控资源根目录或带版本的压缩包中，按当前文体、任务类型和用途选择，不能把整套资源全文塞进每次模型请求。

资源分为四类：

1. **规则包**：保存规则、边界、检查项、方法、路线和来源，负责稳定约束。
2. **脚本**：只通过固定 `actionId` 请求，由应用校验参数、授权根目录、超时、文件数和输出大小后执行；模型不能传入任意命令或绝对路径。
3. **模板**：保存申请表字段、操作手册章节、代码材料排版等生成结构；提示词只读取与当前任务有关的有界片段。
4. **示例**：保存参考案例摘要、输入概况和预期结构；示例只能帮助理解表达和格式，不能作为事实来源，也不能覆盖用户要求。

每个资源必须记录 `id`、`kind`、`title`、`relativePath`、`purpose`、`applicability`、`taskTypes`、`sourceIds`、`verificationStatus` 和 `enabled`。脚本额外记录 `actionId`、参数 schema、允许根目录、超时和输出上限；模板记录格式和可加载章节；示例记录输入概况、预期结构和参考边界。资源描述和加载结果不得包含 API Key、token、密码或本机绝对路径。

工作台在任务分析、提示词生成和软著专项流程中建立资源选择结果：`resourceSnapshot`、`resourceUsage`、`skippedResources`、`unavailableResources`。提示词分别展示规则、模板片段、示例摘要和事实材料，并明确“模板是结构参考、示例仅供参考、用户材料才是事实来源”。UI 显示本轮使用、跳过和失败资源、来源版本及核验状态。

软著资源注册至少覆盖申请表字段模板与检查动作、传统操作手册章节模板与目录/一致性检查动作、代码扫描/候选选择/代码抽取/页数和真实性检查动作，以及两份用户提供 skill 中的相关示例和参考资料。压缩包只登记 archive 与相对路径；解压和读取必须在受控缓存目录进行，不能把压缩包内脚本当作任意命令执行。

## 11. 资源扩展验收

只有同时满足以下条件，才算完成原始 skill 资源按需调用：资源清单和来源可见；申请表、操作手册和代码材料任务分别实际选择适用模板/示例/脚本；提示词带入有界模板片段和示例摘要并标明参考边界；不适用资源被跳过并说明原因；脚本只能调用白名单 actionId 并拒绝越权路径、非法参数、超时和超输出；资源使用和失败状态可追溯；软著任务支持整本手册和按章节处理；相关测试通过。文档和计划必须分别标明哪些已实现、哪些仍是设计目标。

**2026-10-24 实现核对：**上述资源调用条件已由资源 schema、归档读取器、白名单执行器、提示词/协调器快照、桌面端确认按钮和专项测试覆盖。两份用户提供压缩包以归档标识和相对路径注册，正文按需读取；中文 Jev 质量对照仍属于独立评估目标，不能由自动化回归代替。

## 9. 自审

- 首屏是否明确：明确，改写先给原文再说明目标；新写作直接说目标，并可添加参考材料。
- 用户是否保有控制权：明确，材料清单和 Agent 的文体/任务建议都需用户确认或可编辑。
- 是否适用于多种文章：明确，通过通用步骤加文体专属信息，不把所有文章套进同一组字段。
- 是否控制材料范围：明确，用户选择授权文件夹后工作台仅在本机逐个全文扫描；主模型只收到有界相关片段，Jev 开关默认关闭，不上传全目录全文。
- 是否形成闭环：明确，提示词复制后可带回外部结果继续复核和改写。
- 不同来源是否能叠加：明确，文件夹/工作空间和额外单文件、多文件合并；参考材料与专业规则包可同时使用。
- 原文与参考材料是否易混淆：明确，待改原文单独导入；项目材料来自授权文件夹的全文检索，候选不设固定文件数上限，发送量受上下文预算控制。
- 代码目录候选是否易读：明确，默认过滤或折叠噪声文件，使用紧凑列表、按需展开摘录和过滤项入口。
- 长手册是否必须粘贴全文：否，允许文件导入；整本模式通过外部附件和分章节提示词处理，选章模式先提取目录。
- 原文解析边界是否明确：明确，列出支持格式、现有体积/页数/提取长度限制及扫描版 OCR 的核对提示。
- 目录候选是否会因规模再次难看：不会逐项渲染；分页 20 项、显示扫描进度和总量；全文逐文件扫描、及时释放正文，过滤项可恢复，扫描上限和截断均有提示。
- 页面是否仍会像截图一样堆满重复卡片和错误文字：不会，原文与辅助材料纵向分区；候选用紧凑行、每页 20 项，状态与过滤文件按组汇总。
- 提示词是否可能因选章而失去原文：明确提示整本/选章都要附原件，并输出选定章节标题和可用位置。
- 是否可能过度复杂：后续实现应按需显示专属字段，避免把所有步骤内容同时铺在一个页面。
- Jev 是否被当成万能模型：否，只承担独立配置后可选的有界排序/分类；读取、证据综合和最终提示词分别由本机检索、主模型及用户确认完成，中文表现通过项目样本评估，任务页说明哪些内容会发给 Jev。
- 全文扫描是否可能耗尽浏览器内存：设计要求逐文件流式扫描并释放正文，不建立全目录索引；仅保留预算内命中片段。扫描可取消并报告未扫描范围。
- 现有材料数量限制是否自相矛盾：已移除文件数 3/5 硬限制；UI 确认流程仍保留，实际输入按上下文预算约束。
- 上下文预算是否能被当前配置获知：主模型设置含输入 token 上限，默认 8,000；同时校验服务端请求体边界，超限时最多缩减重试一次。OpenAI 兼容中转站配置沿用 Base URL、模型名和 API Key；上下文能力按用户设置及服务响应处理。
- API 中转站是否会被误认为 Jev 可用：设计支持经验证的 Jev/Decisions 协议网关，也支持模型 ID 明确指向 Jev 的 OpenAI 兼容中转站；仅有可填写的 Base URL 不足以证明其提供 Jev。
- Jev/辅助模型协议是否可复用主模型客户端：System One/Decisions 使用对应协议客户端；OpenAI 兼容 Jev/通用辅助模型可复用聊天传输层，但使用独立配置和严格结构化输出校验，并按实际模型身份呈现。
- 辅助判断成本是否随候选数失控：检索仍覆盖所有授权候选；辅助判断不设候选数量上限，但限制每次完整请求累计 4,000 tokens、3 个并发请求，预算外或失败材料明确标记并仍交主模型判断。该预算属于成本保护初值，中文对照评估后可调整。
- 中转站连接检查是否会发送用户材料或泄露密钥：只发送最小探测请求，不包含任务/文件内容；密钥仅放授权头且不进入 URL、日志或错误展示，探测只验证接口和格式，不认证模型身份。
- 文件内容是否可能泄露凭证或注入指令：所有命中片段出站前遮蔽敏感模式；文件文本作为不可信资料，Jev 分数和 injection 判断都不是权限/安全边界。
- 设计稿和实施计划是否同步：计划已改为不限制参考材料份数，并覆盖全文件检索及辅助判断；实施中继续以本稿的状态区分、预算核算和错误降级条款为验收依据。
- 材料状态是否可能混淆：本机检索命中不等于模型已复核，模型推荐不等于用户确认，用户确认也不等于片段已成功发送；各阶段需分别展示状态及未纳入原因。
- 没有匹配或任务目标不足时是否会误选：不自动把未匹配候选加入材料；允许补充目标、手动选择或不带材料继续。用户明确手选项优先保留，不能被自动排序覆盖。
- 输入预算口径是否自洽：主模型与辅助模型预算独立；完整消息 token 估算、服务端请求体字节数分别检查；usage 仅供校准。重要约束不得静默截断，无法容纳时明确报错并保留输入。
- 未扫描、未评估、被裁剪和失败文件是否可区分：分别展示扫描状态、辅助评估状态、发送状态及失败原因，不把任一未完成状态解释为“不相关”。
- Agent 的增量检索是否可控：只接受 schema 白名单 `search`/`read` 请求，最多三轮、每轮五个搜索词，并校验目录权限、路径、定位和预算。
- 推荐依据与发送内容是否一致：协调器仅接受本轮实际发送且有摘录的候选 ID，返回预算裁剪后的真实摘录；UI 重分析开始即清空旧建议，失败时保留手动材料选择但不展示旧推荐。
