## 缺口与目标

当前写作工作台接受 `.pdf`、`.docx`、图片文件，但对这些格式统一生成 `unsupported` 卡片。蓝图 A08、材料规则和图像识别要求尚未实现。当前会话没有暴露 MinerU `parse_documents` 工具；开发机存在的 `pdftotext` 来自 MiKTeX，不能作为目标用户的隐含系统依赖。

目标是在不外发文件的前提下，为 PDF 文本、DOCX 文本和图片 OCR 提供可随应用运行的本地解析路径；扫描版 PDF 若能在上下文预算内本地渲染并 OCR，也纳入支持。显示文件类型、页数/范围、识别状态和不确定边界；失败时保留原材料卡片及替代入口。解析结果只作为未核验材料，不把 OCR 或文本抽取升级为事实核验。

## 实施约束

- 保留当前未提交改动；不安装或调用仓库外脚本，不依赖开发机单独安装的工具。
- 实际选择的 PDF、DOCX、OCR 库必须兼容项目支持的 Node/Electron 版本、Windows 打包方式和离线运行；依赖、数据文件及许可证一并进入运行包。
- 文件内容只送到应用本机解析服务；不得调用远程 MinerU、模型或第三方 OCR。不得记录绝对路径、原附件或完整抽取全文到日志/备份。
- 实施前设定文件大小、页数、压缩比、解压字节数、识别字符数、运行时间和并发上限，拒绝 ZIP 炸弹、超大页和无界 OCR。
- 解析文本只作为本轮可选材料。保留原始文件名、解析状态、来源位置、字符范围和“不等于已核验”的状态；给提示词的内容仍受现有 3 份材料、单份 1200 字预算约束。
- 每阶段先补失败测试；每项完成后运行相应专项。应用验收使用明确标注的合成 PDF、DOCX 与图片，不接真实模型、不联网、不做真机测试、不提交代码。

## 阶段 1：确定本地解析运行时与边界

**范围：** `package.json`、`pnpm-lock.yaml`、`server.js`、新增解析模块、测试。

- 比较并选定与 Electron/Node 版本兼容的 PDF 文本抽取、ZIP/DOCX 文本抽取、离线 OCR 实现；记录固定版本、许可证、包体积和运行时位置。
- DOCX 只读取规范化后的文档正文与表格文本；拒绝宏、外部关系和不受支持的加密内容，不解压路径外文件。
- PDF 按页抽取可用文字；若需扫描件 OCR，限制可渲染页数与图像尺寸，检查原图定位和低置信识别标记。
- OCR 语言模型和 WASM 必须随应用离线携带，不在首次识别时下载。
- 为格式白名单、内容长度、并发、超限及取消编写测试；保持服务的其他路由和旧浏览器调用兼容。

**退出条件：** 无外网时能解析固定合成样本；依赖在项目声明的运行时范围内可加载；不读取样本目录外文件；预算与取消可验证。

## 阶段 2：本机解析 API 与安全失败状态

**范围：** 新增纯解析模块；修改 `server.js`；新增 API、大小边界和失败测试。

- 只接受明确的 MIME/扩展名组合，不信任用户提供的路径或文件名；解析数据通过本机请求体传递。
- 将文件读取、ZIP/XML/PDF 解码和 OCR 与 HTTP 层分开；响应只含有界文本片段、页/行定位、原始字符总量、解析状态和可读错误。
- 对加密、损坏、空文档、图片无文字、超限、取消及依赖不可用分别返回明确状态，不返回堆栈、路径或临时文件位置。
- 所有临时内容在请求结束、取消和错误时释放；外部模型和网络调用计数为零。

**退出条件：** 本机 API 测试覆盖成功与每类失败；日志/响应无附件全文、系统路径或凭证；原有服务测试通过。

## 阶段 3：工作台接入、提示词与预算

**范围：** `prototype/writing-workbench-ui.js`、必要的 schema/prompt 更新、UI/helper 测试。

- 对 PDF、DOCX、PNG/JPEG/WebP 真实发起本机解析，并在卡片显示读取/页范围、字符数、状态和失败原因。
- 支持从已抽取内容选择有限摘录加入本轮；标记页码或图像来源位置、抽取/OCR 状态和未核验边界；原始附件仍由用户按提示另行提供给外部 AI。
- OCR 结果标注识别置信或“可能有误”提示；图表、公式、手写和版面结构不能声称准确还原。
- 用户切换项目、删除材料或取消时，不将迟到结果写入新任务；失败时保留原卡片及用户未提交输入。
- 解析输出不绕过现有选材理由、材料用途、提示词预览、发送确认、保存与备份规则。

**退出条件：** 每种格式的结果与实际可复制提示词一致；未选入的内容不进入提示词；解析失败不伪装成已读取。
