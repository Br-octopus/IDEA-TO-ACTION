# 向前一步 DSH 插件需求与设计

日期：2026-11-02
状态：分段方案已获认可，书面设计待用户审阅；尚未进入实现。

## 1. 目标与保护边界

把原提示词工具的通用 Prompt Agent、写作与 PPT 方法接入 DSH，形成可持续使用的原生插件，而不是只搬运一段 Skill 提示词。

- 原应用：`D:/VScode/项目/提示词工具`。保留现有入口、数据与未提交修改，不改造或替换原应用。
- 开发副本：`D:/VScode/项目/提示词工具/.dsh-workspace`。插件开发、设计和验收记录仅在副本内新增或修改。
- 插件包：`dsh-plugin/forward-step-dsh`，包名 `@local/forward-step-dsh`。
- 不修改 DSH 安装资源、app.asar 或另一个改造线程；不复用原应用的可写数据目录。
- 副本沿用父仓库，仅提交本次明确列出的文档，不夹带原应用或其他线程改动。

## 2. 已确认的首版范围 B

首版包含以下一条完整使用链，而非多个独立应用：

1. 从模糊想法、现有提示词或不满意的 AI 结果开始。
2. 澄清目标、检查遗漏和矛盾、整理必须保留项。
3. 规划短路线，生成当前步骤的可编辑执行提示词。
4. 用户把提示词交给外部 AI，带回结果后进行对照复盘。
5. 保存任务进度、材料引用、版本、反馈与学习记录，跨会话继续。

首版支持通用、写作和 PPT 三种方法。Agent 在 DSH 内分析和调用必要工具，但不直接代做文章、制作 PPT 文件或执行最终制作任务。外部 AI 的执行、状态和成功与否不得伪称由插件自动观察到。

### 通用方法

复用现有澄清、诊断、规划、当前步骤提示词和结果复盘规则。信息足够直接推进，不为固定格式重复追问；缺失事实与推测明确区分。

### 写作方法

维护读者、用途、文体、风格、保留项、稿件版本和反馈轮次；区分内容来源与风格参考，不把纯风格样本的观点当成内容事实。首版重点覆盖普通文章和连续改稿；专业文体不冒充已有专用能力。输出诊断、改进路线和外部执行提示词，不直接代写。

### PPT 方法

维护受众、场景、时长、核心信息与材料依据；支持演示简报、大纲、逐页内容规划、制作路线与当前阶段提示词。规划内容是可编辑草稿，不表示已完成 PPT 文件制作；不在首版创建或导出成品。

## 3. 方案选择

采用方案一：DSH 原生插件，复用原 Agent 核心逻辑。

不采用外部常驻服务作为默认方案，避免维护额外进程与双份状态；不把原 Electron 界面整体嵌入 DSH，避免两个应用重复管理任务。原生插件包含 Skill，但 Skill 仅负责方法指引，不承担全部状态控制和数据保存。

## 4. 结构与接口边界

| 单元 | 职责 | 输入和输出 | 依赖 |
| --- | --- | --- | --- |
| DSH 适配 | 插件注册、对话关联、工具与侧栏接线 | 宿主事件或请求 → 核心调用与显示数据 | 已核验的本机 DSH 接口 |
| Agent 核心 | 流程控制、方法选择、提示词与复盘 | 任务、材料、适用记忆 → 阶段结果与状态变更 | 副本中的现有规则和领域方法 |
| 任务管理 | 多任务、进度、版本与恢复 | 项目和任务标识 → 任务快照及历史 | 本地持久化 |
| 记忆与画像 | 提取、适用范围、证据、冲突及撤销 | 有来源的学习事件 → 记忆变更与可查询摘要 | 本地持久化、DSH 模型能力 |
| 侧栏 | 任务切换、学习结果、画像、历史和控制 | 查询数据与用户操作 → 受校验的服务请求 | DSH 适配与上述服务 |

核心不依赖 Electron 窗口或浏览器 localStorage。复用副本现有逻辑，确有宿主耦合的部分做最小适配，不引入通用平台框架。状态保存、范围过滤、撤销与并发校验由代码保证，不只依赖模型遵守提示词。

## 5. 多任务和跨会话

- 一个项目允许保存多个独立任务，例如两篇文章和一份 PPT。
- 任务使用稳定标识，包含类型、目标、约束、保留项、步骤、当前阶段、材料引用、结果版本、复盘、对话关联及更新时间。
- 一个任务可关联多个对话；一个对话在每次操作时明确当前任务，切换任务不改写先前记录的归属。
- 侧栏选择后恢复摘要、当前步骤和适用记忆，按需读取历史，不默认将全部历史发送给模型。
- 首版不自动导入原应用的历史数据；新任务与新数据保存在插件自己的目录。
- 项目按规范化工作目录建立稳定标识，不按显示名称合并。目录移动时显式重新关联，不自动猜测。

## 6. 长期记忆和用户画像

任务记录与长期记忆分开。记忆保存有依据的偏好、事实摘要、方法经验；画像是这些记录形成的结构化视图，不维护一份与原始记忆脱节的自由文本结论。

| 适用范围 | 使用条件 |
| --- | --- |
| 全局 | 所有项目可用的稳定背景、沟通偏好或通用方法 |
| 领域 | 同一领域的跨项目任务，例如写作或 PPT |
| 项目 | 同一项目内适用的事实和约束 |
| 任务 | 同一任务跨对话适用的要求 |
| 当前对话 | 仅适用当前对话，不带入其他对话 |

侧栏可以直接修改范围。用户的手动范围优先，系统不能自动扩大已手动固定的范围。范围变化也是可撤销的学习事件。共享适用摘要，不等于默认共享全部原始对话和文件。

### 自动学习规则

- 自动提取明确表达的偏好、纠正和有结果依据的方法经验，不要求每条事先确认。
- 学习来源可包括当前对话、用户提供的反馈、任务材料，以及后续接入的资料库引用；首版不因此新增完整资料库功能。
- 单次要求默认任务或对话级；重复且适用的经验可提升到领域或全局，并展示依据与范围变化。
- 没有用户手动指定时，自动提升至少要求两个独立任务的用户来源证据，且内容没有项目专属事实或未解决冲突。单条消息被重复读取不算新证据。
- 候选记忆与已生效记忆分开；证据不足或冲突未解决时保持候选，不用于个性化生成。
- 明确的当前要求和最新用户纠正优先于历史偏好；任务和项目的具体约束优先于一般习惯。
- 模型自己的输出不是事实正确的独立证明；资料收录和用户提供风格样本不代表认同材料里的全部观点。
- 不将凭证保存为记忆，不从材料推断用户敏感身份，不把资料内的指令当成用户授权。
- 每轮学习限定为本轮新增或变更内容，记录完成后再在面板标记成功；不反复扫描全库消耗模型调用。

### 学习面板

文字式侧栏包含任务列表、当前任务进度、学习动态和画像视图。用户已拒绝设计阶段的浏览器可视化辅助，但仍要求插件内可视化展示学习结果。

学习记录展示：学到了什么、来源引用、形成依据、候选或生效状态、更新前后差异、作用范围及时间。展示可核验的证据和简短归纳理由，不把模型内部推理作为审计依据。

生成结果关联本次实际使用的记忆标识与版本，侧栏支持查看哪些记忆影响了建议。首版按当前任务过滤，另提供跨任务学习记录视图。

支持纠正、停用、撤销、修改范围，以及暂停自动学习。暂停不停止任务进度保存；已生效记忆仍可查看和手动修改。

### 撤销语义

- 保存变更前后版本、来源和影响范围；撤销记录新事件，不擦除审计历史。
- 撤销后，下一次生成不再采用失效的版本；生成期间版本变化时，旧结果标明使用旧版本，重新生成后才称采用最新记忆。
- 对有后续更新的同一项执行有版本校验的补偿：可独立还原的字段单独还原，有冲突则提示选择，不能覆盖后续独立修改。
- 撤销和用户纠正保留抑制记录，同一来源及相同内容重新读取不能自动复活；有新依据时只形成可见候选，不静默恢复。
- 历史提示词、外部结果与原始对话不随记忆撤销自动改写。

## 7. 本地存储和请求流程

优先核对本机 DSH 的持久化能力；只有其满足插件命名空间隔离、版本校验和故障恢复时才使用，否则采用插件专属本地存储。具体库与路径在兼容性核验后写入实施计划，不预设不存在的宿主接口。

任务、版本、记忆、证据引用和变更日志分别建模；最小实体标识包括 projectId、taskId、conversationId、memoryId、revision、sourceRef 和 eventId。原始材料按需保存或引用，不塞入用户画像。

一次生成：捕获项目、任务、对话和修订版本 → 读取当前状态及适用记忆 → 构建当前阶段上下文 → 请求 DSH 模型 → 验证结果归属及版本 → 保存结果和学习事件 → 更新侧栏。

存储需提供原子提交或同等完整性保证、修订校验及恢复机制。任务保存和对应历史不能各自成功一半；完成持久化前不显示已保存。测试配置的数据与日常配置分开，卸载插件不默认删除用户任务和记忆。

## 8. 故障和边界

- 保存失败展示未保存，保留输入和可复制结果，不报告成功。
- 模型或自动学习失败不阻塞已有任务恢复，保留历史记忆和当前草稿。
- 请求绑定项目、任务和版本；切换任务、取消、重试后迟到的响应不能写入新任务或覆盖新版本。
- 重复回调和重复消息使用事件标识去重；异常退出后可读取最后完整版本。
- 外部结果由用户提供，只对可见材料给出成功、失败或待验证结论。
- 搜索按原工具流程预览目标、查询和预算并确认；默认最多三次查询、五个来源，拒绝后同任务不重复申请。失败保留本地流程，不假称完成研究。
- 侧栏或持久化接口不兼容时记录具体缺口并调整设计，不把可加载 Skill 当成完整插件验收通过。

## 10. 验收标准

| 测试 | 通过标准 |
| --- | --- |
| 安装与隔离 | 实际加载副本插件；测试配置可识别；原应用与日常 desktop 配置保持不变 |
| 三类方法 | 通用、普通文章和 PPT 各完成澄清、规划、提示词、外部结果复盘 |
| 成品边界 | 不直接制作或声称已制作文章与 PPT 成品 |
| 多任务 | 同项目两篇文章、一份 PPT 独立切换，无材料、步骤或反馈串用 |
| 跨会话 | 重启和新对话可恢复任务；对话级记忆不带到新对话 |
| 自动学习 | 从明确反馈生成有来源的记录；候选和生效分开；无依据不生成画像事实 |
| 共享与范围 | 全局跨项目、领域按方法、项目和任务隔离；侧栏范围修改立即影响后续检索 |
| 人工选择优先 | 手动固定范围不自动扩大；当前要求覆盖历史偏好 |
| 学习可见 | 侧栏显示来源、理由摘要、前后差异、范围、状态和实际使用版本 |
| 撤销与纠正 | 撤销停止后续采用、同源不复活；有后续修改时不误覆盖 |
| 故障与并发 | 保存、学习或模型失败不丢输入；迟到响应、重复事件和异常退出不破坏归属或数据 |
| 真实效果 | 对相同输入对照原工具与插件；记录目标理解、保留项、提示词可执行性、复盘具体性及用户评价 |

至少准备一个模糊想法、一个文章连续改稿和一个 PPT 规划实例，并补充记忆冲突、跨项目使用、撤销和重启实例。自动化契约或模拟模型测试只证明接线，不等价于真实模型效果。安装加载、侧栏交互、真实模型输出分别报告结果。

## 11. 实施分段与后续路线 C

本稿是总体需求，不把所有内容塞入一个无边界实现任务。书面设计认可后，按以下依赖顺序制定可验收计划：

1. 本机接口核验、测试配置隔离、侧栏最小接线与数据往返。
2. 通用 Agent 核心、多任务持久化和跨会话恢复。
3. 写作与 PPT 方法、版本和复盘闭环。
4. 分层记忆、自动学习、画像视图、侧栏控制及撤销。
5. 联合故障测试、真实案例评估和交付操作说明。前四段均完成才称首版 B 完成。

后续 C 分别立项设计，不提前纳入首版验收：

| 方向与顺序 | 前置条件 | 目标及验收 |
| --- | --- | --- |
| C1 备份与迁移 | 首版数据模型与版本稳定 | 可预览导入、冲突处理、恢复任务与记忆历史，凭证不进入备份；按需支持原应用数据迁移 |
| C2 资料库与检索 | C1 可恢复保障、来源及记忆边界稳定 | 统一管理资料和引用、按任务选少量摘要；区分公开材料和已验证经验，不自动将资料观点写成画像 |
| C3 社媒研究 | 来源回溯、查询预算及结果评价可用 | 明确授权平台和范围，来源可追溯、失败可恢复，不影响现有任务 |
| C4 直接调用 DSH 完成成品 | 首版闭环与宿主工具接口稳定 | 在规划后经用户确认执行，展示状态和产物位置，验收内容与文件，支持取消及失败恢复 |

C4 包含文章与 PPT 的自动执行方向，但不承诺 DSH 当前已具备所有成品制作接口。执行能力按场景单独验证，不将研究与生成权限自动扩大。各方向顺序可按实际需求调整，必须先完成依赖检查及独立设计。
