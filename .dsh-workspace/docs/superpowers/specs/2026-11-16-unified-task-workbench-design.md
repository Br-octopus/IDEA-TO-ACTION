# 统一任务工作台：对话、内容与多画布

日期：2026-11-16

状态：用户已确认主要交互与多画布方案；融合补充规则为本文件提出的推荐默认，尚未实施。

## 1. 目标与范围

将新任务、提示词 Agent、写作工作台融合为一个任务入口，主要交付供外部 AI 使用的提示词与配套素材。用户主要输入任务目标，之后在同一任务中补充资料、生成提示词、回填外部结果、批注并迭代。

融合重写界面与任务组织方式，沿用现有可复用的提示词、文体规则、预览、附件和批注能力。不将界面统一等同于删除历史数据或重新实现所有格式编辑器。

本设计针对 task-workbench-merge 工作树中的桌面应用。文档沿用 `.dsh-workspace/docs/superpowers/` 存放约定，不因此扩大到 DSH 插件改造或其他独立工作区。

## 2. 已确认的决策

| 决策 | 具体约定 |
| --- | --- |
| 一个连续工作区 | 不再将需求、提示词、回填拆为三个必经页签；随用户当前操作变化内容 |
| 轻输入 | 起始主要填写任务目标；提示词引导外部 AI 在影响结果时追问，避免预先填写长表单 |
| 两个内容入口 | 对话中的文档/画布卡片，以及任务顶部的“本任务内容”；都引用同一份内容 |
| 独立粘贴文档 | 大段正文放入新建文档，可命名、编辑与批注；修改意见输入框独立 |
| 内容用途 | 按进度智能默认，用户可改为参考资料或外部结果；改用途不丢正文、批注和历史 |
| 多类型内容 | 文稿、PPT、PDF、网页/APP 截图、网页文件/网址、图片/海报 |
| 输入与输出分离 | 输入格式不锁定目标，可从 PPT 提取 APP 需求、从海报提取文案 |
| 多画布 | 一项任务按需创建多张画布，各有名称与用途；不预建一组空画布 |
| 轻量画布 | 拖入图片、移动缩放、框选批注、分组、多图对比和本轮素材选择 |
| 参考与构图分离 | 默认排列只为整理参考；明确选择“按此构图”才把空间关系写进提示词 |
| 本机持久保存 | 未命名文档与画布也保存，提供打开保存位置与完整任务导出 |
| 历史可追溯 | 外部新结果另存版本；生成提示词时固定本轮素材版本 |

确认依据：对话中的七项批注确认，以及多画布方案的完整确认（批注 ID：3c1fc310-6db8-4243-8c35-999f94a3a56b）。

## 3. 页面组织

左侧为任务列表，中间为连续对话与固定输入区，右侧为按需打开的预览或画布。任务名称显示在顶部，避免重复大标题和说明文字。

“本任务内容”集中列出文档、文件、画布和提示词，允许按类别筛选，但不引入新的必经工作步骤。点击条目在右侧打开；窄屏使用单区查看并提供返回对话入口。

预览支持关闭、放大和固定。固定后导入或生成新内容只出现入口，不抢切换。查看内容时可选文引用回输入区；关闭预览不删除内容。

画布顶部提供名称与切换入口，以及新建、重命名、复制操作。多张画布不铺成永久页签。画布聚焦时可放大为主工作区，返回后保留视角。

## 4. 核心交互

### 4.1 开始与生成提示词

用户输入目标即可建立任务。对话展示本轮提示词入口和配套素材，不把很长的提示词正文持续铺满主区。提示词可预览、编辑、复制和导出；已手动修改的版本不被自动生成覆盖。

生成时明确列出本轮使用的文档、页码、图片、批注与版本。默认使用当前选中内容，允许跨画布补选。没有选中素材时显示“本轮未附素材”，不静默附上任务全部资料。

任务不依赖用户已经配置模型才可保存、导入、编辑或回填。关于生成方式与未配置模型时的体验，采用第 8 节推荐默认。

### 4.2 粘贴与导入

“添加内容”提供新建粘贴文档、导入文件、添加网址与新建画布。图片可通过文件选择、拖入或粘贴加入。

新建文档打开独立编辑区。首次有正文输入即创建可恢复草稿，暂用“未命名文档”；再次新建不清空上一份草稿。关闭编辑器保留草稿。提交到对话只是新增入口，不是首次保存的唯一触发点。

整理目标时默认作为参考资料；正在等待外部结果时默认作为外部结果。默认依据以短提示呈现，用户可调整用途。批量导入可统一设置后逐项修改。

外部结果默认推荐当前轮次的结果画布，可选择已有画布或新建。存在多份可能的前稿时，由用户选择关联对象，不根据文件名直接覆盖。

### 4.3 按类型预览与批注

| 内容 | 展示和操作 | 提示词用途与边界 |
| --- | --- | --- |
| 文稿 | 独立正文、选文批注、版本查看 | 改写、扩写、结构调整；批注引用对应版本的原文 |
| PPT | 页缩略图、当前页、整页/区域批注、多页选择 | 逐页修改、叙述顺序、版式和配图；第一版不承诺完整 Office 编辑能力 |
| PDF | 分页、可用文字层引用、图表/扫描区域框选 | 摘要、分析、转文稿或 PPT；没有可读文字层时明确保留图像引用，不伪造解析结果 |
| 网页/APP 截图 | 单图或多图画布、组件框选、页面关系说明 | UI 复刻、布局、组件、状态与交互；不可见行为由用户补充，不当作截图已证明的事实 |
| 网页文件/网址 | 原文件或静态快照、来源、选文/区域批注 | 改版、提取、组件复刻；快照不等于可运行应用，抓取失败保留网址和失败状态 |
| 图片/海报 | 放大、区域批注、多图参考、主体/配色/风格/构图用途 | 生图、参考融合、局部修改、海报排版；保留原图并交付所需素材 |

局部图片批注第一版以矩形区域和文字意见表达，不扩成专业绘图软件。PPT/PDF 页面或文稿片段放入画布时，保留来源版本、页码/片段定位和“打开原内容”入口。

### 4.4 多画布与素材关系

例如同一任务可有“品牌参考”“构图探索”“第一轮结果”“第二轮参考”。系统提供默认名称，用户自由命名和修改用途。

任务拥有素材原件与文档；画布保存引用、排列、分组和局部批注。相同素材可放入多个画布，原件不重复复制；每个画布中的摆放、选择和局部批注独立。

复制画布创建新的排列与批注记录，继续引用原素材版本。后续修改其中一张画布不影响另一张。使用素材新版本时显式替换引用，不让所有画布自动跟随最新版。

从画布移除节点、关闭画布或移除对话入口，都不删除原件。删除画布也不连带删除任务素材。删除仍被历史提示词引用的内容采用保留历史版本的方式，不产生无提示的断链。

“按此构图”是独立的显式选择，只作用于本轮选定范围；普通缩放平移视角不成为构图指令。页面之间的关系第一版通过分组与文字关系说明表达，暂不引入复杂连线编辑器。

### 4.5 一轮生图或 UI 复刻

1. 用户描述目标，添加参考图片或页面。
2. 用户选择素材并标明各自用途，在需要处框选批注。
3. 工作台生成可编辑提示词，同时展示素材清单；构图要求仅在明确启用时纳入。
4. 用户复制提示词并下载所需素材，交给外部模型。复制动作不宣称模型已接收或执行。
5. 外部结果导入当前任务，关联对应提示词轮次，作为新版本或独立候选。
6. 用户对比结果、补充意见并生成下一轮，旧结果和旧提示词继续可查。

示例提示词结构：

```text
任务目标：根据所附参考制作新品海报。
参考用途：图1仅参考配色；图2仅参考构图；图3为产品外观依据。
必须保留：产品外形、标志与比例；主标题“轻装出发”。
本轮意见：减弱背景装饰，保留产品位置。
输出要求：给出符合目标比例的海报；缺少关键条件时先提出必要问题。
附件清单：列出本轮实际选中的文件与版本。
```

## 5. 保存、恢复与版本

### 当前事实

- 交互草图 `.superpowers/brainstorm/1844-1794758883/content/import-and-pasted-document-v4.html` 的临时操作保存在内存，刷新清空；草图源文件不是用户内容备份。
- 当前桌面任务状态通过 `prototype/storage.js` 保存到 localStorage，主键为 `forward-step.workspace.v2`。
- 当前桌面附件保存至 `app.getPath('userData')/ppt-feedback/<taskId>/<attachmentId>/`，批注位于任务目录的 `annotations.json`；实际绝对路径以运行时返回为准。
- 多画布、统一文档草稿持久保存与完整历史关联尚未实现。

### 正式实现要求

- 自动保存任务目标、意见输入草稿、未命名文档正文、未提交批注意见、已提交批注、画布排列与用途、提示词编辑稿和版本关联。
- 导入复制原件到应用管理目录；原文件移动后任务仍可使用。二进制文件不嵌入 localStorage。
- 显示“保存中 / 已保存 / 保存失败”。只有对应内容实际写入成功才标记已保存；保存失败不清空编辑区，提供重试和导出。
- 桌面新增内容沿用应用数据目录。正式实现计划确定新记录的文件组织与现有附件索引关系，不迁移整个应用的数据仓库。
- 写入中断不破坏上一次成功内容；写入完成前保留旧记录。正常切换、关闭编辑器和退出时提交待保存草稿；异常退出恢复到最后一次成功保存，不承诺恢复未落盘的最后输入。
- 外部结果另存版本；正在编辑的草稿持续保存，不把每个按键创建成用户可见历史版本。生成提示词、明确保存版本或导入新结果时保留可追溯版本。
- 批注锚定具体内容版本。内容变化导致定位失效时显示原引用和“需重新定位”，不自动贴到相似但不确定的文字上。
- 提示词轮次记录正文、素材版本、选中批注及构图意图。之后重命名或继续编辑不改变历史轮次的实际依据。
- “打开保存位置”打开真实的本机任务目录；“导出任务”包含清单、正文、原件、画布、批注、提示词及历史引用，不包含模型凭证。
- 任务备份和本轮素材包分开：备份用于恢复全部任务，本轮素材包只包含外部模型需要的所选文件和清单。导出失败或缺文件明确报告，不冒充完整成功。

## 8. 三板块融合仍需落实的规则及推荐默认

以下补足融合行为，不改变已确认的页面方向。它们是设计建议，尚未作为功能完成记录。

| 需落实的规则 | 推荐默认 | 对用户的结果 |
| --- | --- | --- |
| 旧任务、独立提示词与历史稿件如何接入 | 旧任务保留身份；有明确关联的内容映射至同一任务，独立内容保留来源并单独列入历史；不按相似标题自动合并。新入口稳定前保留旧内容访问路径 | 历史稿件和版本不因融合丢失，也不被误并 |
| 哪部分负责生成提示词 | 用一个生成入口组合现有任务上下文、提示词 Agent 和文体规则，避免三份重复生成逻辑。用户选的目标决定所用规则，输入文件类型不决定目标 | 不需要先选择“进入哪个板块” |
| 是否必须配置模型 | 保存、导入、批注和回填不依赖模型。未配置模型时允许整理可复制的基础任务提示词；智能优化仅在已配置服务可用时运行，并明确当前方式 | 随时可继续任务，不把模板结果冒称智能生成 |
| 如何决定当前步骤 | 用建议动作表达“准备提示词、等待结果、继续迭代”；允许随时补充资料或回到旧结果。复制提示词只记录复制，用户回填或明确操作才关联执行轮次 | 流程提供帮助，不强迫按固定步骤走 |
| 一轮多个结果如何组织 | 多个候选并列，用户选择继续哪份；新版本明确关联前稿与提示词轮次，候选之间不相互覆盖 | 支持比较多个模型或多个方案 |
| 编辑稿与新生成稿发生冲突 | 保留用户手改稿，新结果形成另一版本并提供比较/采用；生成失败或切换任务不清空草稿 | 手动修改不会被后台生成覆盖 |
| 保存和模型调用失败时怎么办 | 保留现有内容与上次成功版本，指出失败发生在保存、解析还是生成；仅重试失败操作 | 不必从头建立任务 |

## 9. 实施分段与未完成记录

建议一个总体设计、按依赖分段实施：

1. 任务内容归属、历史兼容、草稿保存和备份恢复。
2. 三板块统一入口、连续对话、独立文档和统一提示词生成。
3. 多画布、素材引用、批注与轮次版本关联。
4. 多格式入口接入、生图/UI 复刻提示词和素材包交付。

目前以上为设计，不标记为已开发。仍需在实施计划中基于实际代码确定：旧记录关联字段、新存储记录的精确结构、各格式解析能力及失败呈现、现有提示词路径的调用关系。它们由代码勘察决定，不要求用户选择数据库或前端框架。

实现时记录真实完成项与剩余项。单次设计文档审阅不等于所有能力已经实现，也不要求再次逐条确认前面已批准的交互。
