# 向前一步 DSH 插件全功能迁移设计

日期：2026-11-05

状态：已获用户确认用于实施（2026-11-07）；本文定义全功能迁移目标，不表示功能已实现或验收通过。

## 1. 目的与文档关系

本设计把“向前一步 DSH 插件”从原先通用 Agent、写作与 PPT 的首版范围，扩展为将提示词工具中全部面向用户的能力分阶段迁入 DSH 插件。原应用保持原样，插件代码、插件专属数据和本设计均位于 `.dsh-workspace` 副本范围内。

本文是全功能迁移的主设计。它保留并扩展 `2026-11-02-forward-step-dsh-plugin-design.md` 中已经形成的插件核心、任务续接、记忆、画像和人工提示词闭环；对于全功能范围、迁移入口和阶段顺序，与 11 月 2 日稿中“C1/C2/C3 后续另行设计”“首版不导入历史数据”等冲突条款，以本文为准。11 月 2 日稿及原应用各领域设计仍是已有实现背景、领域规则和验收案例的参考，不因本稿而被覆盖。

范围来源包括原应用主导航、运行时数据模型、工作区备份实现，以及提示词 Agent、资料库、写作、PPT、学术和社媒研究专项设计。原应用不因此获得任何新功能或代码改动。

## 2. 已确认的产品决策

以下为用户已确认的方向：

1. 目标是将提示词工具的面向用户功能全部迁入插件，不把“全功能”缩减为提示词入口或 Skill。
2. 采用分阶段交付：先做通用基础层，再依领域闭环迁移；阶段顺序见第 8 节。
3. 原应用保留原样；插件使用独立数据存储，不直接扫描、复用或写入原应用可写数据目录。
4. 提供由用户显式选择原应用 ZIP/JSON 备份的迁移入口。导入是一次性复制；后续原应用有新数据时，由用户再次手动导入，不做持续同步。
5. 迁移不包含 API Key、密码、令牌、Cookie、平台登录会话等凭证或认证状态。平台登录在 DSH 侧重新授权。
6. 插件功能应尽可能达到原应用用户能力对等；需要宿主支持的模型、搜索、文件和目录能力通过 DSH 适配或重新授权实现，并如实显示能力是否可用。
7. 非敏感偏好若未包含于原应用可选备份，不从应用私有设置存储猜测或读取；在插件内重新配置。插件自身的偏好可随插件备份恢复。

## 3. 产品边界

- 插件是 DSH 原生工作区和业务模块，不是把原 Electron 界面整体嵌入，也不是仅发布一个 Skill。
- 复用经检查适用的领域规则、schema、提示词流程和测试案例；不将整套原应用运行时或可写数据目录直接复制为插件依赖。
- 用户数据、迁移结果、索引、附件和设置均归插件独立管理。插件卸载、恢复和重装语义须由插件侧定义与验收。
- 外部 AI 提示词由插件生成、编辑、保存和复制；除某个已有领域能力明确由 DSH 宿主工具执行外，不能伪称插件观察到用户在外部 AI 中的执行过程或成功状态。
- 写作和 PPT 中以规划、提示词、诊断、预览或反馈为交付物的能力，不冒称为已经生成或编辑文章/PPT 成品。若将来增加宿主成品制作能力，应作为明确的 DSH 适配能力单独验收。
- 社媒采集只执行用户确认范围内的研究动作；不迁移认证态，不对无法使用或未验证的平台伪报成功。

## 4. 功能对等原则

“功能对等”按用户可完成的任务链验收，而非按菜单名称或页面数量验收。每个迁移项均需证明：入口可到达、必要输入可编辑、关键动作可完成、状态可保存与恢复、失败可见、关联来源可追溯、相邻模块的数据边界有效。

需分别记录三种状态：

| 状态 | 含义 |
| --- | --- |
| 功能实现 | 插件存在相应交互与业务逻辑；自动化测试可作为局部证据 |
| 真实能力可用 | 当前 DSH 宿主、模型、搜索、文件或平台适配实际可运行 |
| 数据迁移支持 | 指定备份格式中确有该类数据，且导入后关系和附件可正确恢复 |

其中一种状态通过，不得推断另外两种也通过。阶段验收记录需指出目标版本、宿主能力、测试输入和证据位置。

所有既有写作文体均在长期迁移范围内，不能因分期而默认为排除：普通文章、长篇研究文章、学术/学位论文、文献综述、审稿与投稿准备、商务营销、新闻与机构新闻稿、技术与产品文档、社交媒体与短内容、影视/口播/播客/演讲、小说、剧本、教程课程、简历求职、邮件、公文和法律文书等。每种文体须有适用规则、来源、材料处理方式和代表性完整任务验收；仅添加名称或空白模板不算迁移完成。具体文体以既有《全文体写作提示词工作台扩展设计》覆盖矩阵为准。

长期记忆与画像是跨领域能力，不限于写作。记忆候选需保留来源、适用条件和验证状态；自动学习不得覆盖明确人工设置，历史偏好不得覆盖本轮明确要求。撤销需停止后续采用且不能使已删除来源自动复活；编辑/删除派生画像时须保持来源关系一致。撤销只影响插件记忆，不声称删除 DSH 原始对话。该能力复用既有插件记忆实现，并在基础层校验数据隔离，在规划与资产阶段核验管理交互，在最终全域验收覆盖跨项目冲突、撤销、重启和来源追溯。

下表用于保证菜单、嵌入入口和重要次级动作均有落点。实施计划须将每行展开为具体用例 ID，并附真实操作/自动化证据；“外链”仍须验证链接可见且用途说明准确。

| 原应用入口/动作 | 插件目标模块 | 主要数据/设置 | 最低验收用例 |

| 新建规划、最近计划、我的计划、步骤复盘 | 工作区与通用 Agent | `projects`、计划/步骤、提示词版本、案例 | 新建、暂停/续接、改提示词、外部结果回填、确认/跳过复盘并重启恢复 |
| 提示词 Agent、提示词优化 | 通用 Agent、提示词库 | `promptAgentTasks`、`promptAgentSources`、`prompts`、`cases` | 三类入口可组合领域；优化前后可比较；经真实案例验证后才标已验证 |

| 社媒研究、平台准备、研究结果/报告/附件 | 社媒研究 | `researchTasks`、`researchAttachments`、非敏感平台状态 | 四个活动平台分别测计划确认、运行/失败、暂停/重试、报告回链；历史平台只测查看 |
| 设置：主模型、搜索、辅助写作服务 | 插件设置/DSH Host 适配 | 原应用独立设置存储；敏感凭证排除 | DSH 模型与搜索能力分别配置/测试；辅助写作服务有无适配明确显示；凭证不导入、不导出 |

该追踪表不要求将第三方社区内容或研究样本整站复制进插件；“功能迁移”可以通过保留外链及来源说明满足入口连续性，但任何原应用内的本地业务动作都必须由插件功能或明确的不可迁移/需重配说明承接。

## 6. 独立架构与数据流

插件分为以下职责边界，优先沿用当前插件技术栈及已验证的 DSH 接口：

| 单元 | 职责 |
| --- | --- |
| 插件工作区 UI | 导航、领域面板、操作状态、提示词/结果/材料编辑与用户确认 |
| Host 适配层 | DSH 注册、对话/任务关联、模型调用、工具能力、文件授权与错误转换；只依赖经验证的宿主接口 |
| 领域核心 | 规划、提示词、写作、PPT、学术、社媒和资料领域流程；领域逻辑不直接访问宿主 UI 内部实现 |
| 插件存储服务 | 版本化 schema、隔离读写、迁移、备份恢复、附件元数据和索引重建 |
| 外部能力适配器 | 模型、普通搜索、文件/目录、平台采集和页面渲染；报告能力、授权、预算和失败状态 |

正常业务数据流：用户选择领域和任务 → 插件加载隔离工作区状态 → 领域流程生成候选计划/提示词/分析 → 展示本次将使用的材料、工具、预算和外发内容 → 用户确认后调用 DSH 能力 → 保存结果及来源 → 用户检查/修改/复盘并继续下一步。

迁移数据流：用户选择备份文件 → 临时解析和结构/附件清点 → schema 归一及敏感字段过滤 → 生成按类别预览 → 用户选择类别并确认 → 写入插件隔离存储 → 校验记录、关联和附件 → 输出逐类结果报告。解析阶段不得写入正式工作区。

## 7. 数据模型、迁移和冲突处理

### 7.1 插件独立数据

- 所有插件记录使用插件自己的命名空间、存储位置和 schema 版本；不读取或写入原应用 `localStorage`、设置存储或用户数据目录。
- 领域记录保留稳定实体 ID、来源 ID、创建/更新时间及必要关联；跨实体引用在迁移时校验，附件使用插件生成的内部标识和相对路径。
- schema 升级和数据导入分别执行；插件存储升级失败时保留可恢复的旧数据，不以空状态覆盖。
- 插件备份包含插件工作区数据及用户主动保存的附件；宿主模型/平台凭证不进入插件备份。

### 7.2 原应用数据导入范围

导入器针对用户显式选择且格式受支持的原应用备份，不直接读取原应用数据目录。格式语义必须区分：完整工作区 ZIP（`forward-step-workspace-archive`，当前归档版本 1）包含 JSON manifest 与被用户保存的研究附件二进制，是恢复附件的完整迁移格式；工作区 JSON 只包含其数据字段和附件索引，不含附件载荷，作为无附件/接受缺失附件的部分迁移输入；资料库范围 JSON 只含知识条目、案例和知识元数据，不能冒称完整工作区迁移。预览逐类统计记录数、附件数、重复、冲突、缺失字段、无法解析项和不支持项，并明确显示本次导入模式及缺失附件。

当前原应用运行时状态与备份字段并不完全相同，必须显式处理：

| 数据类别 | 现有来源/备份可见性 | 设计处理 |
| --- | --- | --- |
| 项目、计划、提示词、案例、资料条目、引用/参考 | 工作区 JSON 有对应字段 | 按类别映射并校验 ID、类型、引用；可选逐类导入 |
| 提示词 Agent 任务与来源 | 当前完整工作区备份可选字段 | 核验字段版本及关联后导入；任务状态不伪装为仍在运行 |
| 写作文章、轮次、记忆、专业包、包设置、复盘 | 完整工作区备份列有对应字段 | 只迁移备份实际包含且通过校验的记录；保存开关语义和来源必须保留 |
| DSH 插件任务记忆/画像与撤销历史 | 属于插件自有数据，不是原应用 `writingMemories` 的同一集合 | 插件自己的工作区备份单独保存和恢复；原应用写作记忆只映射到写作记忆模块，不自动升级为 DSH 跨项目画像或长期 Agent 记忆 |
| 常用写作工作空间 | 运行时状态 `writingWorkspaces` 存在，但当前工作区备份字段清单未包含 | 显示为“所选备份未包含”，不报导入成功；目录授权本身必须重新选择 |
| 学术投稿/审稿项目及关联文献快照 | `academicResponseProjects` 位于可选备份字段 | 按领域 schema 验证项目、快照、轮次与引用关系；文献来源缺失时标注不完整 |
| 学术综述记录、文献筛选/提取数据 | 可能嵌于上述项目或写作记录，不能仅凭集合名假设完整 | 依据真实导出 schema 枚举字段；无法识别的子结构列入未支持/待处理，不静默丢弃 |
| 资料选择与筛选状态 | 完整工作区字段含 `researchSelection`、`knowledgeSelection`、`knowledgeFilters`、`knowledgeMetadata`；资料库范围备份含 `knowledgeMetadata` | 选择状态只在被选中的条目成功导入后保留；无效/缺失引用过滤并报告；筛选条件可恢复则恢复，否则清空并提示；元数据按字段 schema 导入。旧版本缺字段时使用空选择/默认筛选，不推断或静默迁入其他范围的选择；字段存在但类型/引用无效时计入无效项并说明处理结果 |
| 社媒研究任务、结果、报告和附件 | 完整工作区备份有研究记录与附件清单；ZIP 负责附件载荷 | 校验附件路径、大小、摘要/校验和及结果关联；仅恢复存在且匹配的附件 |
| 平台连接状态 | 备份可出现 `platformConnections` | 仅保留非敏感连接元信息；清除 Cookie、token、密码、profile/session 路径与密钥；恢复后要求重新授权和检查 |
| 原应用主模型、搜索、辅助写作服务设置 | 单独存储，工作区备份不包含；其中包含 API key | 旧连接不迁移。DSH 宿主模型配置由 DSH 管理；插件自有非敏感端点/模型名可在插件备份中作为单独可选类别，并须用户预览选择；所有凭证在宿主重新配置 |
| 插件偏好与插件专属服务配置 | 不是原应用备份数据；由插件自有设置管理 | UI/非敏感偏好默认可随插件备份；插件服务端点和模型标识需单独列类、默认不导出或由用户显式勾选；恢复后重新测试连接 |
| 凭证、账户密码、Cookie、会话和私有浏览器 profile | 明确排除 | 不导入、不显示原值、不写入插件存储或插件备份 |

上述可见性基于当前检查的 `prototype/storage.js` 与 `prototype/workspace-backup.js`；后续实施前仍须以实际备份样本核验 ZIP manifest、JSON schema 和附件路径，并记录样本版本及哈希。来源 ZIP 当前格式限额为：manifest 最大 128 MiB、最多 10,000 个附件、单附件最大 25 MiB、单任务附件合计最大 25 MiB、解压总量最大 2 GiB；格式版本改变时必须重新核对，不静默套用旧限额。导入策略 v1 对直接工作区 JSON 和资料库 JSON 设定插件侧输入上限：文件最大 128 MiB、解析后记录总数最大 100,000、嵌套深度最大 64 层；超限在预览前拒绝并说明原因。该 JSON 上限是本设计的插件策略，不是原应用格式已有的硬限制；实施计划需通过样本和目标存储测试冻结策略版本。ZIP manifest 还受记录数和嵌套深度防护约束。插件自己的备份/恢复须使用独立格式版本和限额，不得将来源备份格式版本误当插件备份版本。若原应用备份本身缺字段，插件不得为填补缺口而改动原应用。

### 7.3 预览、去重与冲突默认策略（设计建议）

以下为本稿推荐的明确默认行为，实施前按用户审阅结果冻结：

1. 在临时区解析 ZIP/JSON，检查格式版本、字段类型、记录数量/大小限制、重复 ID、附件路径穿越、附件缺失和 schema 可升级性；任一全局结构错误时不写入正式存储。导入文本和附件始终按不可信用户数据/待分析资料处理：不执行其中的脚本或命令，其中包含的提示词或面向模型的指令不获得指令权限；只有用户在具体任务中选择材料并检查外发预览后，才可作为明确隔离、标注为不可信来源的资料进入模型上下文，不得覆盖系统/开发指令或用户本轮任务要求。
2. 按类别显示“可导入、相同内容跳过、ID 冲突、缺少关联/附件、来源备份未包含、暂不支持、无效记录”等计数和样例；用户可取消不需要的类别。
3. 规范化后内容相同的记录视为重复并跳过，不产生额外副本；同时必须建立“来源实体 ID → 已有插件实体 ID”的映射，使选中导入集合中的后续引用正确指向已有记录。若内容相同的目标有多个候选，须由预览提供可辨识信息供用户选择；未能唯一确定时，阻止依赖该目标的记录导入并报告，不得留下悬空引用。
4. 若相同实体 ID 的内容不同，默认不覆盖插件记录：导入记录保留为副本并分配新插件 ID；引用先在完整已选导入集合内建立 ID 映射，再重写到对应副本 ID。若引用目标无法唯一判定，则阻止相关记录导入并报告，不能猜测关联。
5. 提交前建立已选实体间的依赖图。相互引用或强依赖的类别作为同一可恢复提交组；仅无依赖的类别/组可独立成功。依赖组按拓扑顺序准备，但只有该组全部记录和附件校验通过后才整体提交；组内任一写入失败则回滚/恢复该组，不产生悬空引用。若用户未选择依赖类别，则将关联记录标为“依赖类别未选择”并暂缓提交；用户可补选完整依赖组，或明确跳过该组，不得只提交其依赖记录。来源备份中重复的实体 ID 若不能由类型和关系唯一消歧，按歧义项处理并阻止相关依赖组提交。映射表在整个导入任务及重试期间保持稳定，写入导入收据以保证重试幂等。独立组失败不影响无依赖组。
6. 导入结束显示逐类结果、跳过/冲突原因和失败项；成功类别不因重试重复创建数据。
7. 插件自身备份恢复复用校验、预览、冲突和恢复报告机制；恢复到空工作区与合并到非空工作区须有清晰不同的确认文案。

### 7.4 凭证过滤与导入收据

迁移输入和插件导出都采用允许字段白名单，而非只靠敏感词删除。对可能含认证信息的连接对象进行 schema 过滤和递归检测；发现凭证字段时丢弃并报告“敏感字段已排除”的数量/类别，不回显密钥内容。附件也需排除凭证文件、profile 数据和被明确列为敏感的本机配置。

导入收据与诊断日志保存在插件本地，仅记录备份指纹、格式/版本、时间、类别计数、ID 映射、状态、失败代码和附件校验结果；不记录提示词正文、文档内容、查询私密材料、完整路径或凭证。用户可删除收据/日志；删除收据不撤销已导入数据。日志保留期限和容量上限在实现计划中按本机空间预算设定，并提供到期清理。

## 8. 分阶段交付顺序与阶段门

阶段顺序按用户确认的路线执行；阶段并不缩小全功能目标，阶段状态不能代表其他领域已完成。

| 阶段 | 范围 | 进入下一阶段的验收门 |
| --- | --- | --- |
| 1. 基础层 | 插件工作区导航、模块边界、独立版本化数据模型、迁移预览/冲突处理框架、DSH 能力适配、错误与能力状态 | 插件存储与原应用读写隔离有可重复证据；导入预览不写正式数据；取消、重复导入、冲突、损坏文件和敏感字段测试通过；宿主接口逐项有核验记录 |
| 2. 规划与资产 | 新建规划、我的计划、提示词 Agent 三类入口、提示词库、案例、方法卡/基础资产 | 三类入口与领域可组合；计划跨会话恢复；版本、案例来源和验证状态正确；失败/撤销/删除边界通过 |
| 3. 资料与检索 | 资料库、知识条目、题录、来源/引用、关键词本地检索、授权目录/文件材料、选择与外发预览 | 检索来源可追溯；未选择材料不进入请求；索引可重建；读取范围、解析失败和发送内容可检查；使用含提示词注入文本的导入样本验证它只能作为不可信资料；备份迁移关系通过 |
| 4. 写作 | 全部已规划文体、专业基础包、材料/工作空间、版本、复盘、记忆；按代表文体分批闭环 | 不只显示模板；每类文体完成代表任务链、材料/来源处理、提示词/结果复盘和持久化测试；使用含提示词注入文本的材料验证其不能覆盖本轮任务要求；基础包可管理且来源可追溯 |
| 5. PPT | 场景规划、资料研究、逐页规划、制作路线、预览/标注/反馈、版本和局部重跑 | 完成从简报/资料到逐页内容、外部提示词、结果预览和反馈复跑的端到端测试；含指令文本的导入资料只作为不可信来源，不执行其脚本/命令或服从其模型指令；不能将规划误报为成品 |
| 6. 学术工作流 | 论文项目、文献处理/题录、综述筛选与证据提取、投稿要求、审稿与回复 | 至少覆盖论文优化、文献/综述与逐条审稿回复代表任务；来源、筛选范围、修改证据、提示词和轮次关联正确；含指令文本的论文/审稿材料只作为不可信资料 |
| 7. 社媒研究 | 研究任务、平台计划、来源、结果筛选/深读、附件、报告、暂停/重试/部分失败；按本设计的平台能力矩阵接入 | 小红书、哔哩哔哩、微博、知乎分别验收新建/运行；Reddit、YouTube 只验收历史查看/迁移，除非新设计扩展范围；含指令文本的历史帖子、摘录和附件只作为不可信来源；结果和报告可回链、恢复及重新生成 |
| 8. 设置与交付 | 非敏感插件偏好、插件备份/恢复、旧备份全量映射核对、全域迁移与回归验收、用户操作说明 | 所有功能域有真实任务链证据；备份/恢复及附件验证通过；凭证排除通过；原应用未改；未通过项有明确阻塞和证据，不以自动化绿色替代真实宿主验收 |

已有插件的通用 Agent、写作/PPT 初步能力、任务持久化、学习/记忆和 Host 适配属于复用基线。实施时先按当前代码和计划核实每一项状态；已通过的项目保留证据并跳过重复实现，但须补齐它们对全功能目标的新接口或迁移集成验收。

## 9. 错误、恢复与可观测性

- 宿主能力不可用、未授权或版本不兼容时，显示具体能力及状态；不伪造搜索、读取、模型或平台成功。
- 模型/搜索/解析单次失败保留用户输入、已存结果和原版本；支持重试或在可行时转为手动复制/补充材料。
- 社媒单平台失败允许其他平台按已批准计划继续，报告注明失败来源和实际覆盖范围；用户可暂停、取消、跳过或重试。
- 附件恢复失败不删除记录正文；相关条目标记附件缺失并提供修复/重新导入路径。
- 任何存储失败均不可显示为成功。通过写前校验、事务或恢复日志确保重试幂等；错误报告不包含凭证或不必要的私密正文。
- 迁移日志记录备份指纹、导入时间、插件 schema 版本、类别计数、ID 映射、跳过/失败原因和附件校验结果；不存储原始凭证。

## 10. 总体验收标准

只有以下门槛全部通过，才可称为全功能迁移达到可验收状态：

1. 原应用和其用户数据未被插件读写；插件数据位置、格式和备份边界可验证为独立。
2. 功能对等矩阵中的每个用户能力均有对应入口、关键动作、状态保存/恢复和可追溯的任务验收证据；所有已规划文体均有能力状态和代表路径，不以模板占位。
3. 数据迁移矩阵中的每类数据均标明来源是否含有、插件是否支持、转换/过滤结果和不可迁移原因；实际 ZIP/JSON 样本中可导入字段、附件及引用经读回验证。
4. 同内容重复、同 ID 冲突、重复来源 ID、引用重写、未选类别及其依赖项、损坏备份、类别失败重试、取消及幂等重试均有测试和结果记录；不能提交会产生悬空引用的部分数据。
5. 导入提示词、网页摘录、研究结果和附件中的指令文本在资料检索、写作、PPT、学术和社媒代表路径中均按不可信资料处理；测试证明它不会触发脚本/命令执行或覆盖用户本轮要求。
6. 插件偏好、模型配置和平台认证边界清晰；凭证不会进入插件工作区导出、日志、测试记录或错误消息；平台重新授权后状态才可显示可用。
7. DSH 接口、文件/目录、模型、搜索和社媒平台能力分别记录自动化、宿主运行态及真实效果证据；未配置/未授权能力明确标记未验收。
8. 写作/PPT/学术/社媒关键失败路径会保留已有内容，用户可继续、重试或导出可恢复数据；附件缺失和来源不完整不被隐去。
