# 简洁工作台与跨资料批注设计

日期：2026-11-10

状态：自查修订版 04。A/C 查看方式与批注生成提示词的方向已确认；本文仅覆盖工作台与批注机制，不代表整个产品界面已经完成。完整导航与各板块界面设计见同目录 `2026-11-10-product-interface-redesign.md`。逐项缺口与 GitHub 源码依据见 `2026-11-10-design-audit-and-reuse.md`。当前仍处于设计评审。

## 1. 已确认的目标

- 初始界面干净，以任务输入为中心，避免设置、资料库、迁移和各阶段选项同时堆在页面中。
- 同时具备 A「按需展开」和 C「专注查看」：它们是同一工作台的两种视图。
- 预览类似文件查看器，展示实际资料，并具有批注能力。
- 资料范围包括图片、PPT、文档、HTML、本地网页和网站，不将批注限定为办公文件。
- 支持批注笔、区域标记及选中文字后批注，工作台能辨认批注针对的内容。
- 工作台接收批注后，主要生成可编辑、可复制的修改提示词。

用户认可上述交互方向，并明确补充网站与 HTML 批注，以及提示词生成优先的工作方式。以下定位、存储与异常规则是据此形成的具体设计，随本文一起审阅。

## 2. 当前项目依据与修改边界

目标为 `.dsh-workspace/dsh-plugin/forward-step-dsh` 的 DSH 插件。原应用目录保留。

`src/client/index.ts` 目前在一个主页面中同时渲染设置、迁移、资料、领域工作台与任务控件，导航主要使用页面内锚点。这是本轮应调整的界面结构。

`src/types.ts` 的 `PptVisualFeedback` 已保存页码、单点相对坐标、可选图片序号、问题类别、意见、内容快照和是否用于当前提示词。新设计复用这些已有概念，扩展资料类型和定位方式，不丢失旧批注。

现有任务草稿、版本、资料引用和发送预览继续使用。具体查看器依赖在实施计划中通过样本验证后选择，本设计不预先安装依赖或修改日常 DSH profile。

## 3. 界面结构

### 3.1 首页

- 主区域为简短标题、输入框、添加材料入口和少量任务起点。
- 新任务、最近任务、资料库、提示词收藏和设置提供明确入口。
- 在 DSH 中沿用宿主已有导航能力，避免再复制一层完整宿主侧栏。草图侧栏表达信息归属，最终宿主嵌入位置在实施前验证。
- 设置、备份与迁移、资料管理在进入相应功能后显示。
- 项目、对话、模型等必要上下文优先复用宿主已有信息；缺少信息时出现明确补充入口，保留当前输入，不猜测标识。
- 系统按当前任务判断下一项需要确认的信息，不要求用户在首页填写所有领域和阶段选项。

### 3.2 A：按需展开

- 未打开资料时，输入与任务对话占主区域。
- 打开资料或生成提示词后，展开右侧查看器，左侧继续沟通。
- 顶部标签用于切换资料和提示词；关闭标签只改变视图，不删除资料或批注。
- 查看器只显示当前资料适用的操作，例如有页数的文件才显示翻页。

### 3.3 C：专注查看

- 查看器可放大至工作区域，也可收起查看器专注对话。
- 返回双栏保留当前文件、标签、页码、滚动位置、缩放、选中批注和输入草稿。
- 小窗口使用单区域切换，提供可发现的返回入口，避免挤成多个窄栏。

### 3.4 按需选项与批注浮层

- 影响任务方向的选择使用单问题弹窗；明确推荐理由，允许修改先前选择。
- 非关键问题可稍后处理；关键问题未回答时保留草稿并说明待确认项。
- 选中文字或标记区域后的批注编辑使用就近浮层，避免遮住整页。空间不足时用可收起面板。
- 批注列表默认收起，通过工具栏按钮打开；列表与页面标记双向定位。
- 弹窗支持键盘、Escape、焦点限制及关闭后焦点返回；编辑中关闭不得静默丢失意见。

## 4. 实际资料查看与批注

| 资料 | 查看目标 | 定位方式 |
| --- | --- | --- |
| 图片、截图 | 保持原图比例，可缩放和平移 | 原图坐标对应的相对区域、点位、路径 |
| PDF | 页面外观与可用文字层 | 页标识、选中文字及上下文、页面区域 |
| PPT / PPTX | 原始页面的可靠预览 | 幻灯片标识、页面区域；可准确映射时支持文字划选 |
| Word 等文档 | 可阅读的文档呈现 | 文本块标识、原文引用、文字范围；分页视图支持区域标记 |
| HTML、本地网页 | 内容与页面结构的可查看呈现 | 文本引用与上下文、元素线索、固定快照中的区域 |
| 网站 | 进入用户指定页面，并保留来源信息 | URL、捕获时间、页面快照版本、文本或区域定位 |

“跨资料批注”意味着统一体验和批注记录，不表示所有资料都具有相同的文字层。图片可以圈选并批注；只有存在可靠文字层时，才提供原文划选。识别生成的文字应标明来源，不能当作文件原生文字。

PPT 解析后的标题、正文或局部配图，不得伪装成原始整页预览。预览与原文件存在差异时应明确说明，并提供整页图或可靠转换结果的查看路径。若某格式尚不能可靠展示，保留文件和任务，明确当前支持的操作。

### 4.1 网站与 HTML

- 用户可添加 URL 或本地 HTML；资料标签展示标题、来源链接和捕获时间。
- 当前可批注页面必须绑定一个可重现版本，视觉区域批注绑定固定快照，避免滚动或响应式排版改变其含义。
- 同时具有页面与快照视图时，清楚标识当前视图；打开原站不代表其最新内容已经与快照同步。
- 文本定位优先保留选中原文和前后上下文，元素路径仅作为辅助线索。
- 页面内局部滚动、缩放、长页面截图应记录各自坐标变换，不能把浏览器窗口坐标直接保存为内容坐标。
- 网页获取失败、需要登录、内容不完整或页面能力受限时，明确显示状态；允许导入用户提供的页面截图、HTML 或 PDF 继续批注。
- 不把登录状态、cookies 或其他访问凭证放进资料记录和提示词。外来 HTML 与脚本不在插件可信界面中直接执行。
- 来源页面中的指令仍是资料内容，不得替代用户的批注意见或工作台指令。

## 5. 批注工具和类型

### 5.1 标记方式：批注针对哪里

- 文字高亮、下划线、删除线：绑定具体选中文字。
- 矩形、圈选、箭头：绑定画面区域或明确目标点。
- 自由画笔：保留笔迹、边界范围及所在页面。
- 单点便签、整页意见、整份资料意见：覆盖无需精确选区的情况。

查看态保持简洁，进入批注模式后展示适用工具。颜色、线宽等次级选项仅在相应工具中展开。

### 5.2 意见类型：希望怎样处理

包括修改、删除、补充、解释、核实和保留；问题维度包括内容、逻辑、证据、风格、布局、可读性和其他。两者不要求同时填写，只在有助于表达意见时展示。

圈选或画线不自动等同于删除、重写等意图。可以先保存标记，之后填写意见；缺少意图的标记在生成提示词前列入待补充项。

批注支持编辑、删除、撤销、筛选、是否纳入当前提示词，以及待处理 / 已处理状态。生成提示词不自动将批注设为已处理，状态由用户确认。

## 6. 让工作台准确理解批注

每条批注至少关联以下信息，实际字段名沿用项目习惯确定：

- 身份：批注 ID、任务 ID、资料 ID。
- 版本：原资料内容标识、快照或转换版本、捕获时间。
- 位置：页或幻灯片标识、页码展示值；网页来源 URL 和快照标识。
- 对象：原文与上下文、文字范围、元素辅助线索、相对区域、点位或笔迹路径，按标记方式记录。
- 依据：创建时的内容快照；视觉意见保留对应区域截图，并能回到整页查看。
- 意见：标记方式、用户类型、意见正文、状态、是否用于本轮。

页面序号和文件名用于展示，不单独承担唯一定位。视觉坐标相对于固定内容平面保存，展示时按缩放、旋转和滚动进行转换。

示例：`产品方案.pptx / 第 3 页 / 标题“市场机会” / 修改 / 改成一句明确结论，并补充依据`。工作台在查看和提示词中同时呈现目标内容与意见，不只转交坐标。

### 6.1 资料更新

- 原批注仍关联原版本，更新资料不覆盖其证据。
- 页面内容未变且定位唯一时，可在验证后关联新版本。
- 文字重复、元素移动、页面重排、区域内容变化等导致定位不确定时，标记“待确认”，让用户重新定位。
- 待确认项默认不进入执行性修改提示词；若用户明确保留，只能标为需定位确认，不能作为确定的修改目标。
- 对无法确认的定位，不静默移动批注或丢弃用户意见。

## 7. 从批注到修改提示词

1. 用户在资料中创建批注；系统保存并显示保存结果。
2. 批注抽屉展示本轮拟采用项，默认勾选新建且目标有效、意图明确的未处理批注；用户可调整。
3. 点击“整理修改提示词”后，先列出缺少意图、失效定位或相互冲突的意见；让用户处理关键冲突。
4. 工作台按资料与页面归组，结合当前任务目标、明确约束、目标原文或画面和批注意见生成草稿。
5. 提示词在独立标签中显示，可编辑、复制，并可追溯到原批注。
6. 已生成提示词保留当时的资料与批注版本。之后修改批注时，提示词标为需重新整理，不静默改写旧版本。

提示词应包含目标、适用资料版本、逐项修改要求、明确保留项、交付要求和验收方式。超出上下文容量时展示未纳入项，让用户分批，不能静默截断。

视觉批注进入模型请求时，必须能提供实际区域或整页图像，或采用用户核对过的文字描述。仅提供“坐标 x/y”不构成视觉理解。模型能力不足或外部 AI 需要附件时，明确列出需附上的文件与页图；纯文本复制不能被描述成已附带图像。

生成过程沿用现有发送预览与资料选择流程；仅整理被选中的资料和批注，不自动发送整份资料库。原资料、批注和生成草稿分别保存。

默认产物是修改提示词与所需附件清单。原文件保持原样；直接编辑文件、自动发布网站不属于本次交付。

### 7.1 提示词输出示例

```text
请根据以下批注修改我提供的资料。

目标：让产品方案汇报更清楚地支持资源投入决策。
适用资料：产品方案.pptx，本次提供的版本。

第 3 页，标题“市场机会”：
批注意见：改成一句明确结论，并补充依据。
要求：仅使用已提供的事实；证据不足时列为待补充，不编造数据。

第 4 页，已框选的图表区域：
批注意见：标签太密，调整字号和排列。
视觉依据：随任务附上的第 4 页区域图和整页图。

保留事项：未批注部分保持原意；保留原有来源信息。
交付要求：按批注逐项说明修改结果和仍需补充的内容。
验收：每项修改对应原页码与批注，确保指向正确、文字可读。
```

## 8. 实现职责与依赖判断

- 工作台布局负责导航、任务上下文及 A/C 切换，复用现有任务状态。
- 资料查看负责真实内容、页面导航和内容坐标，按格式提供文字与区域选择能力。
- 批注层负责标记、意见编辑、保存、版本与定位，不承担办公文档编辑。
- 提示词整理复用现有任务和生成流程，读取所选批注及依据。

以上是职责划分，不要求建立统一框架或插件平台。先复用现有组件，只有存在实际差异时才增加格式适配。

前期检索的参考对象包括 Annotorious（图片区域）、react-pdf-highlighter-extended（PDF 文字与区域）、Hypothesis（网页文本定位）、EmbedPDF（PDF 批注工具）。ONLYOFFICE 属于后续完整办公编辑需求的评估对象。本次不把研究候选等同于已验证选型，不对维护状态或兼容性作未验证承诺。

下一阶段先核验 DSH 的嵌入条件、真实文件展示与文字映射、网页获取与隔离条件，再确定最小依赖组合。需要新增依赖时记录来源、许可、维护与版本证据，并遵循用户的安装确认约定。

## 9. 错误与恢复

- 资料加载失败保留任务、资料记录及批注，并允许重试或换用可靠快照。
- 批注保存失败保留编辑内容，显示未保存状态；不能提示保存成功。
- 生成提示词失败或取消保留批注选择和已有草稿，允许重试。
- 切换资料、A/C 视图和标签不丢失未提交输入。
- 删除资料前说明关联批注的影响，用户确认后才执行；保留已生成版本的可解释引用。
- 原文件中的个人信息和局部截图只随用户选择进入发送预览，未选择内容不自动外发。

## 10. 验收条件

- 干净首页、任务双栏、专注对话、专注预览四种状态可互相切换；位置和草稿保持。
- 首页无堆叠的设置、迁移、资料全文与领域表单；选项按当前步骤出现。
- 图片、PDF、PPT、文档、HTML、网站分别用真实样本验收展示与批注；不能用同一个静态图片演示替代所有格式验收。
- 有可靠文字层的资料可划选批注，点击列表能定位原文；重复文字不会错配。
- 画笔、框选、箭头、便签在缩放、滚动、旋转和 A/C 切换后保持对应关系。
- HTML 与网站批注同时保留来源和快照版本；长页面、局部滚动、页面更新和无法获取等情况可解释且可恢复。
- 资料改版或重新排序后不错误复用旧定位；歧义项进入待确认状态。
- 提示词逐项包含正确目标、用户意见和必要依据；未选批注、过期定位、未回答意图不混入确定的修改要求。
- 生成与复制不改写原文件，不把生成完成等同于批注已处理。
- 键盘能够操作弹窗与批注列表；控件具有可读标签、可见焦点、足够文字对比度，功能文字不小于 11px。
- 原有任务保存、恢复、提示词版本和 PPT 批注记录通过相关回归验证。

测试按职责选择最小集合：定位和提示词整理使用确定性测试，跨视图与批注操作使用浏览器交互测试，格式保真通过真实样本视觉验收。仅构建通过不等于真实文件预览验证通过。

## 12. 自查后补齐的交互契约

### 12.1 两套草图合并为同一个工作台的规则

“任务对话”中的大纲示例与“查看与批注”中的资料示例目前是独立演示，不作为已完成统一查看器的证据。正式产品只保留一个当前任务、一个已打开资料列表和一个查看状态；从对话里的资料卡、资料库详情、批注跳转进入同一查看器。

| 状态 | 触发 | 页面变化 | 必须保留 |
| --- | --- | --- | --- |
| 干净首页 | 新建空任务 | 输入框为主；没有空预览栏与常驻批注列表 | 其他任务草稿不受影响 |
| 单独对话 | 开始任务，尚未打开资料 | 对话与输入；资料以短卡片出现 | 当前任务目标、补充输入 |
| A 双栏 | 打开一份资料或提示词 | 沟通＋同一内容查看器；可调整宽度 | 标签、页面、批注和输入 |
| C 专注预览 | 放大查看器 | 隐藏沟通区域，保留“返回双栏” | 内容版本、缩放、滚动位置、未保存批注 |
| C 专注对话 | 专注对话 | 对话占满工作区；资料卡可恢复查看 | 原查看位置与当前资料 |
| 窄屏 | 宽度不足以阅读双栏 | 对话/资料单区切换；当前任务不变 | 与桌面相同的查看状态 |

关闭资料标签不删除资料；关闭当前标签后选临近标签，没有标签则回到对话。打开新任务时新建独立草稿；从历史列表返回旧任务恢复旧草稿，不能共用一个全局字符串覆盖不同任务。

2026-11-10 的草图修复已保留单个示例任务的输入、页码、提示词文本、批注勾选、专注状态和查看区滚动位置。多任务隔离、真实文件缩放/旋转与多标签仍待样本验证。

### 12.2 按资料能力显示工具

| 资料呈现 | 可以直接使用 | 需要条件 | 缺少条件时的设计 |
| --- | --- | --- | --- |
| 图片、截图、整页幻灯片图 | 点、框、箭头、画笔、整页意见 | 文字批注需要用户核对过的 OCR 文本 | 显示“本资料无原生文字层”，保留区域工具 |
| 有文字层的 PDF | 文本范围、页区域、笔迹 | 精确文字位置须与当前页渲染对应 | 不匹配时关闭文字定位，允许区域批注 |
| PPT/PPTX | 可靠整页图上的区域与笔迹 | 文字划选需要文字层与整页图逐项映射 | 提取文本单列为“文本视图”，不叠到不匹配的位置 |
| Word 等重排文档 | 原文范围、段落批注 | 区域批注需要冻结的分页或截图 | 重排视图只提供文本定位；切到固定快照再画区域 |
| HTML、网站快照 | 原文与上下文；固定快照上的区域 | 访问原站与快照版本一致需要额外核对 | 原站链接另开；更新抓取另存新版本 |

无效工具显示简短原因与可用入口，不能让所有格式都显示一个可点但无效果的画笔或文字按钮。当前演示按格式切换的是示意内容，这张矩阵是正式实现的能力约束。

### 12.3 定位、更新和批注生命周期

- 文本目标保存原文、前后文、文内位置及来源版本；DOM 路径是辅助信息。先验证原文是否一致，再使用位置；多个相同候选必须让用户确认，不能自动取第一个。
- 区域与笔迹使用原图/固定页平面内的坐标，记录平面尺寸和旋转。页内唯一标识由快照版本与页标识组合；页码只用于显示，不跨版本复用。窗口缩放和滚动只改变显示变换。
- 每条批注拥有独立 ID，批注列表不是单个意见字符串。第二次批注追加记录；编辑只改该 ID；删除可撤销，不覆盖其他标记。
- 保存状态（未保存/保存中/失败/已保存）、处理状态（待处理/已处理）、定位状态（有效/待确认/缺失）分别显示。生成、复制或收藏提示词均不自动标为已处理。
- 批注草稿因 Escape、切页或切模式被收起时，保留待续入口。用户主动丢弃时才清除。键盘焦点返回原选区附近的批注入口。
- 批注勾选由用户控制，展开工具或切换模式不得恢复默认勾选。默认选择只在本轮首次整理时执行，后续新建有效且意图明确的批注提示是否加入。

### 12.4 从批注到提示词的决定点

| 情况 | 下一步 | 对生成正文的影响 |
| --- | --- | --- |
| 没有选中批注 | 提示选择意见，保留编辑 | 不生成空版本 |
| 只有圈画、没有意图 | 就近询问希望修改什么；允许本轮跳过 | 未回答标记不变成推测的修改要求 |
| 目标过期或重复原文有歧义 | 打开旧证据与新资料，让用户重新指向或暂不采用 | 暂不确认的项仅列在待补充清单 |
| 同一区域同时要求删除与保留 | 单问题弹窗选择保留哪条、合并或暂缓 | 不按列表顺序擅自决定 |
| 需要视觉依据但尚无区域图 | 显示所需图片、截图预览与是否附带 | 文字复制明确列附件；缺图时不假称已理解图像 |
| 意见量超过本次容量 | 列出本轮与后续批次，用户调整 | 不静默省略意见 |
| 意见/来源更新，已有提示词被手动编辑 | 旧稿标“依据已变化”；选择生成新版本或继续编辑旧版 | 不覆盖用户修改；新旧版本可比较 |

提示词每一项保留批注 ID 与来源版本的内部引用，在界面提供“返回原处”。跨资料生成按资料和页分组，不能把 PPT 的意见带到网站模板中。收藏记录来源提示词版本；案例记录实际采用的版本。

### 12.5 必须在真实样本中验收

图片、文字 PDF、扫描 PDF、含文本和图片的 PPTX、重排 Word、长网页分别准备一个样本。每个样本检查：打开真实内容 → 建立两条独立批注 → 取消一条勾选 → A/C 来回切换 → 返回正确位置 → 生成只含所选意见的提示词。

额外检查：同句重复两次、页面改序、200% 缩放、90° 旋转、长页和局部滚动、保存失败、模型中断、手动改提示词后重新整理。旧版点位批注迁移后仍可查看。没有这些样本结果前，状态保持“设计规则已写明，能力待验证”。
