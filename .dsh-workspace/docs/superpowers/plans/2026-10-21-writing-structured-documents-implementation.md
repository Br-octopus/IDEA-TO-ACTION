# 结构化文档阶段实施计划

对应规格：`docs/superpowers/specs/2026-10-21-writing-structured-documents-spec.md`
上位设计：`docs/superpowers/specs/2026-10-20-writing-domain-expansion-design.md` 第 5–17 节
依赖：普通文章基线、共用核心 A/B/C、学术 A–D；执行前重新检查当前工作区和未提交改动。
实施目标：九类领域分别形成可使用、可回填和可复核的应用任务闭环，并达到 D 盘浏览器开发版可验收。真机测试由用户暂缓；不提交代码。
并行判断：规格阶段及实施均先由当前代理串行推进。领域之间共享 `genre/taskType`、包选择、提示词构建、保存和 UI 路由，分支并行容易产生 schema/UI 冲突且需额外集成验收；先按三个纵向切片串行完成。若后续仅有来源调研等只读且互不依赖工作，可在实施时再评估子智能体收益。

## 全局约束

- 先读取本规格、当前 `git status`、相关文件和当时的 AGENTS/项目脚本；保留所有已有变更，不重置、覆盖或夹带无关内容。
- 每项先补能暴露现状缺口的失败测试，再做最小实现，跑该项定向验证后进入下一项。不要只新增文体下拉选项或把九类路由到普通文章同一模板。
- 复用现有 `writingArticles`、`knowledgeEntries`、包管理、核心 B/C 工作区关系、版本快照与备份；无证据不得增加平行存储或服务层。
- 领域包进入运行时包目录和应用分发路径。内置规则及案例来源/许可记录可追溯；未核对来源保持 `unverified`，固定模拟案例只标记流程验证。
- 每个切片完成后运行该切片测试、必要的相邻回归、`pnpm check`、`git diff --check`，再做 D 盘浏览器开发版应用验收并记录证据。失败项修复后重跑；全局既有无关失败需分清归属，不得静默忽略相关失败。
- 全阶段收口前确认九个领域都完成规格第 10.2 节路径。真机测试暂缓；不提交代码。

**步骤：**

2. 为领域任务扩展输入定义最小字段；优先复用 `goal/audience/platform/preserveItems/constraints/successCriteria/units/materials/issues/routeSnapshot`。只有不能合理映射的领域事实才新增有长度/数量上限、未知字段会被清理的契约。
3. 扩展 `WRITING_GENRE_CONFIGS` 并为九类建立各自目标字段、任务集合、检查维度、输出要求、风险提醒、风格基线与记忆命名空间。任务选择 UI 显示本领域任务，不将所有领域假定为 `revision`。
4. 调整协调器任务路由：非学术结构化文体进入结构化文档提示词 builder；既有 `article` 保持原诊断/改稿行为，`academic-paper` 保持学术专用 builder；不支持的 genre/task 明确失败。

6. 运行上述 schema/coordinator/prompts/UI/pack 定向测试和普通文章、学术基础提示词回归。

**验收门槛：** 只有领域/任务选择、旧任务兼容和提示词路由契约通过后，开始领域包内容与切片一。

## 切片一：长篇研究文章 + 技术文档

### 任务 1.1：领域包与来源映射

**文件：** Modify `prototype/writing-pack-catalog.js`、`tests/writing-pack-catalog.test.js`、必要的 `prototype/writing-pack-schema.js`/`tests/writing-pack-schema.test.js`。

- 为长篇研究文章、技术文档分别建立稳定 ID、版本、适用 genre/task、独立 prompts、checks、routes、来源和验证状态。
- 长篇研究文章覆盖跨节规划/证据关系/作者样本用途/未解决问题复核；技术文档覆盖版本环境/前置条件/动作/预期结果/故障恢复。
- 为每个专业方法项记录实际读取的官方/专业来源条目、版本/日期、许可说明、适用范围和限制；自拟规则标成原创操作建议。来源未经审阅的内容保持未验证。
- 以失败测试确认两个包可选、禁用后正确降级、任务不串包、历史快照保留当时包版本。

### 任务 1.2：领域提示词、单元和问题复核

**文件：** Modify `prototype/writing-workbench-prompts.js`、`prototype/writing-workbench-coordinator.js`、对应 tests。

- 构建领域专属任务提示词，实际消费各自目标字段、单元、材料范围、适用包条目和证据/风险说明；不能只把包名附在通用文章提示词末尾。
- 长篇研究文章：支持跨章节简报/分节规划/分节诊断与修订/跨节复核；将章节职责、相邻章节关系、跨节约束、作者样本用途和关联证据写入提示词快照；选中单元时排除其他单元专属材料。
- 技术文档：任务类型区分操作说明、API/接口、设计说明、故障排查；将版本、环境、前置条件、权限、输入、步骤、可观察结果、失败与恢复路径带入提示词，缺项标注待补。
- 对未知接口、命令、性能和环境行为生成验证步骤，不生成已执行事实；结果带回后由已有问题状态机制定位并显式复核。
- 断言提示词只含实际选材、字符预算真实、附件要求可见、未关联结果来源不被推断、候选问题不会自动成为已确认问题。

### 任务 1.3：应用 UI、保存与浏览器验收

**文件：** Modify `prototype/writing-workbench-ui.js`、`prototype/index.html`、必要的 `tests/helpers/writing-app.js`/`tests/helpers/writing-dom.js`、UI/存储/备份测试；Create `docs/superpowers/plans/2026-10-21-writing-structured-documents-slice-1-acceptance.md`（后续实现阶段）。

- 接入领域与任务选择、必需信息提示、适用包和来源状态、对应路线、材料用途/预算、提示词预览复制、外部结果回填、候选问题处理和历史对照。
- 对长篇和技术各跑一条完整固定案例；开启保存后刷新恢复任务、包/来源和材料/问题关系；保存关闭时不持久化新轮。
- 检查旧文章/学术工作区、备份往返、包停用后历史阅读和失败保留。
- 浏览器验收检查 390×844、键盘路径、提示词/预览一致、控制台、实际材料范围；不以真机验收替代。

**切片一完成条件：** 两类均完成规格矩阵中的领域输入、专属包、任务提示词、结果回填、定位/复核、持久化及浏览器代表路径；测试和应用证据写入单独验收记录。通过后才进入切片二。

## 切片二：商务文档 + 新闻/机构新闻稿 + 教程与课程

### 任务 2.1：独立专业包

**文件：** Modify `prototype/writing-pack-catalog.js`、对应 catalog/schema tests。

- 分别建立商务、新闻、教程课程的包与来源映射，不共享一份文章模板。
- 商务包分别处理报告/方案/商业说明/营销文案，跟踪受众、目标行动、产品事实、数据来源、品牌样本和限制。
- 新闻包分别处理事实整理/消息结构/采访材料/机构新闻稿，区分时间线、来源归属、直接引语、未证实信息和机构口径。
- 教程课程包处理学习目标、学习者/先备知识、课节顺序、示例、练习、反馈和可观察完成条件。
- 每个包记录核验范围、适用条件、来源/许可/日期及未验证项；固定案例不能把案例验证推广为整领域认证。

### 任务 2.2：任务提示词和回填复核

**文件：** Modify `prototype/writing-workbench-prompts.js`、`prototype/writing-workbench-coordinator.js`、对应 prompts/coordinator tests。

- 为三类独立定义 taskType、必需字段、提示词和检查维度。
- 商务：产品事实只来自用户确认材料；指标/预测缺证时标待核实；目标行动及执行条件进入提示词。
- 新闻：逐条要求事实、引语、时间、出处和确认状态；引语原文不被改成直接引述；观点/背景/推断分开；发布前清单不表示事实已验证。
- 教程课程：路线步骤与目标、先备知识、示例、练习及反馈一一对应；未做学习者测试不得标记经案例验证的学习效果。
- 对固定外部结果解析成候选而非自动确认；问题继续绑定原轮次/材料位置并可在新轮复核。

### 任务 2.3：UI、持久化和验收

**文件：** Modify UI/HTML 和需要的测试 helper/存储备份测试；Create `docs/superpowers/plans/2026-10-21-writing-structured-documents-slice-2-acceptance.md`（后续实现阶段）。

- 在工作台逐类显示输入、来源、路线和边界；任务切换不得静默丢弃或错用字段。
- 每类完成固定代表闭环；验证保存开关、刷新恢复、提示词版本、问题复核、工作区备份与资料库备份边界。
- 检查 390×844、键盘和页面/控制台错误；执行切片专项测试、共用工作台/包/存储回归、`pnpm check`、`git diff --check`。

**切片二完成条件：** 三类的领域规则与应用行为可分别证明，通用文章/长篇/技术/学术既有路径不回归；证据写入验收记录后进入切片三。

## 切片三：简历与求职 + 邮件 + 公文 + 法律文书

### 任务 3.1：独立专业包与高风险边界

**文件：** Modify `prototype/writing-pack-catalog.js`、必要 schema 和 catalog/schema tests。

- 独立建立简历求职、邮件、公文、法律文书包及任务类型，不合并为“正式文书”模板。
- 简历包要求经历/指标逐项来自用户材料，并将岗位要求映射至证据。
- 邮件包覆盖请求、答复、跟进、告知/协调；体现关系、已有往来、行动项和用户确认的披露边界。
- 公文包要求组织、文种、行文关系、时点和用户提供/选择的有效要求来源；来源冲突保持可见。
- 法律文书包仅组织用户材料、事实/主张/证据和待核对项，记录法域与时点，默认提示由执业专业人士审阅；不含法律意见或结论生成承诺。
- 对规范类来源逐条记录发布主体、准确标题/条款、版本/有效时点、适用法域/组织、访问日期、许可及限制；未核实有效性时不提供“当前有效”状态。

### 任务 3.2：短路径、任务提示词与安全回填

**文件：** Modify `prototype/writing-workbench-prompts.js`、`prototype/writing-workbench-coordinator.js`、对应测试。

- 邮件和简历允许短流程，但仍要求材料用途和事实来源明确。
- 简历候选结果的学历、岗位、年限、职责、技能、量化成果逐项与用户提供材料核对；未知事实不自动补齐。
- 邮件提示词突出收件人、目的、上下文、行动人和期限；确认按钮仅复制内容，不发送邮件；有承诺/披露缺口时要求用户确认。
- 公文/法律的法域、组织、文种或时点关键字段缺失/冲突时，切到补充信息或审校提示词，不能展示规范合规通过状态。
- 法律文书任何检查输出都标为材料整理/提示词建议，不解释为法律意见、有效性认证或结果预测；外部 AI 结果保持原文且须用户审阅。

### 任务 3.3：UI、兼容和分领域应用验收

**文件：** Modify UI/HTML、必要 schema/storage/backup/tests；Create `docs/superpowers/plans/2026-10-21-writing-structured-documents-slice-3-acceptance.md`（后续实现阶段）。

- 跑四类完整代表路径，包括法域/组织/时点缺项和补齐、事实冲突、失败恢复等边界路径。
- 对每类检查提示词实际输入、材料范围、候选/用户确认边界、任务历史和包快照；确认不触发任何邮件发送、法律结论或公文普遍适用承诺。
- 跑窄屏/键盘、保存/刷新、备份隐私、旧数据兼容和当前阶段所有新增测试；记录未配置模型、真实法律专业审查、真实用户测试、真机、Electron/分发包状态。

**切片三完成条件：** 四类均通过独立应用路径及边界用例，且不存在将求职/邮件/公文/法律任务错误路由到普通文章或其他专业模板的行为。
